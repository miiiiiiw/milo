開場 Introduction

00:00這是一期很樸素、也很囉嗦的 Remotion 教學。沒有什麼「一個 Skill 搞定」，更沒有一句話就能做出來，而是把這些動畫從探索到製作的過程還原出來。希望能夠幫助你掌握方法，創作出自己的作品。

00:13我最常收到的幾個問題：提示詞（prompt）是什麼？用什麼 Skill、得花多少 token？其實我很少自己寫提示詞（prompt），我跟 AI 聊需求，讓它幫我寫提示詞（prompt）。至於消耗多少 token——非精確統計——上個影片展現的 50 多個動畫，包括結尾那一大堆，大概花了 Codex 一週多的額度。但也有人說，他光做一個音符跳躍的動畫，就用完了一週的額度。這找誰說理去呢？所以光抄提示詞（prompt）是不行的。

00:38這期內容分成四個部分，你很多問題的答案其實就藏在各個環節裡。

影片模型 vs Remotion Video models vs Remotion

00:44影片模型是透過神經網路生成畫面，而 Remotion 是透過程式碼定義動畫元素、運動軌跡和時間軸，再逐幀算繪成影片。一個是生成式 AI，一個是程式化動畫。那不玩概念了，我們直接拿例子來對比。

00:58同樣是花朵生長的動畫，左邊是可靈（Kling）生成的，右邊是用 Remotion 做的。你看花朵的形態、枝條的生長、隨風搖曳的光影變化，右邊 Remotion 會生硬很多，因為它是透過程式碼參數來控制不同圖像的運動軌跡、縮放和透明度，來模擬枝條生長、花朵綻放的過程。

01:16再看這個音符跳躍的動畫。兩顆光球分別對應鋼琴的左右手聲部，隨著樂曲的演奏，精準地落在對應的音符上。音符位置和動畫軌跡高度同步。這種動畫單靠影片生成模型基本做不到，但 Remotion 就非常適合。

01:32還有大家可能會關心的成本問題。影片模型通常按時長和次數計費，而 Remotion 動畫更接近氛圍編程（vibe coding），主要消耗 token 或額度。所以不能簡單地說哪一個更划算。畢竟 Remotion 反覆修改起來也會消耗 token。但它有個優勢，就是程式碼可以複用。

01:46當你完成一個動畫，留下的不只是影片，還有它的動畫組件、運動軌跡、視覺效果、鏡頭設計以及可調整的參數。以後製作同類的動畫，就不需要從零開始，可以在原來的基礎上去替換素材、調整參數，製作效率會更高，token 消耗通常也會減少。

02:04這也是我在上期影片提到的：我用 Astra 模型作為主力製作動畫模板，DeepSeek 可以複用、製作同類動畫。

模型與 Agent 的能力差距 Model vs agent capabilities

02:11現在主流大模型的能力，其實已經形成了明顯的梯隊。就拿 Opus 5.5、Astra 和 DeepSeek-v4 來舉例。雖然都是透過程式碼來製作動畫，但差距不僅在於程式設計水準，更重要的是審美、運動設計，以及對整個動畫的導演和規劃能力。

02:28像 Opus 5.5，很多時候你只需要給它一個參考影片或一種風格，它就能抓住那個感覺，做出相當不錯的效果。Astra 其實也一樣，不需要事無鉅細地去指揮它，但它在審美和導演能力上比 Opus 會遜色不少。在畫面的設計感、動畫的流暢度，以及敘事和鏡頭之間的連貫性，能明顯看出差距。

02:48至於 DeepSeek，就拿這個音符跳躍的動畫來說：如果只給它一段參考影片和提示詞（prompt），讓它自己從零開始做，那出來的效果跟被雷劈了一樣。但是，如果我把 Astra 已經做好的運動模板——包括運動軌跡、視覺設計、鏡頭參數、Composition 等等——交給 DeepSeek 參考，來做其他樂曲，出來就是這樣的效果。

WorkBuddy 的環境問題 Solving WorkBuddy's environment issues

03:14除了模型本身的能力，還有一個很重要的因素，就是整套工作環境與權限配置（harness）的工程設計，也就是 Harness Engineering。這裡主要聊一下 WorkBuddy 的情況。

03:22我之前習慣用 Codex 做動畫模板，再用 WorkBuddy 去呼叫 DeepSeek 復刻同類效果。當然是為了節省 Codex 的額度啊——畢竟我在 WorkBuddy 每天可領 100 積分。但是很多小夥伴回饋，用 WorkBuddy 做 Remotion，動不動跑一兩個小時，消耗幾百積分，最後還失敗了。可同樣用 DeepSeek，切換到 Claude Code 裡面運行同一個專案、一樣的提示詞（prompt），它很順利地完成了動畫。

03:48原因在於 WorkBuddy 的執行環境對 Remotion 並不是很友善，導致大胖魚不停掉進環境坑裡：換路徑、寫 workaround、繞環境限制。動畫越複雜，這種摩擦就越明顯。

04:00給你的 WorkBuddy 加上這段提示詞（prompt），幫你的大胖魚少踩幾個坑。很多時候，飯是大胖魚吃的，但鍋是 WorkBuddy 的。大胖魚是講者給當時那個代理的暱稱：活兒是它幹的，問題卻往往出在 WorkBuddy 這口「鍋」——也就是工作環境（harness）。

04:08我自己跑下來的情況是：DeepSeek 做一個幾秒鐘的簡單動畫，只需要消耗幾個積分；完成一個大概一分鐘的音符跳躍動畫，消耗了 30 積分。僅供大家參考。

製作動畫前的準備 Preparation before making animations

04:20在正式製作動畫之前，先完成基礎能力的設定。首先安裝 Remotion 官方 Skill，跟你的 Agent 說一聲即可。這其實是 Remotion 的 Skill 合集，裡面最常用的是 remotion-best-practices。

04:34值得一提的是 Remotion Studio，可以讓 Agent 直接打開操作台、即時預覽動畫。你還可以自己動手調整元素的位置、角度、顏色等等參數，不用每個小細節都反覆跟 Agent 溝通。這個功能非常實用。如果你用 Codex，也可以直接在外掛裡面安裝。接著讓 Agent 檢查電腦的基礎執行環境。

04:54接下來，建議大家搭建一個長期維護的 Remotion 專案。比如我就建立一個叫「動效庫」的資料夾，讓 Agent 在這個資料夾裡初始化專案。以後製作動畫，我都在這個動效庫裡完成：根目錄統一管理依賴，每個動畫在 effects/ 資料夾下建立獨立的子資料夾。這樣製作新的動畫時，就可以直接複用已有的環境和依賴。

05:14因為 Remotion 本質上是基於 React 的前端專案。如果每做一個動畫就新建一個獨立專案，Agent 就得反覆初始化專案、安裝依賴、設定環境，動畫還沒開始做呢，額度先燒掉了不少。而且每個動畫都裝一套依賴，特別占硬碟空間。

05:30這是我長期累積下來的動效庫。Codex 裡面的專案對話是這樣的：當我想要直接複用某個動畫效果，就直接在相應的對話裡繼續提需求；或者不想消耗 Codex 的額度了，換成其他 Agent，打開動效庫的專案也是一樣的。長期累積下來，這個動效庫就相當於自己的動畫資產庫。甚至你還可以在這個基礎上，搭建一個動效工作台。不過建議在自己的工作流程穩定成熟以後，再折騰工作台，不然一會搭一會改，純粹給自己添堵。

06:02大家都知道，Opus、Astra、DeepSeek 都是大型語言模型，本身不具備生圖能力。那它們怎麼做出漂亮的動畫呢？很多畫面元素是透過程式碼繪製出來的。比如你讓 Opus 畫一輪月亮，你可以讓它寫出幾行 CSS，再加上山脈、星星、漸層的夜空，就能組成一幅夜景了。

06:20但是，單靠程式碼繪製圖形，表現力還是有局限的。如果能結合生圖模型，製作更多精美的圖片素材，動畫的表現力就能提升一個臺階。所以現在很多 Agent 也內建生圖工具和模型。Codex 有內建的 Image Gen，可以呼叫 OpenAI 的 Image 2.5 模型，直接為動畫生成圖片素材。WorkBuddy 同樣內建了 Image Gen 工具，可以呼叫混元的圖片生成模型來製作素材。而 Claude 本身沒有生圖模型，Claude Code 也沒有內建生圖工具，所以我給它設定了一個 codex-image 的 Skill。當它需要圖片素材時，可以直接把 Codex 叫起來幫它生圖。

用一個案例拆解過程 A case study of the full process

06:58依賴設定好了，可以開始做動畫。這時候，很多人的第一反應是：提示詞（prompt）是什麼？不如轉變一下思路。第一，說清楚需求，比研究提示詞（prompt）更重要。Remotion 就是個前端專案，AI 比你更懂技術語言和實作方案，提示詞（prompt）交給 AI 來寫，你更需要做的是讓它理解你的需求。第二，提供參考動畫，比文字描述更有效；提供你想要的效果範本，溝通可以事半功倍。

07:22還是拿音符跳躍這個動畫來舉例。我之前刷到很多相似的影片，覺得很有意思，但不知道該怎麼實作。於是我保存了一個影片樣本發給 GPT，問它：幫我看一下這些動畫，能用 Remotion 實現嗎？還是只能用 Blender？它建議使用 Remotion，不需要 Blender 也能做出這種 3D 的效果。

07:40那我接著問，用你建議的方式需要準備什麼素材？它告訴我需要準備音訊、曲譜、MIDI、MusicXML 等檔案，還解釋了這些檔案分別有什麼作用。那乾脆讓它選好曲目、找好資料吧。它推薦了巴赫的《C 大調前奏曲》（BWV 846），還幫我找到了相關資料的下載地址。

07:56接下來我就在動效庫的 effects/ 目錄下建立了這個資料夾，把這些素材下載進去。發給 Codex 的提示詞（prompt），當然是 GPT 幫我寫的了。這種又專業又囉哩八嗦的提示詞（prompt），誰愛寫誰寫，我反正是寫不出來的。

08:10模型我選擇 Astra，思考強度中等。我的動畫基本是用中等強度做出來的，除非氣得跳腳了才會切到高。大概運行了 18 分鐘就出來了第一版，後面對亮度、小球跳躍幅度等細節調整了幾版。

08:24其實，從零開始製作一個動畫模板，通常很難一次定稿；但模板做好之後，復用來做同類效果，大多就一次定稿了。看到這裡你會不會有點驚訝：整個過程並沒有高深的提示詞（prompt），甚至談不上什麼技巧。其實我自己現在用 AI，很少會去研究提示詞（prompt）具體怎麼寫，更多關注什麼能力可以實現什麼效果，以及怎麼把自己的需求表達清楚。

08:46現在不少 AI 分享不講實際探索的過程和方法，只展現好看的結果，還有讓 AI 倒推整理的提示詞（prompt）。因為把真實的探索過程講出來，一下子就去魅了，也就那麼回事。

08:58對了，可能有人會問：為什麼不直接在 Codex 裡面聊，讓它自己調研方案、下載資料，不是更方便嗎？當然可以，當然更方便。我在 ChatGPT 裡面問，純粹是前期方案調研的時候，不想太過消耗 Codex 的額度。

09:12話說回來，新手上路最好的辦法就是：給參考，先復刻。可以在社群媒體、GitHub 搜尋 Motion、Vibe Motion、MG、Opus 5.5 動畫等等關鍵字，也可以去 Pinterest 之類的設計網站尋找靈感。當然，這種連程式碼都公開的動畫模板，AI 復刻起來就會更容易。總之各種風格、各種樣式，你總能找到自己喜歡的作品。但回歸實際需求，純粹追求好看的設計是沒有盡頭的，你會收穫短暫的虛假成就感，攢一堆好看但用不上的模板，最後沒啥用。

09:46製作 Remotion 動畫的難度，不一定和時長、畫面複雜度成正比，而是需求約束越精細，反而越難做。我們拿幾個例子來看。比如我刷到一個剪紙風格的影片，覺得蠻喜歡的，就讓 Codex 學習這個風格，幫我製作一個日常休閒 Vlog，內容它自己發揮。它做了一個 40 秒的動畫，第一版我就 OK 了。還有這個講諾貝爾醫學獎的科普動畫，足足兩分半鐘，我用 Opus 5.5 製作，幾乎一版定稿。因為這類需求比較開放，我只要求風格和內容主題，對具體的畫面元素、鏡頭角度、動畫細節沒有具體限制，AI 有很大的自由創作空間，更容易一兩版定稿。

10:25但這個動畫的地圖轉場就短短幾秒，但我對地圖大小、傾斜角度、彈出模組的透明度、鏡頭推進的時機和速度等等，都有很刁鑽的要求。這時候即使 AI 已經做得很好看了，只要某個細節不符合預期，就還得繼續調整。有時候可能就幾個參數，你可能要跟 AI 反覆溝通好幾個回合。

用 Studio 調整控制參數 Tweaking parameters in Studio

10:46這種情況建議調出 Remotion Studio，讓 Agent 把你想調整的地方設定成可編輯的參數，再打開 Studio。這樣你就可以在一個視覺化的介面裡，自己動手調整了。

10:58不過這裡提醒大家，動手之前，讓 Agent 先用 Git 保存當前版本。因為在 Studio 裡調整的參數會直接存回專案程式碼。如果你調整之後不滿意，就讓 Agent 恢復之前的版本，不用擔心改壞了。

預先準備圖片的幫助 Why preparing images first helps

11:12很多時候我其實挺建議先準備一些圖片素材，這樣後面正式做動畫的時候，流程會順暢很多。舉個例子，我在 YouTube 看到一個影片，覺得這個風格很適合做敘事類內容，我就發給 GPT，說要參考這個風格來講 OpenAI 和 Anthropic 的淵源。GPT 一下就來勁了，嘰哩咕嚕開始寫故事腳本。我讓它把幾個重要的靜態畫面做出來，才好具體討論。

11:36你看，畫面出來之後立刻就變得很具體了。你一眼就能判斷這是不是自己想要的，有偏差的地方也可以在這個階段先修正了。接著讓 GPT 把這個畫面裡的關鍵人物和素材，做成透明底的 PNG，這樣 Codex 可以直接拿來用。如果沒有提前準備，或者在實際製作動畫中發現不是那麼符合，Codex 也可以自己補全或重做素材，畢竟自帶著生圖能力。當然，給 Codex 的提示詞（prompt）也是 GPT 寫的。然後，這個動畫就是這麼來的。

手繪風格的動畫 Hand-drawn style animation

12:11關於手繪風格的動畫，可以分兩種情況。一種是像這樣的簡單線稿，直接做成 SVG 素材就可以了。因為 SVG 本身就包含著圖形的路徑資訊，Remotion 可以透過程式碼，讓這些線條沿著路徑一點點顯現出來，來模擬畫筆繪製的過程。這種線條少、結構清晰、路徑簡單的畫面就特別適合。但是如果畫面比較複雜，用 SVG 做逐筆繪製就有難度了。

12:36比如我想用手繪動畫來講馬斯克和 OpenAI 之間的糾葛。還是跟前面一樣，先跟 GPT 聊訴求，它又開始嘰哩咕嚕寫腳本，然後生成場景畫面。我覺得還行，讓它把畫面做成四張 SVG。GPT 還考慮到要適合 Remotion 繪製，打包好方便下載，非常貼心。下載一看——呵呵呵，它，它是不是故意的？甩回去給它，我說謝謝你，它倒是秒跪，還知道檢討錯誤。這是重新做的一版。

13:05接下來就要進入到動畫製作了。GPT 不建議用 SVG 繪製路徑，因為畫面太複雜、路徑數量多、順序還亂。它更推薦模擬手繪的方法：就是用一個畫筆或遮罩，走到哪裡，哪裡就逐步顯現，做出一種「像是在畫出來」的效果。

13:20但咱主打一個不聽勸、不信邪，非要試一下真正的 SVG 路徑繪製。結果……好吧，該聽勸的時候得聽勸。按 GPT 建議的方式重新製作的版本，有一說一，能看出來是假裝在畫畫。

13:36如果你想做比較真實的手繪動畫，有一個 Skill 推薦：srt-whiteboard-animation（SRT 白板動畫 Skill）。用這個 Skill 做出來的效果是這樣的。畫面做了重繪，原來版本的線條太複雜了。不過這個 Skill 有點吃 token，大家根據效果需求來選擇。

13:50前面講了這麼多有參考影片的例子，但實際做動畫的時候，不一定每個想表達的內容都能找到合適的範本。我還是跟 AI 聊需求，而且我很習慣用語音輸入法，跟嘮嗑一樣跟它聊想法。

14:02比如之前我做個人知識庫的解說影片，有這麼個畫面需求：我想表達個人知識庫搭建之後，其實有很多檔案，這些檔案在系統資料夾裡一個個點開看就挺麻煩的。我還把資料夾和 Obsidian 的截圖發給了 AI，讓它看一下怎麼來設計動畫，能直觀表達出來這個意思。這個動畫就是 Codex 根據我描述的需求直接製作出來的。

14:25有些時候我也會簡單粗暴地跟它聊需求，直接把旁白文本發給它讓它製作動畫，要求直觀清晰地呈現，不要花裡胡哨。這是 Codex 直接做出來的效果。其實這些動畫也都是這麼來的：看起來比較普通，也不酷炫，但是滿足我的要求，直觀好理解。

地圖動畫，接入高德 API Map animations with Amap API

14:43製作這種需要用到真實地圖資料的動畫，可以接入高德地圖 API。它有免費的呼叫額度，對於普通個人完全夠用了。需要到高德開放平台去申請 API 金鑰：點選建立新應用，類型選擇「出行」，添加 Key，選擇 Web 服務。

15:00這裡說一下 Web 服務和 JSAPI 的區別。Web 服務主要是取得地理資料和靜態地圖圖片；JSAPI 更適合在網頁裡載入互動式地圖。用於 Remotion 製作動畫的場景，其實 Web 服務就夠用了。查看配額這裡，可以了解每月免費呼叫額度詳情。然後讓 Agent 幫你把高德 API 接入 Remotion 專案中，提示詞（prompt）可以參考畫面。提醒一下：不要直接把金鑰用對話發給 AI，讓 Agent 設定好 .env 檔案，自己填進去，或者它會彈窗給你填寫。

15:30如果要製作像這種透明底的動畫素材，可以一開始就告訴 Agent，要求輸出透明背景；或者已經做好的動畫，讓它重新改成透明底的也可以。

15:41有人問能不能把這些動畫放進 PPT 裡當素材？當然是可以的，因為 PPT 本來就支援插入影片。不過，半透明的動畫效果就要注意一下了：因為動畫裡有陰影或者半透明的情況，點選播放就可能出現黑邊或者鋸齒。

以下為譯者整理，非原片內容

這支影片在說什麼

講者用自己做 Remotion 動畫的完整過程說明：這不是「一個 Skill、一段提示詞（prompt）就能出片」的速成術。Remotion 是用程式碼定義動畫、再逐幀算繪的工具；和可靈（Kling）這類影片模型比，畫面可能比較生硬，但音畫能精準同步，做完還留下可複用的專案。影片從模型怎麼選、工作環境（harness）怎麼踩坑，講到如何安裝官方 Skill、建立長期「動效庫」，再用音符跳躍、手繪和地圖動畫把流程走一遍。

為什麼值得學

如果你也想用 AI 代理做可反覆修改、可複用的動畫，卻卡在「提示詞（prompt）該怎麼寫、會燒多少 token」，這支影片把那些問題拆回實際工作環節：需求怎麼講、參考怎麼給、模板怎麼做、環境出問題時怎麼檢查。它不神化某一個模型或某一段提示詞（prompt），而是把可複製的方法攤開來。

你可以帶走的重點

1. Remotion 和影片模型不是同一條路

影片模型用神經網路「生成」畫面，質感往往更好，但像音符跟著樂譜跳這種必須精準對齊的效果，很難穩定做到。Remotion 則是程式化動畫：元素、軌跡、時間軸都寫在程式裡，再逐幀算繪。代價是看起來可能比較生硬，好處是做完不只留下一支影片，還留下可以替換素材、調整參數的專案。成本也不能直接比：前者多按時長和次數計費，後者更接近氛圍編程（vibe coding），主要消耗 token 或額度，反覆修改也會燒用量。

2. 先用強模型做模板，再用 DeepSeek 複用

講者把模型看成有明顯梯隊。Opus 5.5 像一名審美在線的導演，給個參考影片或風格就常能抓住感覺；Astra（講者常用 GPT-6 Astra）更像老實執行你想法的工匠，推理和開發更快，審美相對克制。DeepSeek-v4 適合當日常產量主力，但從零做複雜動畫，效果經常「像被雷劈了一樣」；若把 Astra 做好的運動模板（軌跡、視覺、鏡頭、Composition）交給它做同類樂曲，就常常一次能看。省額度的關鍵不是逼弱模型從零創造，而是讓它複用已經驗證過的模板。

3. 同樣的模型，換工作環境（harness）就可能翻車

講者習慣用 Codex 做模板，再用 WorkBuddy 叫 DeepSeek 復刻，以節省 Codex 額度（WorkBuddy 每天可領 100 積分）。但不少人回饋：同一專案、同一套提示詞（prompt），在 WorkBuddy 裡做 Remotion 可能跑一兩個小時、耗掉幾百積分還失敗；切到 Claude Code 就順利完成。原因是 WorkBuddy 的執行環境對 Remotion 不友善，代理（講者暱稱為「大胖魚」）會不停掉進換路徑、寫 workaround、繞限制的坑裡。標語是：「很多時候，飯是大胖魚吃的，但鍋是 WorkBuddy 的。」補上針對 Remotion 的 Runtime Rules，能少踩一些坑。講者自己的參考數字：DeepSeek 做幾秒的簡單動畫只需幾個積分，一分鐘的音符跳躍大約 30 積分。

4. 先裝官方 Skill，專案做成長期「動效庫」

開工前先讓 Agent 安裝 Remotion 官方 Skill（這是一套合集，其中最常用的是 remotion-best-practices），並檢查電腦的基礎執行環境。Remotion Studio 可以讓 Agent 打開操作台即時預覽，你也能自己調位置、角度、顏色，不必每個小細節都來回對話；Codex 也可在外掛裡安裝。專案不要每支動畫新建一個：Remotion 本質上是基於 React 的前端專案，反覆初始化又裝依賴，額度先燒掉，硬碟也被占滿。講者的做法是建一個叫「動效庫」的長期專案，根目錄統一管理依賴，每個動畫放在 effects/ 下的獨立子資料夾，需要時直接在對應對話裡繼續提需求，或換一個 Agent 打開同一個專案。等流程穩定了，再考慮搭什麼工作台。

5. 說清楚需求、給參考，比鑽研提示詞（prompt）重要

Remotion 是前端專案，AI 通常比你更懂技術語言和實作方案。提示詞（prompt）可以交給 AI 寫；你要做的是讓它理解需求，並盡量提供參考動畫。音符跳躍案例裡，講者把範例影片發給 GPT，問能不能用 Remotion 而不是只能用 Blender；再請它列出要準備的音訊、曲譜、MIDI、MusicXML，連曲目都讓它選（巴赫《C 大調前奏曲》，BWV 846）。發給 Codex 的那一段「又專業又囉哩八嗦」的提示詞（prompt），就是 GPT 寫的。模型用 Astra、思考強度中等，約 18 分鐘出第一版，再調亮度和跳躍幅度。從零做模板很難一次定稿，但模板做好後，復刻同類效果大多一次就能收。

難度也不跟時長成正比。剪紙風格的 40 秒休閒 Vlog、兩分半的諾貝爾醫學獎科普，因為只限定風格和主題，AI 發揮空間大，常常一版定稿。短短幾秒的地圖轉場，如果對大小、傾角、透明度、鏡頭時機要求很刁鑽，就算已經很好看，一個細節不對也得繼續改。這種時候不要只靠對話死磕，調出 Remotion Studio，讓 Agent 把要調的地方做成可編輯參數，自己在視覺化介面裡改。動手前先讓 Agent 用 Git 保存當前版本，因為 Studio 會把參數直接寫回程式碼；不滿意再還原。

6. 先準備畫面，再進動畫；複雜手繪別硬走路徑

正式做動畫前，先讓 GPT 把關鍵靜態畫面做出來，對錯一眼能看出來，偏差也可以先改。再把人物和素材做成透明底 PNG 給 Codex 用。Codex 自己也有生圖能力，必要時能補全或重做；給它的提示詞（prompt）同樣可以讓 GPT 寫。大語言模型本身不會生圖：簡單元素可用 CSS 等程式碼畫，精美素材則靠各環境的生圖工具——Codex 內建 Image Gen（可呼叫 OpenAI 的 Image 2.5），WorkBuddy 可呼叫混元，Claude Code 沒有內建生圖，講者為此加了 codex-image Skill，需要時再把 Codex 叫起來。

手繪可分兩種。簡單、路徑清楚的線稿，做成 SVG，讓 Remotion 沿著路徑逐筆顯現即可。畫面一複雜，路徑又多又亂，硬走 SVG 路徑很容易翻車；GPT 更建議用畫筆或遮罩掃過，做出「像是在畫出來」的效果。講者不服氣試過真路徑，最後還是聽勸。若要更接近真實手繪，可以試 srt-whiteboard-animation（SRT 白板動畫 Skill），不過比較吃 token。找不到參考範本時，用語音像嘮嗑一樣把需求講清楚，或把旁白直接丟給 AI，再補上資料夾、Obsidian 截圖，也可以做出直觀好懂、不一定酷炫的動畫。

7. 地圖動畫用高德 Web 服務，金鑰不要貼進對話

需要真實地圖資料時，可到高德開放平台申請 API 金鑰：應用類型選「出行」，添加 Key 時選 Web 服務，不要選 JSAPI。Web 服務用來取得地理資料和靜態地圖圖片，就夠 Remotion 使用；JSAPI 更適合在網頁裡放互動地圖。個人有免費呼叫額度。讓 Agent 幫忙接入專案時，不要把金鑰用對話發給 AI，改讓它先設好 .env，你自己填 AMAP_KEY，或等它彈窗再填。若要當疊圖素材，一開始就要求透明背景。這些動畫可以放進 PPT，但有陰影或半透明時，播放可能出現黑邊或鋸齒。

怎麼開始

  1. 跟你的 Agent 安裝 Remotion 官方 Skill（常用 remotion-best-practices），並檢查本機執行環境。
  2. 建一個長期「動效庫」專案，根目錄統一安裝依賴，新動畫放在 effects/ 子資料夾，不要每支新建專案。
  3. 找一支你喜歡的參考影片（可在 GitHub、社群媒體搜 Motion、Vibe Motion、MG、Opus 5.5 動畫，或到 Pinterest 找靈感），先復刻，不要一開始就追求全新設計。
  4. 先跟 GPT 或 ChatGPT 把需求、素材清單和提示詞（prompt）聊清楚（也較不燒 Codex 額度），再用 Astra 這類較強的模型做模板；同類效果再交給 DeepSeek 複用。
  5. 若所在環境對 Remotion 不友善，先檢查工作環境（harness）和 Runtime Rules，不要只換模型。
  6. 要精調參數時，先 Git 保存，再打開 Remotion Studio；地圖類需求用高德 Web 服務，金鑰只放在 .env。

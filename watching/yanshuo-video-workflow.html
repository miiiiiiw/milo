00:12展開具體內容之前，我想先分享兩點。第一：用程式碼做動畫沒有固定套路。我分享自己摸索的一些方法，如果能讓你收穫一些啟發或者靈感，那這期分享就值得了。

00:26我自己的習慣是極簡主義先行：能不額外加 Skill 就先不加，非必須的約束也先不加。我管它三七二十一，先跑起來；跑偏了，再增加約束。因為現在模型越來越聰明了，官方文件反覆強調：不要拿過去老模型的方法來用現在的模型。而我自己的體驗也是，少加約束的時候，AI 反而交出了一些讓我驚喜的效果。

00:52我製作講解影片會先準備這些素材，用 Remotion 來製作。接下來我們就細拆上期影片製作的每個環節。

腳本 Script

01:04首先我會準備一份相當於逐字稿的腳本。另外，那些旁白不念出來、但要在畫面裡展示的提示詞（prompt）或說明，也會整理進腳本。

01:14我的影片腳本主要自己寫，因為我覺得 AI 寫的東西特別沒有體感。腳本還可以交給 AI 來寫，但分享自己的經驗和方法論，如果非要推薦一個 AI 寫腳本的話，那目前 Gemini 是一騎絕塵，GPT 就是個差等生。

01:34還是重點聊兩個大家比較關心的問題：要不要備註對應素材？要不要寫每一段的動畫要求？

01:42像我上期的影片有大量的截圖、錄屏，我沒怎麼標註也還行。但那是因為 Opus 5.5 模型本身足夠強，而且有些瑕疵的地方我也算了。所以我的建議是：最好在腳本對應的段落，標註上可用哪些素材。這樣能減少 Agent 用錯素材、後期返工的情況。不過手動標註太繁瑣了，可以在素材收集好之後，讓 Agent 幫忙匹配，你來做確認和修改。

02:06接下來，要不要規劃分段的腳本？我是幾乎不寫的，只在個別地方做了備註。例如對比三個模型能力那段，我就標註了 Claude、Codex 和 DeepSeek 三個玩偶的互動。但整條影片下來其實有踩坑：比如檢查電腦環境設定，還有初始化 Remotion 專案，這兩個環節的提示詞（prompt）我明明放在腳本裡了，結果 Opus 直接給我略過，影片裡只展示了幾個要點。所以一些原則性的要求，最好還是提前備註清楚，甚至寫入專案的 AGENTS.md 裡。

02:40但如果說要提前規劃好每一段的動畫，以我對解說影片的要求，我認為沒有必要。當然有人說可以讓 AI 來規劃，然後自己來修改確認——啊，真的嗎？就算讓 AI 寫出來，我看一遍都覺得費勁。那怎麼來控制整個影片的動畫效果呢？這個在後面環節裡聊。

素材 Assets

03:00講解類影片通常會涉及大量的截圖、錄屏等素材。那這些能不能讓 Agent 來幫忙準備呢？如果素材在本機資料夾，或者 Agent 可以造訪的網頁上，就可以協助查找和整理。但是如果散落在各種軟體裡面，具體就得看 Agent 有沒有相應的操作權限，往往需要借助 MCP 外掛或者 Computer Use。所以技術上是可行的，但實際它整理出來的素材，未必都能符合你的要求。可以輔助你做基礎的收集，最後還是需要你自己動手。而且真要嘗試，我建議這步用輕量模型即可，沒必要上強度。

03:36然後有人好奇，我影片裡的這些小玩偶是怎麼弄的。看過我影片的小夥伴都知道，這些是老演員了。我平時攢了一些圖片和動畫素材。比如這個 Codex 的擬人小玩偶，我會先讓 AI 做成綠幕圖片，再丟給影片模型生成動畫。為什麼用綠幕？因為大多影片模型無法直接生成透明底的動畫，綠幕方便去背嘛。

03:58那怎麼把綠幕動畫變成透明底的動畫素材呢？你可以直接丟給 Agent 讓它幫你處理，或者自己在剪輯軟體裡去背一下：先用遮罩把浮水印切掉，然後去背，選擇色度去背，把綠色去掉。去背的強度太高，容易把影子也抹沒了，降低一點。還有綠色怎麼辦？在調整裡找到 HSL，把綠色的飽和度拉到最低，然後匯出，影片編碼選擇 Alpha。匯出的就是透明底的動畫素材了。

04:28你可能想問，為什麼不用程式碼來做動畫素材呢？因為影片模型做出來的動作更流暢自然。其實更主要的是：到處領各家影片平台的「雞蛋」。之前最開心的是千問（Qwen），一天領十個積分，一條十秒的影片才花兩積分。點小積分，做點小素材。

旁白和 SRT Voiceover and SRT

04:54沒想到問得最多的問題，竟然是配音用的什麼工具、是不是 TTS。抱歉了，這是我自己配的音，但做了一些後期音色美化。當然我知道大家更關心的是：能不能省掉自己錄音這一段，讓 Agent 來完成配音。只要讓你的 Agent 接入相應的語音合成工具就可以了。

05:14這裡推薦三個可以免費使用的開源工具，它們都支援透過參考音訊克隆聲音，也能透過文字描述來設計音色。關於這些專案的詳細介紹和操作指引，你可以讓你的 Agent 來指導，這裡我就不具體演示了。

05:30讓 Agent 生成 SRT 字幕，把每句旁白對應的時間戳標記出來。怎麼讓字幕跟配音同步、動畫怎麼跟著旁白節奏走，靠的就是 SRT。Agent 可以根據時間戳，安排字幕和動畫在對應的時間出現。

05:46要注意了，Opus、Astra、DeepSeek 這些模型要根據配音生成 SRT，它得借助語音辨識模型，或者飛書妙記、剪映這些有語音轉文字功能的工具。這裡我最推薦的方法，就是本機部署 Whisper。它是 OpenAI 免費開源的語音辨識模型，有不同規格。我用的是 whisper.cpp 版的 v3-turbo，這是社群開發的，用更輕量的方式來執行 Whisper 模型。安裝前你可以讓 AI 幫你評估電腦設定，然後讓 Agent 生成 SRT。

06:18但有幾個小細節值得你關注。提示詞（prompt）裡可提醒 Agent 參考腳本，因為語音辨識經常會出現專業術語辨識錯誤，有腳本輔助校準就幾乎不會出錯了。另外加上文字寬度的要求，避免長句擠在一起，導致影片出現兩行字幕。比如章節之間想留一點停頓，或者某段動畫需要多一點展示時間，但不可能我們一開始配音就能精準留夠停頓。製作影片的時候，讓 Agent 根據動畫的實際情況，來調整章節之間或語句之間的停頓，但要保證調整後 SRT 的時間戳也要同步。

製作影片 Making the video

06:56到這裡，腳本、素材、配音和 SRT 都準備好了，其實就可以讓 Agent 製作影片了。但我知道大家更關心的是：有沒有動畫模板或者設計風格的 Skill。先說我上期影片的做法：沒有疊加 Remotion 以外的其他 Skill。主要兩個原因。一是我對講解影片的要求就是清晰明瞭、不需要炫技，而很多 Skill 會過度設計動畫，每個轉場秀一下、卡片飛來飛去。二是 Opus 5.5 模型本身夠強，並不需要過度約束它。所以我只給了它一個灰色背景圖，並且要求字體（Plus Jakarta Sans、Noto Sans SC），其他都交給模型來導演規劃。

07:32不過還是要特別提醒一下：無論模型多強，都不建議一上來就做完整的長影片。我上期一次成片，純粹因為當時在感冒發熱，無論它做成什麼樣我都認了。其實應該先讓它做一兩分鐘的片段，然後確認風格、動畫設計是否符合預期，調整好之後，再讓它按這個標準製作整片。不然它能跑上一個小時，等全部做完才發現不喜歡、推翻重來，那時間和 token 成本就消耗太大了。而且很多時候我們自己也說不清楚想要什麼效果，跟你老闆一個樣：要什麼的時候讓你發揮，交付之後呢，這也不行。既然你都說不清楚想要什麼樣的，就讓它先打個板，再來調整。

Skill 推薦 Skill recommendations

08:14借助別人做好的 Skill 先跑起來。GitHub 上 VibeMotion 相關的 Skill 非常多，你可以根據喜歡的風格來選擇。這裡我不負責任地推薦一些，因為我自己比較少用 Skill。

08:28lemo-opuscar 收錄了 66 種動畫風格，涵蓋剪輯紀實、手繪與繪畫、立體書、3D 等 11 個類別，每個風格都有演示成片和對應的製作方法。

08:40huashu-art-motion 主打藝術風格動畫，有 36 種風格，比如像素、梵谷油畫、莫內睡蓮等等；另外還有 9 種解說動畫語法，包括 Vox、白板、數學動畫、動態文字等等。

08:54vox-director 專門做 Vox 風格的解說影片，從腳本、分鏡，到影片生成、配音、BGM 和字幕都可以自動化完成。

09:04這兩個是手繪講解影片的 Skill：sweety-handdraw-video 和 srt-whiteboard-animation。

09:08主打火柴人風格的動畫 Skill 是 stickman-video-director。除了經典的黑白火柴人，還有彩色、洞穴壁畫。如果你想找真人出鏡的影片模板，可以看看這個 motiontemplates，裡面有專門針對口播講解設計的模板，有橫屏和直式的版本。

09:26video-shotcraft 對比前面動畫風格模板，這個 Skill 更偏產品宣傳片的鏡頭工具箱，目前收錄了 150 張鏡頭卡。

09:36mg-styles-15 這個專案收錄了 15 種 MG 動畫風格，從插畫、2.5D、3D 到圖形。

09:42anatomy 不是專門製作影片的，而是擅長把機械設備、複雜系統，轉化成可以互動的立體結構圖。

09:50Skill 實在太多太多了，這裡沒法一一列舉。有些雖然不是以 Remotion 為核心，但同樣透過程式碼來製作動畫，底層的技術棧和依賴高度相似。我覺得找 Skill 還是蠻有樂趣的，就像在遊戲裡到處去撿裝備。不過裝備撿回來未必就趁手：你可能會發現實際效果不如模板，或者做出來千篇一律，又慢又耗 token。這時候你可以改裝升級，或者乾脆拆零件。你去實踐了才有體感。

10:20我給 Agent 裝的 Skill 不多，但我也經常去 GitHub 撿裝備來拆零件：看裡面有哪些模板可以沉澱到自己的動效庫裡，合適的音效可以收進自己的素材庫。而且拆解別人的 Skill 還能偷師，看作者是怎麼把踩過的坑和積累的經驗，梳理成可複用的方法。

音效 Sound effects

10:38最後來聊聊音效。我上期影片的「雷霆音效」都是 Opus 用程式碼合成的。那些叮叮噹噹的電子音，真的很讓人煩躁。

10:48這段時間我也測試了一些，甚至部署了 CLAP、AST 這些音訊理解模型，試圖給 Agent 裝上耳朵，看它合成的音效是否會好些。就一通操作下來，時間和 token 消耗都不小，但實際效果還是很一般。所以我決定換個思路：與其費勁讓 AI 合成好的音效，不如讓它找到合適的音效。

11:10去哪裡找呢？Envato Elements 收錄了百萬個音效，可惜是訂閱制的。但它旗下免費素材平台 Mixkit，有 3,000 多個音效可免費下載，也支援商用。同樣免費可商用的音效庫，還有 Pixabay 和 Freesound，音效素材也相當豐富。注意：Freesound 是部分可商用。

11:30不過把這些音效庫甩給 Agent，它就能找到最合適的音效嗎？因為我們用 Opus、Astra、DeepSeek 這些模型，它們本身沒有耳朵來聽，它們是靠音效的檔名、標籤、說明文字等資訊來篩選。

11:46所以我建議搭建一個自己常用的音效庫。其實解說影片裡常用的音效，來來回回就那麼些，可以整理到一個資料夾裡，讓 Agent 幫你整理標註好。以後製作影片就可以優先從自己的音效庫裡挑選，不用每次重新找或者從頭生成，效果更可控，成本也更低。

12:04另外，社群媒體有不少剪輯師分享，翻一翻就能搜刮到一批音效了。

12:12那這期依舊很囉嗦的分享，就先到這裡。

以下為譯者整理，非原片內容

這支影片在說什麼

這是 Remotion 教學的第二期。講者拿上期那條 16 分鐘的講解影片當例子，把一條影片從腳本、素材、配音、SRT，做到成片和音效的流程拆開來看。重點不是再給一段「萬能提示詞（prompt）」，而是分享他實際怎麼準備、哪裡踩坑、哪些開源工具和 Skill 可以先借來跑。

為什麼值得學

如果你也想用 AI 代理加 Remotion 做講解影片，卻卡在「腳本要不要寫很細、素材誰來整理、配音和字幕怎麼對上、要不要裝一堆 Skill」，這支影片把這些決定放回真實工作順序裡。它強調極簡主義：能不加的 Skill 和約束就先不加，先跑起來再調整；同時提醒，模型再強也不該一上來就做完整長片。

你可以帶走的重點

1. 極簡主義先行，跑偏了再加約束

用程式碼做動畫沒有標準答案。講者的習慣是：能不額外加 Skill 就先不加，非必須的約束也先不加，三七二十一先跑起來，跑偏了再補規則。官方文件也反覆強調，不要拿舊模型的方法套在新模型上。他自己的體驗是：少加約束時，AI 反而常交出驚喜。

2. 講解腳本自己寫，素材要標，原則寫進 AGENTS.md

講者的講解腳本主要自己寫，再用 AI 輔助校驗，因為他覺得 AI 直接寫的東西「特別沒有體感」。若是分享經驗、方法論那類腳本，可以交給 AI；若非要推薦，他目前覺得 Gemini 明顯領先，GPT 差一截。腳本裡除了旁白逐字稿，畫面要展示、旁白不念的提示詞（prompt）或說明也要收進去。大量截圖、錄屏最好在對應段落標註可用素材，減少 Agent 用錯檔；手動太繁可以先讓 Agent 匹配，你再改。不必提前寫好每一段動畫，只在少數對照鏡頭做備註（例如 Claude、Codex、DeepSeek 三個玩偶怎麼互動）。但原則性要求不能只放在腳本裡——上期「檢查環境」「初始化 Remotion 專案」兩段提示詞（prompt）明明寫了，Opus 還是略過——最好寫進專案的 AGENTS.md。

3. 素材可讓 Agent 幫忙收，小動畫常用綠幕

截圖、錄屏如果在本機資料夾或 Agent 能打開的網頁上，可以協助查找整理；散落在各種軟體裡，就得看有沒有 MCP 外掛或 Computer Use 權限。技術上可行，但整理結果不一定符合你的要求，最後還是要自己過一遍。這步用輕量模型即可，不必上強度。影片裡那些「老演員」小玩偶，是先讓 AI 做成綠幕圖，再丟給影片模型出動畫（多數影片模型無法直接出透明底）。去背時先用遮罩切掉浮水印，再用色度去背去掉綠色；強度太高會連影子一起抹掉，殘綠可把 HSL 裡的綠色飽和度拉到最低，最後以 HEVC（Alpha）匯出。為什麼不直接用程式碼做這類小動畫？一來影片模型的動作更自然，二來可以到處領各家平台的積分——他之前最開心的是千問（Qwen），一天十個積分，十秒影片只花兩個。

4. 配音可以自己錄，同步全靠 SRT

上期配音其實是講者自己錄的，只做了後期音色美化。若想省掉錄音，可以讓 Agent 接上開源 TTS：畫面介紹了 GPT-SoVITS、VoxCPM2、IndexTTS-2.5，都支援用參考音訊克隆聲音，也能用文字描述設計音色。字幕、動畫要跟旁白節奏走，靠的是 SRT 時間戳。Opus、Astra、DeepSeek 本身不會聽，得借助語音辨識，或飛書妙記、剪映這類工具。講者最推薦本機部署 Whisper，自己用的是社群維護、較輕量的 whisper.cpp（v3-turbo）；安裝前可先讓 AI 評估電腦設定。提示詞（prompt）裡記得請 Agent 參考腳本校準術語，並限制字幕寬度，避免兩行擠在一起。章節停頓或某段動畫要多留時間，製作時再調，但調整後 SRT 時間戳必須一起改。

5. 先打個板再做整片；Skill 當裝備，不趁手就拆

上期成片沒有疊加 Remotion 以外的 Skill，一是講解片只要清晰、不必炫技，很多 Skill 會讓卡片飛來飛去；二是 Opus 5.5 夠強，不必過度約束——他只給了一張灰色背景圖，並指定字體（Plus Jakarta Sans、Noto Sans SC），其餘交給模型導演。即使模型很強，也不建議一上來就做完整長片。上期一次成片，是因為他當時感冒發熱，做成什麼都認了。正常做法是先做一兩分鐘確認風格，再按同一標準做整片，否則跑一小時才推翻，時間和 token 都太貴。自己也說不清要什麼的時候，更該先打個板。

GitHub 上 VibeMotion 相關 Skill 很多，可以先借別人做好的跑起來。講者不負責任地列了一些：lemo-opuscar（66 種風格、11 類）、huashu-art-motion（36 種藝術風格加 9 種解說語法）、vox-director（Vox 風格解說，腳本到字幕可自動化）、sweety-handdraw-video 與 srt-whiteboard-animation（手繪講解）、stickman-video-director（火柴人）、motiontemplates（口播、有橫式直式）、video-shotcraft（150 張宣傳片鏡頭卡）、mg-styles-15（15 種 MG 風格）、anatomy（把複雜系統做成可互動結構圖，不是專門做影片）。裝備撿回來未必趁手，可以改裝，或拆零件沉澱進自己的動效庫；拆別人的 Skill，也能看到作者怎麼把踩過的坑寫成可複用的方法。

6. 音效與其合成，不如找到；再自建常用庫

上期「雷霆音效」是 Opus 用程式碼合成的，事後覺得叮叮噹噹很煩躁。他試過部署 CLAP、AST 這類音訊理解模型，想給 Agent 裝耳朵，時間和 token 花了不少，效果仍普通。於是改成「讓它找到合適的音效」：Envato Elements 雖然有上百萬條，但是訂閱制；旗下 Mixkit 有三千多條免費可商用，Pixabay 也可免費商用，Freesound 素材豐富但只是部分可商用。不要指望把整個音效庫甩給 Opus、Astra、DeepSeek 就能挑到最好的——這些模型沒有耳朵，是靠檔名、標籤和說明來篩的。更穩的作法是自建常用音效庫：解說片來來回回就那些聲音，整理好讓 Agent 標註，以後優先從自己的庫挑。社群媒體上剪輯師分享的音效，也可以順便蒐集。

怎麼開始

  1. 先寫一份相當於逐字稿的腳本（講解類建議自己寫），在對應段落標註可用素材，把原則性要求寫進 AGENTS.md。
  2. 截圖、錄屏自己收集為主，Agent 只做輔助；小動畫可用綠幕流程做出透明底。
  3. 旁白可自己錄，或讓 Agent 接 GPT-SoVITS、VoxCPM2、IndexTTS-2.5。用本機 Whisper 生成 SRT，並用腳本校準術語、限制字幕寬度。
  4. 不要一上來做完整長片：先打一兩分鐘的板，確認風格再做整片。Skill 能借就借，不順手就拆進自己的動效庫。
  5. 音效優先從 Mixkit、Pixabay 或自建音效庫找，而不是讓模型用程式碼合成電子音。

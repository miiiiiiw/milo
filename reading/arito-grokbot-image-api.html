別再為了幾張封面來回切視窗了！我把便宜的生圖 API 塞進 Grok Bot，一個聊天框就能出圖，成本直接砍到零頭，全程不寫一行程式碼。這套全網爆紅的流程，今天一次全部公開！！！

最近，我把自媒體工作流程搬進了 Grok Bot：剪影片、做配音、找資料、管素材、寫初稿、看營運數據、拿營運建議，日常創作基本上都能在一個工作台裡完成，不少流程也已經自動化跑起來了。

但每天寫文章，我還要頻繁製作推文封面和角色插畫。以前我在 Notion 寫稿，用 image 2.6 生圖；想換模型，或呼叫手上更便宜的第三方 API，就得在不同工具之間來回切換：生成、下載、再上傳。幾張圖，硬是把創作節奏切得七零八落。

生圖流程我之前一直在琢磨：我想用 GPT 圖像模型做封面，也想把手上便宜的第三方 API 額度用起來。可每次出圖，都得切到 Codex，生成後下載，再傳回工作流程。為了幾張圖來回折騰，思路斷了，效率也被拖慢。

我想要的其實很簡單：寫稿、出圖、取圖，全在 Grok Bot 的一個聊天框裡完成；模型我來選，成本也由我控制。

後來我發現，根本不用再部署一套新工具。Grok Bot 自帶雲端電腦和終端機，只要準備好外部生圖 API，再配一個輕量的 Python 腳本，就能把整條流程接起來。

今天把整套省錢又提升效率的建置流程拆開來講。就算你完全不會寫程式，直接把文中的兩段提示詞複製給 Grok Bot，它自己就能把環境建好。

一、Grok Bot 本來就能生圖，為什麼還要外掛 API？

Grok Bot 原生就有生圖工具，偶爾畫一張圖，直接叫它就行。但只要你每天大量出圖，馬上就會算清楚這筆時間和金錢的帳：

省錢：自己買的第三方 API 或特定管道額度往往便宜得多，大量出圖能省下一大筆預算。（Grokbot）

省事（不用切視窗）：寫完推文，順手就在同一個聊天框裡把配圖做出來，不用在多個網頁之間來回跳。

省時間（不必重複寫設定）：手上有固定的個人 IP 角色設定圖，希望每次生圖自動帶上，不用每次都重新複製貼上幾百字的外貌描述。

自動歸檔：把你要用的素材圖片和生成好的圖片，直接按日期整整齊齊存在雲端電腦的素材資料夾裡，隨用隨取，讓 AI 充分運用以圖生圖。

所以最划算的做法是：一般雜事直接用原生工具；大量、指定風格的出圖任務，就讓它去呼叫我掛上去的外部便宜 API。既不用改變使用習慣，又把成本和效率全握在自己手裡。

二、30 秒搞懂：腳本是怎麼幫你省事的？

真正出圖的是外部模型，真正發出請求的是雲端電腦裡的 Python 腳本；

「當使用者點名要用 GPT 生圖時，別用原生工具，直接去雲端電腦執行 image.py 腳本，把提示詞傳進去，執行完把生成的圖片讀出來，發回聊天框。」

或者以後讓它預設呼叫這個 API 來生圖，預設數量、樣式都由你決定。

整條流程一氣呵成：

你下指令 → Grok Bot 讀取 Skill → 執行雲端電腦裡的腳本 → 呼叫外部便宜 API → 圖片存進雲端電腦 → 讀出圖片發回給你

因為 Grok Bot 自帶的雲端電腦本身就有硬碟和終端機，這套流程直接在它的背景就能跑完，連租雲端伺服器的錢都省了。

三、四步實作：把外部生圖 API 塞進 Grok Bot

這裡以串接 OpenAI 圖像 API（或相容的中轉站介面）為例，一共只有四步：

第一步：準備好 3 個 API 參數

先從你的 API 服務商後台拿好三樣東西：

  • API Key：你的金鑰
  • Base URL：介面網址（官方為 https://api.openai.com/v1，中轉站則填對應網址）
  • Model：模型名稱（例如 gpt-image-2.6-flare，以服務商實際支援的為準）

⚠️ 儲值前必看的省錢避坑重點：很多便宜的第三方中轉站嘴上說「相容 OpenAI 介面」，其實只做了文字聊天（/chat/completions），根本沒做生圖介面（/images/generations）。儲值之前，一定先看一眼文件，確認支不支援生圖，以及回傳格式是 Base64 還是圖片 URL。

第二步：丟一段提示詞，讓 Grok Bot 自己寫腳本

不用自己敲程式碼，直接把下面這段話傳給 Grok Bot：

使用 Codex CLI 幫我開發一個輕量級的生圖呼叫腳本，供 Grok Bot 呼叫，寫好後跳出網址和金鑰的輸入框讓我填寫。要求：使用 Python 撰寫，直接呼叫中轉站的 OpenAI GPT 圖像生成 API，設定第三方 API 中轉站網址、API Key 和模型名稱。

支援文字生圖、參考圖生圖、圖片編輯，支援自訂提示詞、尺寸和品質參數。

透過關鍵字呼叫，只要和生圖有關就呼叫。每次出圖一次出 2 張。

生成的圖片自動存到本機，並輸出圖片檔案路徑。

API Key 用環境變數管理，支援逾時、錯誤處理和失敗重試。

盡量使用標準函式庫，不引入複雜框架，不需要 Web UI、資料庫或獨立伺服器。

提供 README、設定範例和呼叫範例。

目標：讓 Grok Bot 能直接執行腳本生成圖片，並讀取生成結果。優先相容現有的 Grok Bot 雲端電腦環境。

如果你想自己直接貼程式碼，只要在雲端電腦執行一句 pip install openai，然後存下面這 30 行的最簡腳本（按 Base64 回傳格式撰寫；如果中轉站回傳的是 URL，存檔邏輯需要微調）：

image.py（原文程式碼，提示字串已轉繁中）

import os, sys, base64
from pathlib import Path
from datetime import datetime
from openai import OpenAI

if len(sys.argv) < 2:
    sys.exit("用法: python image.py '圖片描述'")

client = OpenAI(
    api_key=os.environ["OPENAI_API_KEY"],
    base_url=os.getenv("OPENAI_BASE_URL", "<https://api.openai.com/v1>"),
    timeout=180, max_retries=1
)
result = client.images.generate(
    model=os.getenv("IMAGE_MODEL", "gpt-image-2.5-flare"),
    prompt=sys.argv[1], size="1536x1024", quality="medium"
)
output_dir = Path("generated_images")
output_dir.mkdir(exist_ok=True)
output_path = output_dir / datetime.now().strftime("%Y%m%d_%H%M%S_%f.png")
output_path.write_bytes(base64.b64decode(result.data[0].b64_json))
print(output_path.resolve())

譯註：原文第 11 行（base_url）的網址被包在角括號 <…> 裡，看起來是排版時自動加上的連結符號；實際使用時應寫成 "https://api.openai.com/v1"，否則預設網址會無效。另外，腳本預設模型寫的是 gpt-image-2.5-flare，與第一步範例的 gpt-image-2.6-flare 不同，兩處均照原文保留。

第三步：把腳本打包成可永久重複使用的 Skill

腳本跑通後，緊接著傳第二段話給 Grok Bot，把流程固定下來：

請將剛才的 image.py 整理成一個可重複使用的 Skill，命名為「GPT 外部生圖」：當我明確說「生圖」「呼叫外部圖像模型」時，強制觸發這個 Skill；

觸發後擷取我的畫面描述，呼叫腳本生成圖片，讀取存好的檔案，直接作為附件發回聊天框。

呼叫出錯時直接回傳具體的錯誤訊息，嚴禁自動重試付費請求。

觸發關鍵字時，去素材包尋找對應的圖片。

第四步：實際驗收

直接對它說：「用 GPT 幫我畫一張 16:9 的科技風推文封面，冷色調，不要文字。」

只要確認它確實走了外部介面、圖片存進了資料夾，而且順利把圖回傳到聊天框，這套外掛就徹底打通了。以後也就是一句話的事。

四、讓它自動鎖定你的個人 IP 素材庫

把外部 API 接進來只是省了錢，真正能幫你省下大把時間的，是用它來管理固定的角色設定素材。

比如我平常做圖，經常用到自己的個人 IP 角色 Muon。以前每次畫封面，我都得把「亂髮、黑框眼鏡、深色連帽衫」的設定翻出來重新貼一遍，漏寫一個詞，畫風就跑掉了。

現在直接在 Grok Bot 的雲端電腦裡建一個固定的素材目錄：

  • references/muon.png：存角色的標準參考圖
  • prompts/muon.txt：存固定的角色外貌描述
  • generated_images/：存所有生成好的成品圖

然後把腳本升級成呼叫「圖像編輯／墊圖介面（Image Edits）」，並在 Skill 裡加一條鐵律：「只要提到用 Muon 做圖，就自動去讀 muon.txt 的設定，並掛上 muon.png 當參考圖，不准擅自改動角色的核心外貌。」

設定好之後，現在我每天寫完推文，只要順口說一句：「用我的個人 IP 做一張關於今天文章的封面。」它就自己在背景把角色設定詞和參考圖全掛上了，連翻資料夾、複製貼上的工夫都省了。

五、動手前必看的 3 個注意事項

絕對不要把 API Key 寫進 Skill 文字裡：Skill 很容易被你順手分享給朋友，或匯出備份。金鑰必須乖乖待在雲端電腦的環境變數或憑證庫裡，別為了省一分鐘把額度洩漏出去。

嚴禁腳本自動無限重試：生圖 API 是按張扣錢的。上面給你的提示詞與腳本裡，專門用 max_retries=1 和「出錯不准自動重試」來限制，就是為了防止網路一卡，腳本在背景偷偷呼叫十幾次，把你的餘額燒光。

外掛 API 省的是生圖費，不是對話額度：圖像的算圖帳單走的是你外掛的便宜 API，但 Grok Bot 理解你的話、操作終端機、傳檔案，還是會正常消耗一點它自己的對話額度。

其實你根本不需要再多養一個專門的生圖工具。只要給手上的主力 Bot 寫好一份清楚的 Skill 說明書，它就是你的自媒體工具站，能在一個視窗裡調動所有便宜好用的外部工具。以前為了省點錢、換個模型，我電腦上常年開著五六個聊天視窗，自己活成了複製貼上的中轉站。

這篇在說什麼

作者是自媒體創作者，每天要做很多封面和角色插畫。以前他得在好幾個工具之間切來切去：生成、下載、再上傳。這篇教你讓 Grok Bot 在同一個聊天框裡，呼叫你自己買的、比較便宜的外部生圖服務（API），並自動帶上你的固定角色設定，省錢也省時間。

做法分四步：準備好服務商給的三個參數、請 Grok Bot 寫一支小程式（腳本）、把流程存成可重複使用的 Skill、最後實際測一次。作者強調全程可以不寫程式，只要把文中兩段話複製給 Grok Bot。

為什麼值得學

很多人用 AI 做圖時，時間其實不是花在「生成」，而是花在「搬運」：換工具、重貼角色描述、下載再上傳。這篇示範的思路是把這些搬運工作交給 AI 代理（Agent）自己處理，你只要下指令。

即使你不打算接外部 API，「把固定設定存成檔案、讓 AI 每次自動讀取」這個做法也適用於任何重複性工作，例如固定的文章格式、品牌配色或簽名檔。

你可以帶走的重點

1. 偶爾用內建，大量用外掛

Grok Bot 本來就能畫圖，偶爾一張直接叫它就好。但每天大量出圖，自己買的第三方額度通常便宜得多，也不會佔用 Bot 本身的額度。

好比家裡偶爾印一張紙用家用印表機就好，但每週要印幾百張傳單，找影印店包月反而划算。

2. 儲值前先確認對方真的支援「生圖」

不少便宜的轉售服務（文中稱「中轉站」）宣稱「相容 OpenAI」，實際上只能聊天、不能畫圖。付錢前先看文件：有沒有生圖功能、回傳的是圖片檔內容（Base64）還是圖片網址。

3. 讓 AI 幫你寫小程式，再存成 Skill

你不必會寫程式：把需求講清楚（用什麼語言、要支援哪些功能、金鑰怎麼保管、出錯怎麼辦），AI 就能寫出腳本。跑通後再請它整理成 Skill，下次說一句「生圖」就會自動照流程走。

4. 把固定角色存成檔案，不再每次重貼

作者把角色參考圖、外貌描述、成品圖分別放在固定資料夾，並在 Skill 裡規定「提到 Muon 就自動帶上設定和參考圖」。從此一句「用我的個人 IP 做封面」就夠了，也不會因為漏寫一個詞而畫風跑掉。

怎麼開始

  1. 先算一下自己的用量。如果一週只做幾張圖，用內建工具就好；每天都要大量出圖，才值得接外部 API。
  2. 挑服務商，先查文件再儲值。準備好 API Key、Base URL、模型名稱三樣東西。
  3. 把原文第二步的提示詞貼給 Grok Bot，讓它寫腳本並跳出輸入框讓你填金鑰；再用第三步的提示詞存成 Skill。
  4. 用一句話實測，確認它真的走了外部 API、圖片有存進資料夾、也回到聊天框。
  5. 最後把角色參考圖和描述放進固定資料夾，在 Skill 裡加上自動帶入的規則。

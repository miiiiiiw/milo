一、Grok Bot 1.0 和會議功能

1. 問：Grok Bot 1.0 裡你最喜歡哪個功能？（0:42）

答：Lauren 先說喜歡購物功能，因為她自己買東西多。接著她說會議功能也很好。Grok Bot 現在能替你加入 Google Meet 和 Zoom 會議，做會議紀錄，還能在會議聊天區回覆。Matt 補充說，這和那種只會進會的會議機器人不一樣，接到 Grok Bot 上的連接器（connector）在會上都能用，比如讓它去 Notion 或 Slack 裡查東西。

原話：「It's like you have a personal assistant that's like answering your questions in a meeting.」

中文翻譯，就像會上有個私人助理在替你回答問題。

二、用量、例行任務（routine）和 Webhook

2. 問：能不能用工具呼叫（tool call）查剩餘用量？（4:55）

答：Matt 說可以。點大頭貼進設定，打開 usage and billing，在 Grok Bot usage 那一欄可以按 Bot 篩選，看清用量花在哪裡。他的建議是把例行任務合併、刪掉，或者降低執行頻率，因為例行任務很耗用量。

回答延伸（5:39）

Lauren 說 Webhook 被低估了。例行任務是按時間醒來，Webhook 是外部服務有動作時才觸發 Bot。她舉了 Linear 的例子，Linear 自帶 Webhook 整合，可以只在真正有動作時叫醒 Bot。Webhook 的入口不太好找，她建議直接讓 Bot 幫你看哪些例行任務可以改成 Webhook。

她還說團隊在看一份新的 MCP events 規範。現在例行任務每小時醒來查一次行事曆，行事曆沒變也要花 token；如果支援 events，Bot 只在真有事發生時才醒。這是「正在看」的方向，沒有說已經上線。Matt 說這件事做成了會很重要。

3. 問：用量限制的問題你們知道嗎？（15:06）

答：Lauren 說知道。她建議去用量頁按 Bot 看誰最費用量，也可以安裝 Dr. Eggbot 或直接跟自己的 Bot 說，讓它幫你降低這個 Bot 的消耗，把不再用的例行任務刪掉。她提到同事 Sam 當天發文講了執行框架（harness）的改進，兩人對了一下時間，貼文是當天大約九小時前發的。他們當場讀出的說法是：

原話：「You should get 7% more usage out of your plan and up to 15% more on routine runs.」

中文翻譯，方案用量大約能多出 7%，例行任務執行最多能多出 15%。

這兩個數字出自那則貼文，未經獨立證實。

Matt 接著說，他看到用量不夠的人，常常是開了六個 Bot、跑著 15 到 20 條例行任務。條數是一方面，單條例行任務有多重也要算。一天只跑一次、但要做很多事的例行任務，可能相當於和 Bot 連聊 15 到 30 分鐘。上傳很大的文件，比如很大的 CSV，也會進脈絡（context）、耗用量。

三、Bot 怎麼組織：範本、數量、主要 Bot 和團隊

4. 問：能不能把 Bot 分享到別的帳號，讓朋友試用？（7:06）

答：Matt 說可以做成範本（template）。在右側設定裡點分享圖示，把 Bot 變成範本，產生的是一份不含私人資訊的公開副本，把連結發給朋友，對方一鍵就能安裝。Lauren 說範本是她最喜歡的功能之一，她自己的 Dr. Eggbot 和 Tinkabot 都發成了範本。

5. 問：你們各有幾個 Bot？（11:24）

答：Lauren 說她大概有 12 個，但她覺得不需要那麼多，一個主要 Bot 就能做很多事。

6. 問：Lauren 才 12 個，我都 16 個了，你們不應該有幾十上百個嗎？（23:10，觀眾 Stormy）

答：Matt 說他走過一段彎路，Grok Bot 剛出來時建了太多 Bot，多到管不過來。現在他把 Bot 當工具，反覆要解決的問題才留一個專門的 Bot，一次性的事用完就算，比如在 Swappa 上賣一台 Apple 裝置。他經常寫文案，所以長期留著一個寫作 Bot。

Lauren 說她也想過建一支 50 個 Bot 的團隊把自己平行化，後來發現管理成本太高，合併了不少。她把 Bot 當隊友，給它們取人名。她留著的有管 X 帳號和 mentions 的 Bot、做工程的 Bot，還有私人助理 Bot。寫程式的活她多交給 Cursor 的專案（project）或 Cursor Cloud Agents，那些更像一次性的幫手，不值得長期占著側邊欄。

7. 問：要不要設一個幕僚長（chief of staff）？（25:46）

答：Matt 說這正是主要 Bot（primary bot）的用途。現在可以在 Grok Bot 裡指定一個主要 Bot，旁邊會有一顆小星。你可以叫它 Grok Bot，也可以叫它幕僚長（chief of staff），按幕僚長的思路來用。

8. 問：有沒有適合全家一起用的設定？（13:16）

答：Lauren 說這個需求他們常聽到，內部討論過可能的樣子，但她不知道有沒有具體方案。Matt 說他聽得最多的是想和配偶共用一個 Bot，或者家裡有孩子。

他順帶講了剛宣布的 Tailscale 整合，可以把 MCP 伺服器跑在自己的 tailnet 上，比如家裡的 Mac mini，再直接接到 Bot。他轉述了兩位使用者的用法。一位每天下班路上，用家裡 tailnet 上的 Plex 媒體伺服器給孩子排睡前歌單；另一位想和兒子玩 PS5 時網路不好，讓 Bot 做了網路診斷，幫他緩解了 Wi-Fi 壅塞。這是家庭網路的例子，不是家庭帳號功能。

9. 問：有人在做 Slack 整合嗎？（11:00）

答：Lauren 說他們在做，這也是她最喜歡的功能之一。現在已經可以把 Bot 加進 Slack，你和同事都能在裡面跟 Bot 說話。

10. 問：我在公司裡推行 Grok Bot，怎麼讓不同同事的 Bot 互相配合？（19:04）

答：Matt 說他們內部就這麼用。可以把 Bot 當成內部工具。某個工作流程成熟了，如果是 Teams 或 Enterprise 帳號，就能做成團隊 Bot（team bot）分享給團隊，在 Grok Bot、Slack 或 Microsoft Teams 裡用。你可以把幾個團隊 Bot 加到自己帳號裡讓它們配合，也可以在 Slack 裡同時 @ 幾個 Bot，比如先讓文案審閱 Bot 看行銷文案，再交給發布 Bot。

Lauren 說，在 Slack 裡 Bot 更像隊友。有人想到一個功能或發現一個 bug，就開個 Slack 討論串，@ 自己的 Bot 去修或去做，大家在同一個討論串裡一起推進。

四、Cursor Cloud Agents、寫程式和工具串接

11. 問：Cursor Cloud Agents 和 Grok Bot 有什麼差別？（26:36）

答：Lauren 說，Cursor Cloud Agents 也有自己的電腦，不用你的機器。她把它們看成 Bot 的小幫手，做完一件事就走。直接讓 Bot 寫程式，它會被這一件事占住；讓它拉起 Cloud Agents 去改程式碼，Bot 就能同時做別的事。

Matt 說這是 Grok Bot 最強、但知道的人還不夠多的用法。Cursor 的 AI 代理（agent）是專門寫程式的執行框架（harness），而寫程式的執行框架（harness）其實很適合做複雜工作。所以可以讓 Grok Bot 當協調者（orchestrator），去雲端拉起這些 AI 代理。好處有兩個。一是脈絡分開，寫程式的 AI 代理裡可以放很多技能（skill）、連接器和工作流程，Grok Bot 不用都裝進自己的脈絡；二是能做更複雜的任務，混用不同模型，或者用 Cursor routing。

12. 問：Matt 能用 Grok Bot 剪影片嗎？（28:30）

答：Matt 說當然能，影片處理一複雜，就很需要寫程式的 AI 代理這套執行框架（harness）。他自己的剪輯流程常常是 Grok Bot 呼叫 Cursor Cloud Agents，再加上一些自己後端的客製步驟。他還說雲端專案（cloud project）幾乎像一個脈絡視窗近乎無限的共用對話，Grok Bot 可以和這份越積越多的專案脈絡對話。

13. 問：專案（project）和 Bot 有什麼差別？（29:16）

答：Lauren 說團隊也在想怎麼把這個講清楚。她的類比是，Bot 像一個虛擬的人、一個隊友，而一個隊友會同時做好幾個專案，比如一個專案搭直播設備，一個專案改文件。

14. 問：有了 Grok Bot 以後，最好的寫程式工作流程是什麼？（30:22）

答：Matt 說，他在 X 上看到不少品味很高、他很尊重的軟體工程師在用 Grok Bot，而且是把它當協調者（orchestrator），去調度 Cursor Cloud Agents 或者自己的 AI 代理，他猜有的人還接到 tailnet、用 SSH 在開發機上拉起任務。

Lauren 說，對她來說 Grok Bot 的價值在連接器。她在演講和貼文裡常說 Grok Bot 是外迴圈（outer loop），負責把工作需要的脈絡拿回來。比如讓它去開會、做紀錄，會上如果有她的待辦，就拉起一個專案去做，回來用影片給她看做了什麼；或者去 X 上找關於 Grok Bot 的回饋，再去處理。

Matt 說真正打動他的往往是簡單的事，他不用再自己搜 Gmail，十年前的一則貼文也可以讓 Grok Bot 去找。另一個被低估的用法是當膠水（glue）。發布日期改了，就讓 Grok Bot 私訊相關的人、改 Notion 裡的草稿並和程式碼保持一致、拉起一個 Cursor Cloud Agent 去改程式碼，再每小時看一眼那個 Slack 頻道。

15. 問：某某服務沒有現成整合怎麼辦？（26:06）

答：Matt 說，只要對方有 MCP 伺服器或 API，就能做成 Bot 的自訂工具或外掛，Lauren 的範本 Tinkabot 就是幹這個的。聊天區有人提到和 DoorDash 合作，他說已經有一個早期體驗版的 DoorDash MCP，可以接進 Grok Bot 直接用。

16. 問：能不能支援伺服器端推論掛鉤（hook），用上本機端推論？（20:57）

答：Matt 把它連到 Tailscale 外掛。如果家裡有台 Mac mini 跑本機端推論，再把它暴露成 MCP 伺服器，理論上 Grok Bot 就能呼叫。他說現在有一些變通辦法能勉強做到，這類問題他們收到很多。他沒有宣布正式支援。

17. 問：能不能配合本機端的程式開發模型用？（1:04:48）

答：Lauren 說完全可以。Bot 有自己的電腦，可以在裡面安裝東西；很多人不知道，Bot 也能在你自己的電腦上執行指令，你電腦有顯示卡就能跑本機端模型。再配上 Tailscale，多台裝置都能接起來讓 Grok Bot 控制。Matt 舉了自己的例子，錄 What's New in Grok Bot 影片前，他讓 Bot 檢查內容，再透過區域網路把一頁大綱從印表機列印出來。

18. 問：能和 T3 Code 一起用嗎？（1:05:57）

答：Matt 說當然能，還向 Theo 和 T3 團隊打了招呼。

19. 問：雲端服務的 API 文件寫得不清楚，能不能讓 Bot 反推它怎麼拉資料？（1:03:08）

答：Lauren 說她不確定該不該在節目裡談「逆向」這部分。她能說的是 Bot 寫程式很強，能自己摸清不少事。她做燈光自動化時沒給任何說明書，Bot 在 Wi-Fi 裡找到連網裝置，發現那盞燈有一個對區域網路開放的 API，就直接呼叫了，這算不上逆向。Matt 說關鍵是工程思路，人會怎麼查，就讓 Bot 怎麼查，找文件、找開源套件、試探介面、寫腳本，幫你做出原本沒有的連接器。

五、長期使用：脈絡漂移、反模式和聊天機器人用法

20. 問：長期對話的脈絡漂移怎麼辦？（21:20）

答：Lauren 說團隊很清楚這個問題，正在做幾個方案。她給的現成辦法是，對希望 Bot 長期穩定執行的例行任務或任務，讓 Bot 給自己寫一個技能（skill），存到別處，比如他們的 Origin 或 GitHub，這樣技能有版本管理。對話再長，Bot 都照同一份技能做事，因為這部分行為已經搬出了脈絡視窗。

她還說他們在改進記憶（memory），目標是 Bot 記住你說過的事實以後就不再忘，並且真的用上，比如你說過自己常點 flat white。這是在做的方向，不是已經完成的效果。

21. 問：你們常看到哪些該避免的用法？（34:39）

答：Lauren 說是不夠大膽。不太習慣用 AI 代理的人，可能只把 Grok Bot 當聊天機器人問問題，但它有自己的電腦，能主動做事，會用工具、瀏覽器和你用的應用程式。她建議先問自己，哪些事其實可以交給 Bot。小到點午餐、提醒吃飯、食材快用完時下單，願意的話還能把智慧冰箱接上去自動補貨。

Matt 說另一個反模式（anti-pattern）是讓例行任務每五分鐘跑一次，真這麼跑就該想想自己在跑什麼。他還說自己不喜歡把對外溝通交給 AI：

原話：「I think an anti-pattern is just like slop in slop out.」

中文翻譯，一個反模式就是垃圾進、垃圾出。

Lauren 說她也不喜歡用 Bot 寫作，因為寫作就是思考。用語音模式時她容易變成意識流，打字反而逼著自己想清楚要說什麼。她會讓 Bot 幫她找資料，但字自己寫。Matt 補了一句，哪怕在 Slack 裡給同事寫句謝謝，也值得花十分鐘寫點自己的話。

22. 問：把 AI 代理當聊天機器人用，是不是浪費了大部分能力？（39:38）

答：Matt 說 Grok Bot 不是聊天機器人。聊天機器人是大模型的第一代形態，主要是文字；Grok Bot 更像 AI 隊友，要接上各種服務、設例行任務、接 Slack、進會議，替你做原本要自己做的事。

原話：「You should evaluate a tool like Grok Bot like a personal assistant.」

中文翻譯，評估 Grok Bot 這樣的工具，要按私人助理的標準來。

Lauren 提到 Grok Bot Galaxy，她、Matt 和 Roshan 在直播裡用三天試著做一家公司。她期待看到有人用 Grok Bot 跑一整家小公司，她覺得已經有人這麼做了，比如讓它處理客戶諮詢、會計和行銷。Matt 說他以前要手動給支出打標籤，後來接了 QuickBooks、做了試算表，現在 Bot 會去郵件裡整理收據、放進試算表、算總數。很多他以前要自己寫小軟體的事，現在直接做成 Bot。

23. 問：不在網路上做生意的人，比如開咖啡店的，怎麼用 Grok Bot？（42:19，觀眾 Brian）

答：Matt 講了舊金山 Potrero Hill 的 Icon Coffee。店主 Marcel 是 Grok Bot 重度使用者，產品上線才兩週，Matt 去買咖啡時就看到他螢幕上開著 Grok Bot。Marcel 的收銀系統有 API，他會問上一季什麼好賣、什麼不好賣、菜單上該撤掉什麼，資料分析交給 Grok Bot。那時還沒有 Pages 頁面，現在 Grok Bot 可以直接把資料做成互動式圖表。Marcel 還用它處理部分工時表，幫員工排到想要的班。Matt 記得這家店也用 Slack，他覺得可以再做請假、換班的團隊 Bot，但這是他的設想。

Lauren 看了一下連接器清單，說現在有 Xero 和 QuickBooks。Matt 另外講了自己的做法，他讓 Grok Bot 去建立一個 QuickBooks（Intuit）應用程式並拿到 token，像在 Google Cloud Console 裡建 OAuth 應用程式那樣，做到了官方整合範圍以外的事。他自己也說 QuickBooks 團隊未必高興。

24. 問：你們見過最酷的公司用例是什麼？（1:10:35，觀眾 Mr. Gomez）

答：他們先請對方說清楚是指公司內部的用例，還是用 Grok Bot 來建公司。他舉了直播裡看到的高中橄欖球教練，用它在 X 上找球員、做招募；也說了自己用 Grok Bot 拉起 Cloud Agent 剪影片。

六、電話、訊息、安全和檔案

25. 問：應用程式裡有沒有簡單的辦法，給 Bot 配信箱和電話？（8:51）

答：Lauren 說兩樣都有。你向 Bot 要信箱地址，它就會給你一個，地址在 mail.grokbot.com 底下。一兩週前他們上線了電話功能，Bot 可以替你打電話，比如開會時讓它幫你改牙醫預約。Matt 補充，Bot 打的電話可以轉到你自己的手機號碼，所以可以讓它先打給監理所或保險公司排隊，它也能應付語音選單。你還能看即時逐字稿，一邊幹活一邊跟，需要時自己接過來。

26. 問：除了郵件和電話，能發簡訊嗎？（18:25）

答：Matt 說昨天或前天他們剛上線了 Apple Messages（iMessage）支援，可以把 Grok Bot 接到 Messages 上替你發訊息，也能讀一部分簡訊。

27. 問：電話和訊息是不是只支援 Apple 裝置？（56:01）

答：Matt 說不對，他們支援多平台，他認為打電話在任何裝置上都可以。訊息整合兩人的判斷是暫時只支援 Apple，同時說他們在做訊息整合，沒有給出 Android 訊息支援的上線時間。他說 Android 上已經支援不少功能，比如可以把 Grok Bot 設成 Android 的預設語音 AI 代理。

28. 問：國際電話什麼時候有？（58:19）

答：Matt 說這個回饋他聽過很多，是個很複雜的問題，他們在處理。美國有些州的電話功能也還沒開通，國際電話「最終會有」，沒有給時間。後來又有觀眾問到電話涵蓋範圍，他解釋有些州有限制通話錄音的法律。

29. 問：用 Grok Bot 代發 X 私訊或貼文，會被封號嗎？（53:20，觀眾 Tristan）

以下為譯者整理，非原文內容。

這篇在說什麼

Mai Yang（@MaiYangAI）把一場 Grok Bot 的 Q&A 直播整理成文。直播由 Grok Bot 團隊的 Matt Palmer（@mattyp）和 Lauren Tan（@poteto）主講，時間是美國西部時間 2026 年 11 月 13 日週五晚上，兩人共回答了近 50 個問題。

文章依主題分成十個部分：會議功能、用量與例行任務、Bot 怎麼組織、Cursor Cloud Agents、長期使用、電話與安全、路線圖問題、入門、觀眾自報的用法，以及閒聊。每題都標了在回放裡的時間點，可以對照 B 站完整版。

為什麼值得學

這場問答集中了新手最常卡住的幾件事：用量為什麼不夠、Bot 是不是越多越好、哪些事可以交給它、某個功能到底有沒有。原文還把「已經上線」「正在看」「沒有說在做」分開寫，幾個數字也註明未經獨立證實，讀的時候不必自己猜哪些是承諾。

你不需要會寫程式。大部分問答談的是日常用法：開會、省用量、分享 Bot、處理敏感資訊。

你可以帶走的重點

1. 把 Grok Bot 當私人助理，不是聊天機器人

Matt 說，聊天機器人是大模型的第一代形態，主要是文字；Grok Bot 更像 AI 隊友，要接上各種服務、設例行任務、接 Slack、進會議，替你做原本要自己做的事。他說評估這類工具，要按私人助理的標準來。

Lauren 常看到的問題是「不夠大膽」：不太習慣用 AI 代理的人，只拿它問問題，卻沒想到它有自己的電腦，能主動做事。她建議先問自己，哪些事其實可以交給 Bot。

例子：Lauren 提到點午餐、提醒吃飯、食材快用完時下單；Matt 說他讓 Bot 去郵件裡整理收據、放進試算表、算總數。

2. 用量不夠，先查是誰在花，再合併、刪除或降頻

查法是點大頭貼進設定，打開 usage and billing，在 Grok Bot usage 那一欄按 Bot 篩選。Matt 看到用量不夠的人，常是開了六個 Bot、跑著 15 到 20 條例行任務。不只條數，單條有多重也要算：一天只跑一次、但要做很多事的例行任務，可能相當於和 Bot 連聊 15 到 30 分鐘。上傳很大的文件（例如大型 CSV）也會進脈絡、耗用量。

Lauren 說 Webhook 被低估了。例行任務是按時間醒來，Webhook 則是外部服務有動作時才觸發 Bot，例如 Linear 自帶的 Webhook 整合。入口不太好找，她建議直接請 Bot 幫你看哪些例行任務可以改成 Webhook。

留意：直播中讀出的「方案用量多 7%、例行任務執行最多多 15%」，出自 Sam 的貼文，原文註明未經獨立證實。團隊正在看的 MCP events 規範，也只是「正在看」，沒有說已經上線。

3. Bot 不必多：先用好一個主要 Bot，需要時再拆

Lauren 大約有 12 個 Bot，但她覺得不需要那麼多，一個主要 Bot 就能做很多事；她也想過建 50 個 Bot 的團隊，後來發現管理成本太高，合併了不少。Matt 走過一段彎路，現在把 Bot 當工具：反覆要解決的問題才留一個專門的 Bot，一次性的事用完就算。

在 Grok Bot 裡可以指定一個主要 Bot，旁邊會有一顆小星，也可以按幕僚長（chief of staff）的思路來用。想把 Bot 分享給朋友，可以做成範本，對方一鍵安裝；在公司裡，Teams 或 Enterprise 帳號可以把成熟的工作流程做成團隊 Bot，在 Grok Bot、Slack 或 Microsoft Teams 裡用。

4. 寫程式的重活，交給 Cursor Cloud Agents

Lauren 說，Cursor Cloud Agents 也有自己的電腦，不用你的機器，她把它們看成 Bot 的小幫手，做完一件事就走。直接讓 Bot 寫程式，它會被這一件事占住；讓它拉起 Cloud Agents 去改程式碼，Bot 就能同時做別的事。

Matt 說這是 Grok Bot 最強、但知道的人還不夠多的用法：讓 Grok Bot 當協調者（orchestrator），去雲端拉起這些 AI 代理。好處有兩個，一是脈絡分開，二是能做更複雜的任務、混用不同模型，或用 Cursor routing。

例子：發布日期改了，就讓 Grok Bot 私訊相關的人、改 Notion 裡的草稿並和程式碼保持一致、拉起一個 Cursor Cloud Agent 去改程式碼，再每小時看一眼那個 Slack 頻道。

5. 想長期穩定：把做法寫成技能，重要檔案另外備份

對話越長，Bot 越容易偏離原本的做法（脈絡漂移）。Lauren 說團隊正在做幾個方案，她給的現成辦法是：對希望長期穩定執行的例行任務或任務，讓 Bot 給自己寫一個技能，存到別處，例如 Origin 或 GitHub，技能就有版本管理，Bot 都照同一份做事。她也說他們在改進記憶，那是「在做的方向，不是已經完成的效果」。

檔案也要留意。Lauren 說目前電腦自動更新時，不是所有檔案都能保住：用完就丟的東西可以留在 Bot 的電腦上，想留住的要另外備份到 GitHub、Google Drive 或 Dropbox，偏技術的人可以用 Cloudflare R2 這類物件儲存。

6. 敏感資訊走保險庫，別貼進聊天

Matt 說，Grok Bot 提供了安全的輸入方式，例如輸入密碼時 Grok Bot 看不到密碼。他的判斷標準是：你願意放進密碼管理器的東西，就可以交給 Grok Bot 的保險庫；連密碼管理器都不想放的，例如社會安全號碼，就再想想。他還說，聊天裡的資訊會以明文存在某處，隨後改口說聊天也不是毫無保護，只是保險庫更安全。密碼也不該打進終端機。

另一個常見擔心：用 Grok Bot 代發 X 私訊或貼文會不會被封號？Matt 說用 Grok Bot 裡的整合不會，它發私訊或訊息前一定會先徵得你同意，符合服務條款；自己寫腳本或做可疑的事，就會被封。

7. 沒有現成整合時，還有幾條路

Matt 說，只要對方有 MCP 伺服器或 API，就能做成 Bot 的自訂工具或外掛；Lauren 的範本 Tinkabot 就是做這件事的。他也提到已有一個早期體驗版的 DoorDash MCP 可以接進 Grok Bot。

如果雲端服務的 API 文件寫得不清楚，Matt 的思路是：人會怎麼查，就讓 Bot 怎麼查，找文件、找開源套件、試探介面、寫腳本。Lauren 的例子是做燈光自動化時沒給任何說明書，Bot 在 Wi-Fi 裡找到連網裝置，發現那盞燈有一個對區域網路開放的 API，就直接呼叫了。

服務如果跑在家裡的機器上（例如 Mac mini），可以用剛宣布的 Tailscale 整合，把 MCP 伺服器放在自己的 tailnet 上再接到 Bot。Matt 轉述過有人用家裡的 Plex 媒體伺服器給孩子排睡前歌單。至於把本機端推論接進來，Matt 說有些變通辦法能勉強做到，但沒有宣布正式支援。

8. 分清楚哪些功能「已經有」，哪些只是「覺得不錯」

路線圖類的問題很多，但回答的肯定程度差很多。原文逐題標明：已經上線的有會議、Slack、電話、Apple Messages 和 Bot library；說「在做」或「在看」的有 MCP events、Web MCP、訊息整合；國際電話「最終會有」、週邊商品有團隊在做，但都沒有時間；Apple Health 是 Lauren 覺得有人在做、要再確認。

CarPlay、iOS 小工具和 Apple Watch、SDK、LinkedIn，現場都沒有說在做；洗碗和 GTA 6 整合則是玩笑或設想，不是產品計畫。讀到這類問答，先看回答用的是哪一種說法，再決定要不要期待。

用 Agent Skills 為 AI 代理配備面對真實世界的能力

原文標題：Equipping agents for the real world with Agent Skills

作者：Barry Zhang、Keith Lazuka、Mahesh Murag（Anthropic）

原文：https://www.anthropic.com/research/equipping-agents-for-the-real-world-with-agent-skills

日期：2025-10-16

備註：繁體中文翻譯，僅供個人閱讀。

原文頁面標註的更新（Update，2025-12-18）：我們已將 Agent Skills 發布為開放標準（open standard），以便跨平台移植。（原文連結）

隨著模型（model）能力提升，我們現在可以打造能與完整運算環境互動的通用 AI 代理。以 Claude Code 為例，它可以靠本機的程式碼執行（code execution）和檔案系統（filesystem），完成橫跨各領域的複雜任務。但隨著這些 AI 代理愈來愈強大，我們需要更可組合（composable）、可擴充（scalable）、可攜（portable）的方式，為它們配備特定領域的專業知識。

這促使我們創造了 Agent Skills：由指示（instructions）、腳本（scripts）和資源（resources）組成、經過整理的資料夾，AI 代理可以自行探索並動態載入，讓自己在特定任務上表現更好。Skills（技能）把你的專業知識打包成 Claude 可用的可組合（composable）資源，藉此擴充 Claude 的能力，把通用 AI 代理變成符合你需求的專業 AI 代理。

為 AI 代理打造一個 skill，就像為新進員工準備一份入職培訓（onboarding）指南。你不必為每個使用情境各自打造零散、客製的 AI 代理；現在任何人都能靠整理並分享自己的程序性知識（procedural knowledge），用可組合（composable）的能力讓 AI 代理專精於特定工作。這篇文章會說明 Skills 是什麼、示範它如何運作，並分享打造自己 Skills 的最佳實踐（best practices）。

技能的構造The anatomy of a skill

為了看看 Skills 實際怎麼運作，我們來走一個真實的例子：Claude 最近推出的文件編輯功能，背後就由幾個 skill 驅動，這是其中之一。Claude 本來就很懂得理解 PDF，但直接操作 PDF（例如填寫表單）的能力有限。這個 PDF skill 讓我們能賦予 Claude 這些新能力。

最簡單來說，skill 就是一個包含 SKILL.md 檔的目錄（directory）。這個檔案必須以 YAML frontmatter（YAML 前置資料）開頭，其中包含幾項必要的中繼資料（metadata）：name 和 description。AI 代理在啟動時，會把每個已安裝 skill 的 name 和 description 預先載入（pre-load）到系統提示詞（system prompt）裡。

這些中繼資料（metadata）是漸進揭露（progressive disclosure）的第一層（first level）：它只提供剛好足夠的資訊，讓 Claude 知道每個 skill 該在什麼時候使用，而不必把全部內容載入脈絡（context）。這個檔案的正文則是第二層（second level）細節。如果 Claude 認為這個 skill 與目前的任務相關，就會把完整的 SKILL.md 讀進脈絡（context），藉此載入該 skill。

隨著 skill 愈來愈複雜，它們可能包含太多脈絡（context），一個 SKILL.md 放不下，或是只在特定情境下才用得到的脈絡（context）。這時，skill 可以在 skill 目錄裡打包額外的檔案，並在 SKILL.md 中以檔名引用。這些額外連結的檔案是第三層（third level）（以及更深層）的細節，Claude 可以自行選擇只在需要時才去瀏覽與探索。

在下面這個 PDF skill 中，SKILL.md 引用了兩個額外檔案（reference.md 和 forms.md），這是 skill 作者選擇與核心 SKILL.md 一起打包的。skill 作者把填寫表單的指示移到獨立的檔案（forms.md），就能讓 skill 的核心保持精簡，並相信 Claude 只會在填寫表單時才讀 forms.md。

漸進揭露（progressive disclosure）是讓 Agent Skills 兼具彈性與可擴充性（scalable）的核心設計原則。就像一本編排良好的手冊，先有目錄，接著是各個章節，最後是詳細的附錄，skill 讓 Claude 只在需要時才載入資訊：

具備檔案系統（filesystem）和程式碼執行（code execution）工具的 AI 代理，在處理特定任務時，不需要把整個 skill 都讀進脈絡視窗（context window）。這表示能打包進一個 skill 的脈絡（context）量，實際上是沒有上限的。

Skills 與程式碼執行（code execution）Skills and code execution

Skills 也可以包含程式碼，讓 Claude 自行斟酌，當作工具來執行。

大型語言模型（large language models）擅長許多任務，但有些操作更適合用傳統的程式碼執行（code execution）來做。例如，靠令牌（token）生成來排序一份清單，成本遠高於直接跑一個排序演算法。除了效率考量，許多應用還需要只有程式碼才能提供的確定性（deterministic）可靠度。

在我們的例子中，PDF skill 包含一支預先寫好的 Python 腳本，能讀取 PDF 並擷取所有表單欄位。Claude 可以執行這支腳本，而不必把腳本或 PDF 載入脈絡（context）。而且因為程式碼是確定性的（deterministic），這個工作流程（workflow）既一致又可重複。

開發與評估 SkillsDeveloping and evaluating skills

以下是開始撰寫與測試 skill 時幾項實用的指引：

  • 從評估開始（Start with evaluation）：請你的 AI 代理執行有代表性的任務，觀察它們卡在哪裡、或在哪裡需要額外的脈絡（context），藉此找出能力上的具體缺口。接著再逐步建立 skill 來補足這些缺點。
  • 為規模化設計結構（Structure for scale）：當 SKILL.md 檔變得難以駕馭時，把內容拆成獨立的檔案並加以引用。如果某些脈絡（context）彼此互斥、或很少一起使用，把路徑分開就能減少令牌（token）用量。最後，程式碼既可以是可執行的工具，也可以當作文件。必須讓人清楚知道，Claude 應該直接執行腳本，還是把腳本讀進脈絡（context）當作參考。
  • 從 Claude 的角度思考（Think from Claude's perspective）：觀察 Claude 在真實情境中如何使用你的 skill，並依據觀察結果迭代：留意意料之外的執行軌跡（trajectories），或對某些脈絡（context）過度依賴。要特別注意 skill 的 name 和 description，因為 Claude 會依據它們，來決定是否要針對目前的任務觸發這個 skill。
  • 與 Claude 一起迭代（Iterate with Claude）：在你和 Claude 一起處理任務的過程中，請 Claude 把它成功的做法和常犯的錯誤，整理成可重複使用的脈絡（context）與程式碼，放進 skill 裡。如果它在用 skill 完成任務時偏離了方向，請它自我反省哪裡出了問題。這個過程能幫你找出 Claude 實際需要什麼脈絡（context），而不是一開始就試圖預先猜想。

使用 Skills 的安全考量Security considerations when using Skills

Skills 透過指示與程式碼，為 Claude 提供新能力。這讓它們很強大，但也意味著惡意的 skill 可能在使用它的環境中引入漏洞，或指示 Claude 外洩（exfiltrate）資料並採取非預期的行動。

我們建議只從可信任的來源安裝 skill。若要安裝來自較不可信來源的 skill，使用前請徹底稽核（audit）。先閱讀 skill 中所打包檔案的內容，了解它做了什麼，並特別留意程式碼的相依套件（dependencies）以及打包的資源，例如圖片或腳本。同樣地，也要留意 skill 內部是否有指示或程式碼，叫 Claude 連線到可能不可信的外部網路來源。

Skills 的未來The future of Skills

Agent Skills 目前已支援在 Claude.ai、Claude Code、Claude Agent SDK 和 Claude Developer Platform 上使用。

在接下來的幾週，我們會持續新增功能，支援建立、編輯、探索、分享與使用 Skills 的完整生命週期。我們特別期待 Skills 能幫助組織與個人，把他們的脈絡（context）和工作流程（workflows）分享給 Claude。我們也會探索 Skills 如何補強模型上下文協定（Model Context Protocol，MCP）伺服器：教 AI 代理處理涉及外部工具與軟體的更複雜工作流程（workflows）。

放眼更遠的未來，我們希望讓 AI 代理能自行建立、編輯和評估 Skills，讓它們把自己的行為模式固化成可重複使用的能力。

Skills 是個簡單的概念，格式也相應地簡單。這種簡單，讓組織、開發者與終端使用者更容易打造客製的 AI 代理，並賦予它們新能力。

我們很期待看到大家用 Skills 打造出什麼。今天就從查看我們的 Skills 文件（docs）和範例集（cookbook）開始吧。

這篇在說什麼

Anthropic 介紹 Agent Skills：把某項工作的做法寫成一個資料夾，裡面放說明檔、腳本和參考資料，AI 代理（以 Claude 為例）需要時才自己翻出來用，就像給新進員工一份入職培訓（onboarding）指南。

文章依序講了：skill 的構造、它如何與脈絡視窗（context window）和程式碼執行（code execution）搭配、開發與評估的建議、安全提醒，以及未來的方向。

為什麼值得學

即使你不寫程式，也能學到「把專業做法整理成可重複使用的說明書，讓 AI 代理按需取用」這種思路。讀的時候留意兩點：這是一篇產品介紹，原文沒有附效果數據；而且作者自己提醒，惡意的 skill 可能讓 Claude 外洩（exfiltrate）資料，所以只該安裝可信任來源的 skill。

你可以帶走的重點

1. skill 就是一個資料夾

最簡單的 skill 只有一個 SKILL.md 檔，開頭必須有 name 和 description。內容變多時，可以把額外的說明檔和腳本放進同一個資料夾，再由 SKILL.md 用檔名引用。原文的例子是 PDF skill：填表單的指示放在 forms.md，所以核心檔案能保持精簡。

2. 漸進揭露（progressive disclosure）：需要才讀，不一次塞滿

AI 代理一開始只讀每個 skill 的名稱與描述，約 100 個令牌（token），剛好夠判斷什麼時候該用。真的要用時，才讀 SKILL.md 正文；正文再引用的額外檔案，Claude 需要時才去讀。原文說，因此能打包進一個 skill 的脈絡（context）量，實際上沒有上限。

3. 適合用程式碼做的事，交給腳本

原文指出，有些操作用程式碼比讓模型自己做更合適：排序一份清單，靠令牌（token）生成比跑排序演算法貴得多；而且許多應用需要只有程式碼才能提供的確定性（deterministic）可靠度。PDF skill 附了一支腳本來擷取表單欄位，Claude 執行它時，不必把腳本或 PDF 載入脈絡（context）。

4. 從評估開始，和 Claude 一起迭代，並注意安全

原文的四項開發建議：先用代表性任務找出 AI 代理的缺口，再逐步建立 skill；內容太雜就拆檔，互斥或少用的脈絡（context）分開放，能省令牌（token）；觀察 Claude 實際怎麼用你的 skill，特別留意 name 和 description；請 Claude 把成功做法和常犯錯誤整理進 skill。安裝來源不夠可信的 skill 前，要先讀過裡面的檔案，特別留意相依套件和會連到外部網路的指示。

怎麼開始

  1. 挑一件你常請 AI 代理做、卻常常做不好的事，先觀察它卡在哪裡，或缺了哪些背景資訊。
  2. 把缺的做法寫進一個資料夾裡的 SKILL.md，檔案開頭寫好 name 和 description；內容太長就拆成別的檔案，在 SKILL.md 裡用檔名引用。
  3. 用幾次真實任務試用，留意 Claude 有沒有在對的時候觸發這個 skill、有沒有走偏。
  4. 走偏時，請 Claude 自我反省哪裡出了問題，再把答案寫回 skill。
  5. 只安裝你信任來源的 skill；不確定的，先讀過它打包的檔案再用。
  6. 想看更多範例，原文最後附了 Skills 文件（docs）和範例集（cookbook）的連結。

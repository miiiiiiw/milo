HTML 新手從 0 到 1：學懂網頁基礎，再用 AI 代理做出個人首頁

作者：Adrian Punk（@AdrianPunk115）

原文：https://x.com/AdrianPunk115/status/2083832138462605504

日期：2026-08-02（台北時間 16:27；UTC 2026-08-02 08:27）

備註：原文為簡體中文，已轉為台灣用語繁體中文；繁體中文翻譯，僅供個人閱讀。

現在，人人都能用 AI 代理（Agent）做一個自己的網頁。

打開一個 AI 程式設計工具（例如 Codex、Cursor、Claude Code），告訴它「幫我做一個個人首頁」，它就能建立檔案、調整樣式，再把網頁放進瀏覽器。做出第一版已經很容易了。

差距會在第二輪修改時出現。

懂結構的人會說：「檢查 images 資料夾的相對路徑」「把手機版改成單欄」「只調整 CSS，不要動 HTML 內容」。AI 代理馬上知道該去哪裡、改什麼、怎樣驗收。

不懂結構的人只能反覆說：「圖片怎麼沒了？」「再高級一點。」「怎麼和剛才不一樣？」AI 代理繼續猜，修改範圍也越來越大。

HTML、CSS、JavaScript、根目錄、相對路徑、響應式……這些聽起來有點「古法」的術語，今天反而成了 AI 代理建站的實用寶典。你不用靠它們手寫幾百行程式碼，但要用它們描述問題、約束修改範圍、檢查最終結果。

同一個 AI 代理，懂結構的人提示更準、修改更快，出錯時也更容易找到原因。

所以這篇文章分成兩段。前半段從零開始，帶你認識網頁專案，再親手做一個很小的頁面；後半段進入 AI 代理示範，用黃色 Punk 個人首頁走一遍「找參考、分析設計、產生網頁、繼續修改、瀏覽器驗收」的完整流程。

一、先分清網頁、網站和 Web 應用程式

這三個詞經常混在一起，其實很好區分。

可以這樣記：

一句話記住

網頁是一頁紙
網站是一本書
Web 應用程式是一台機器

你今天要做的是一個網頁。以後增加作品詳情、部落格和聯絡頁面，它會慢慢變成一個網站。

二、網頁專案就是一套檔案和資料夾

一個網頁專案不等於一個 HTML 檔案。它通常包含頁面、樣式、互動、圖片和說明文件。

你可以把它想成一套房子：

這些內容需要放在同一個大資料夾裡，這個最外層資料夾叫專案根目錄。

一個常見結構是：

目錄樹

my-first-site/
├── index.html
├── css/
│   └── style.css
├── js/
│   └── script.js
├── images/
│   └── avatar.jpg
└── README.md

這裡的 my-first-site 是整個專案，也是根目錄。css、js、images 是用來分類的小抽屜，實際內容放在檔案裡。

第一個練習：只搭資料夾，不寫程式碼

現在就做一遍：

  1. 在電腦上新增資料夾，命名為 my-first-site；
  2. 進入它，再新增 css、js、images 三個資料夾；
  3. 在根目錄新增 index.html；
  4. 再新增 README.md；
  5. 在 README 裡寫一句：「這是我的第一個網頁專案。」

完成後，對照上面的目錄樹檢查。資料夾層級一樣，就算過關。

先把抽屜分好，後面才知道每樣東西應該放在哪裡。

三、認識網頁裡的常見檔案

檔名最後的小尾巴叫「副檔名」。它告訴電腦這個檔案是什麼類型。

你在螢幕上看到的一個按鈕，通常由三個檔案一起完成：

一個按鈕的分工

HTML：頁面裡有一個按鈕
CSS：按鈕是什麼顏色、大小和形狀
JavaScript：點選按鈕後發生什麼

這就是常說的「骨架、皮膚、大腦」：

  • HTML 管結構和內容；
  • CSS 管樣式和外觀；
  • JavaScript 管行為和互動。

三個檔案分開以後，專案更容易修改。想改文案就找 HTML，想換顏色就找 CSS，按鈕沒反應再檢查 JavaScript。

四、index.html 為什麼最重要

在大多數簡單網頁專案裡，index.html 同時承擔首頁和入口檔案兩個角色。

訪客開啟網站網址時，伺服器通常會先在根目錄尋找 index.html。檔案不存在、名字寫錯或者被移到其他資料夾，首頁就可能打不開。

所以新手先記住三件事：

  • index.html 放在專案根目錄；
  • 不要隨意重新命名它；
  • 檔名全部使用英文小寫。

HTML 頁面裡面有什麼

一個 HTML 頁面可以分成兩塊：

HTML 頁面的兩大區塊

html
├── head：網頁設定
└── body：使用者看到的內容

head 裡通常放網頁標題、中文編碼、手機顯示設定，以及 CSS 和 JavaScript 的位置。body 裡放標題、段落、圖片、按鈕等可見內容。

頁面內部還會繼續分區：

body 內部分區

body
├── header：頂部和導覽
├── main：頁面主要內容
│   ├── section：自我介紹
│   ├── section：作品展示
│   └── section：聯絡方式
└── footer：頁尾

這些標籤能幫助瀏覽器、搜尋引擎和螢幕閱讀器理解頁面。2

譯註：原文此處的「2」是附註，連到 MDN 的〈Structuring documents〉說明頁。

你暫時只需要認識幾個常用標籤：

五、親手做出第一個能開啟的頁面

理論講完一半，現在讓瀏覽器出現第一行屬於你的文字。

第一步：準備一張圖片

把一張自己的照片或頭像放進 images 資料夾，命名為 avatar.jpg。

如果你的圖片是 PNG，就命名為 avatar.png，後面的 HTML 也要寫相同的副檔名。檔名和程式碼裡的路徑必須完全一致。

第二步：寫入最小 HTML

用你選好的編輯器開啟 index.html，複製下面這小段：

HTML：index.html

<!DOCTYPE html>
<html lang="zh-Hant-TW">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>我的第一個網頁</title>
</head>
<body>
  <h1>你好，這是我的第一個網頁。</h1>
  <p>我正在學習網頁是怎樣組成的。</p>
  <img src="images/avatar.jpg" alt="我的個人頭像">
  <button id="hello-button" type="button">和我打個招呼</button>
</body>
</html>

譯註：原文範例寫的是 lang="zh-CN"（簡體中文）；這裡的範例文字已改為繁體中文，所以一併改成 lang="zh-Hant-TW"。

這段不用背。你只要能看出這些事：

  • title 是瀏覽器分頁上的名字；
  • h1 是頁面裡的大標題；
  • p 是介紹文字；
  • img 從 images 資料夾讀取頭像（這裡的 images/avatar.jpg 就是「檔案路徑」，告訴瀏覽器頭像放在哪裡，第八章會詳細解釋）；
  • button 在頁面裡放了一個按鈕。

第三步：儲存，再用瀏覽器開啟

Mac 按 Command + S，Windows 按 Ctrl + S 儲存。然後雙擊 index.html，用 Chrome、Edge、Firefox 或 Safari 開啟。

你應該能看到標題、介紹、圖片和按鈕。頁面會很樸素，圖片也可能很大，這是正常的。HTML 此時只負責把內容放出來。

常見出包現場： 如果瀏覽器顯示一堆程式碼，先檢查檔案副檔名是不是被改成了 index.html.txt（Windows 記事本常常這樣搞）。如果圖片裂開，對照 images 資料夾裡的真實檔名，大小寫和副檔名一個都不能錯。

這一關的驗收標準：瀏覽器能打開頁面，文字和圖片都能出現。

六、用 CSS 給頁面加上外觀

接下來讓頁面有顏色、有間距，圖片也縮小一點。

第一步：連結 CSS 檔案

在 index.html 的 head 裡面加入這一行：

HTML：加在 head 裡

<link rel="stylesheet" href="css/style.css">

這句話的意思是：請去 css 資料夾裡讀取 style.css。

href="css/style.css" 也是一個檔案路徑——下一級 css 資料夾裡的 style.css 檔案。

第二步：給 style.css 寫幾條規則

用編輯器開啟 css/style.css，複製下面這段：

CSS：css/style.css

body {
  margin: 0;
  padding: 48px;
  color: #111111;
  background: #f5f5f5;
  font-family: Arial, "PingFang SC", sans-serif;
}

img {
  display: block;
  width: 240px;
  margin: 24px 0;
  border-radius: 24px;
}

button {
  padding: 12px 20px;
  border: 0;
  border-radius: 999px;
}

這裡不用逐個記屬性。先觀察它們改了什麼：

  • body 負責整個頁面；
  • background 把背景改成淺灰色；
  • padding 給頁面四周留出空白；
  • width 把頭像限制為 240 像素；
  • border-radius 讓頭像和按鈕出現圓角。

CSS 的寫法可以簡單理解為：

CSS 的寫法

找到誰 → 改什麼 → 改成什麼

儲存 CSS，回到瀏覽器重新整理。Mac 可以按 Command + R，Windows 可以按 Ctrl + R。

這一關的驗收標準：背景變成淺灰色，頭像縮小，按鈕出現圓角。

七、用 JavaScript 讓按鈕有反應

現在按鈕已經出現，但點選它還沒有任何變化。接下來給它加一個最簡單的互動。

第一步：連結 JavaScript 檔案

在 index.html 的 body 結束標籤前（也就是 </body> 的上一行）加入：

HTML：加在 </body> 前

<script src="js/script.js"></script>

注意：為什麼放 body 底部，而不是 head 裡？因為瀏覽器是從上往下讀程式碼的。如果 script 放在 head，它會在按鈕還沒出現時就去找按鈕——然後什麼都找不到。放在 body 底部，確保按鈕已經「出生」在頁面上，JavaScript 再來找它。

第二步：寫入按鈕行為

用編輯器開啟 js/script.js，複製下面這段：

JavaScript：js/script.js

document.querySelector("#hello-button").addEventListener("click", () => {
  alert("你好呀！謝謝你來到我的網頁。");
});

它做的事情很簡單：找到 hello-button，等使用者點選，然後彈出一句話。

儲存檔案、重新整理瀏覽器，再點選按鈕。出現彈出視窗，就說明 HTML 裡的按鈕和 JavaScript 已經連上了。

這一關的驗收標準：點選按鈕後，瀏覽器會出現歡迎語。

八、檔案路徑為什麼經常讓新手出包

頁面想讀取圖片、CSS 和 JavaScript，都要先知道它們在哪裡。這個位置就叫檔案路徑。

到目前為止，你已經用過了三種路徑：

三種相對路徑

css/style.css        下一級 css 資料夾裡的樣式
js/script.js         下一級 js 資料夾裡的腳本
images/avatar.jpg    下一級 images 資料夾裡的頭像

專案內部優先使用這種相對路徑。好處是：整個專案被搬到另一個位置時，這些路徑仍然可以繼續工作。

路徑可以這樣記：

  • 同一層：直接寫檔名；
  • 下一層：資料夾名/檔名；
  • 上一層：../；
  • 檔案、大小寫和副檔名必須一致。

新手階段遵守「三不」會省很多時間：

  • 不隨意刪除檔案；
  • 不隨意移動檔案；
  • 不隨意重新命名檔案。

如果一定要移動或改名，對應的路徑也要一起修改。

九、學會「修改、儲存、重新整理、驗證」

這是網頁學習中最值得養成的習慣。

四步工作法

修改 → 儲存 → 重新整理 → 驗證
  ↑                    ↓
  └──── 不滿意再修改 ────┘

一次只改一個地方。先換標題，儲存並重新整理；確認正確後，再改背景顏色。HTML、CSS 和 JavaScript 同時大改，出錯後很難知道問題來自哪裡。

最常見的出包現場是：「我明明改了，為什麼沒效果？」

先檢查兩件事：檔案有沒有儲存，瀏覽器有沒有重新整理。

這個四步工作法以後同樣適用於 AI 代理。AI 代理改完檔案，你仍然要回到瀏覽器驗證。

十、開啟檔案、執行專案和公開上線

雙擊 index.html 時，瀏覽器網址通常以 file:// 開頭。這個方法適合檢查最小頁面。

當網頁變得更複雜時，理想的方式是啟動一個「本機伺服器」，讓瀏覽器網址變成 http://localhost 開頭的形式——這樣更接近真實的線上環境。

不過你現在不需要手動折騰這個。 好消息：後面用的 AI 代理會自動啟動本機伺服器並開啟預覽，你只需要在瀏覽器裡看。這裡先記住概念就好：

三種開啟方式

雙擊開啟：先看內容
本機執行：完整測試
公開上線：讓別人瀏覽

電腦版正常也不代表手機版正常。縮窄瀏覽器視窗，檢查標題有沒有被裁掉、圖片有沒有超出螢幕、按鈕有沒有擠在一起。響應式設計會讓頁面根據螢幕寬度調整字級、間距和排列方式。

到這裡，你已經從零搭出了第一個網頁專案，也知道每個檔案負責什麼。接下來進入 AI 代理示範。

新手：從手動建置到用 AI 代理建置

你可能在想：前面手寫了這麼多程式碼，後面 AI 代理真的能全自動嗎？

答案是：能。但你不需要理解 AI 代理寫的每一行程式碼。

前面十章只想幫你拿到三樣東西，你不需要因此變成程式設計師：

  • 一套術語——你知道「CSS」「檔案路徑」「根目錄」「響應式」這些詞是什麼意思，所以你能跟 AI 代理說清楚；
  • 一個工作習慣——修改、儲存、重新整理、驗證。AI 代理改完程式碼，你仍然要自己開啟瀏覽器檢查；
  • 一種判斷力——圖片裂了多半是路徑寫錯了，按鈕沒反應多半是 JS 沒連上。你不需要會修，但你能告訴 AI 代理往哪個方向排查。

接下來用的 AI 代理叫 [Codex / 你實際使用的工具名]。它是一個 AI 程式設計工具——你跟它聊天，它幫你寫程式碼、建檔案、啟動預覽。你負責描述想要什麼、檢查做得對不對；它負責實作。

好，現在進入實戰。

十一、最終示範：用 AI 代理做黃色 Punk 個人首頁

前面的小頁面用來學習。現在用 AI 代理做一個可以展示的版本。

這次示範使用 Punk 的個人資訊和像素頭像，目標是完成下面這張個人首頁：

第一步：準備個人內容

在專案的 images 資料夾裡放入像素頭像，命名為 punk.jpg。

再準備這些資訊：

個人資訊

名字：Punk
介紹：我用 AI、設計和內容，把想法做成作品。
身份：中科大 MBA、HerName 首席設計師、Stanley 商學院執行院長
頁面：關於我、作品、聯絡方式
頭像：images/punk.jpg

第二步：找一兩個參考網頁

可以從這些設計網站開始：

網站入口：Recent｜Awwwards｜Siteinspire｜Land-book｜One Page Love

以 Recent 為例，先點進喜歡的作品，再開啟它對應的真實網頁。複製具體頁面網址，並記下自己喜歡的部分。

一次選一兩個就夠了。你可以喜歡 A 頁的配色，也可以喜歡 B 頁「左邊文字、右邊照片」的首屏。

第三步：先只分析參考網頁

第一條提示詞只負責分析。先讓 AI 代理把配色、排版、字型、按鈕和動態效果說清楚，暫時不要建立網頁，也不要修改專案檔案。

下面這段提示詞看起來很長，但你要做的只是把方括號 [ ] 裡的內容替換成你自己的，然後整段複製給 AI 代理。不需要理解每一行，AI 代理會按要求一條一條分析。

在 AI 代理中開啟專案資料夾，把下面方括號裡的內容替換掉，再整段複製。

提示詞：分析參考網頁（可直接複製給 AI 代理）

請閱讀並分析下面的參考網頁：

參考網頁 A：[貼上具體網頁 URL]
我喜歡它的部分：[例如：黃色配色、超大標題、首屏留白]

參考網頁 B：[沒有第二個就刪除這一項]
我喜歡它的部分：[例如：左側文字、右側人物照片、按鈕樣式]

這一步只做設計分析。暫時不要建立網頁、不要寫程式碼，也不要修改當前專案中的任何檔案。

請分別分析每個網頁，並用簡單的中文說明：

1. 頁面結構
- 頂部導覽、首屏、內容區、作品區和頁尾怎樣排列；
- 內容最大寬度、左右對齊方式、網格和留白大概是多少；
- 哪些內容最先吸引注意力，視覺順序是什麼。

2. 配色
- 主色、輔助色、背景色、文字色和按鈕色；
- 給出接近的 HEX 色值；
- 說明每種顏色用在什麼位置、大概佔多少比例；
- 檢查文字和背景是否容易閱讀。

3. 文字和字型
- 標題、正文、導覽、按鈕分別是什麼字型氣質；
- 估算電腦版和手機版的字級、字重、行高和字間距；
- 分析標題怎樣換行，正文一行大約多長；
- 分析文案的層級、長度和語氣，不複製原文。

4. 排版
- 首屏是左右布局、上下布局還是居中布局；
- 文字、圖片、按鈕之間怎樣對齊；
- 區塊之間的上下間距和頁面節奏；
- 圖片是什麼比例，有沒有圓角、邊框、旋轉或陰影。

5. 按鈕和元件
- 按鈕的大小、顏色、圓角、邊框、陰影和文字樣式；
- 滑鼠懸停、按下和點選後分別有什麼變化；
- 導覽、卡片、標籤和聯絡方式分別怎樣設計；
- 哪些元件承擔主要操作，哪些只負責展示資訊。

6. 動態效果
- 頁面開啟、捲動、懸停和點選時分別有什麼動態效果；
- 動態效果從什麼狀態開始，到什麼狀態結束；
- 估算持續時間、延遲和速度變化；
- 哪些動態效果適合保留，哪些可能影響手機效能；
- 如果無法確認動態效果，請明確告訴我需要補充截圖還是螢幕錄影。

7. 手機版
- 頁面在窄螢幕上怎樣重新排列；
- 標題、圖片、按鈕和導覽怎樣縮放；
- 有沒有隱藏內容、摺疊選單或橫向捲動；
- 電腦版和手機版最大的三個區別是什麼。

分析完成後，請輸出一份「設計 DNA」：
- 每個參考網頁最值得借鑑的三條規律；
- 兩個參考之間有沒有衝突；
- 如果需要組合，應該怎樣確定主次；
- 哪些規律適合個人首頁；
- 哪些內容需要改成我的版本；
- 製作時最容易做錯的地方。

最後列出你還需要我補充的資訊。

再次提醒：這一步只分析，不建立檔案，不開始製作網頁。

如果參考網站阻擋存取，把電腦截圖、手機截圖和一段捲動螢幕錄影放進 references 資料夾，再讓 AI 代理從這些材料開始分析。不要讓它根據網站名字猜設計。

拿到分析報告後，先看三件事：它有沒有抓住你喜歡的部分，有沒有把兩個參考的主次說清楚，給出的設計規律能不能落到你的個人首頁上。

方向不對時，先繼續追問。例如：

追問範例

你對配色的分析比較準確，但首屏排版還不夠具體。請補充文字區和圖片區的寬度比例、對齊方式、上下留白和手機版變化。繼續只做分析。

第四步：確認分析後，再發製作指令

分析方向確認以後，在同一個 AI 代理任務中傳送第二條提示詞。這樣它可以直接使用剛才整理的設計 DNA。

如果你換了一個新任務，需要先把上一輪的設計 DNA 一起貼過去。

提示詞：製作指令（可直接複製給 AI 代理）

請基於你剛才完成的參考網頁分析和「設計 DNA」，在當前專案資料夾製作一個屬於我的原創個人首頁。

這一步開始建立和修改網頁檔案，不需要重新分析參考網站。

一、我的個人資訊

- 名字：Punk
- 主標題：你好，我是 Punk。
- 介紹：我用 AI、設計和內容，把想法做成作品。
- 身份：中科大 MBA、HerName 首席設計師、Stanley 商學院執行院長
- 頁面內容：關於我、作品、聯絡方式
- 頭像：使用 images/punk.jpg

二、我的設計要求

- 整體使用明亮的黃色背景和黑色文字；
- 首屏左側放標題和介紹，右側放像素頭像；
- 「看看我的作品」使用通透的亮藍色按鈕；
- 「和我打個招呼」使用明亮的正紅色按鈕；
- 頭像完整顯示，不裁掉人物、相機和薩克斯風；
- 保留充足留白，頁面清楚、有趣，手機上也容易閱讀；
- 動態效果保持輕量，包含按鈕懸停和適量的進入效果；
- 參考剛才的設計 DNA 決定具體字級、間距、圖片比例和元件細節。

三、原創和檔案要求

1. 使用原生 HTML、CSS 和 JavaScript；
2. 建立清楚的專案資料夾和 README；
3. 不安裝前端框架；
4. 不複製參考網頁的 Logo、品牌名、文案、圖片、影片和原始碼；
5. 不使用 iframe，也不把參考網頁截圖當成背景；
6. 可以借鑑配色比例、字型層級、網格、元件和動態效果規律；
7. 所有檔案只寫入當前專案資料夾；
8. 如果資料夾已有內容，先讀取並說明準備修改哪些檔案；
9. 圖片新增準確的文字說明；
10. 動態效果需要照顧不希望看到動畫的使用者。

四、完成瀏覽器驗收

製作完成後，請：
1. 啟動本機預覽；
2. 在 1440×900 的電腦尺寸檢查頁面；
3. 在 390×844 的手機尺寸檢查頁面；
4. 點選導覽和所有按鈕；
5. 檢查標題裁切、圖片變形、橫向捲動和資源載入；
6. 檢查瀏覽器控制台有沒有出現錯誤；
7. 發現問題直接修復，再重新檢查；
8. 儲存電腦版和手機版截圖；
9. 最後列出實際建立或修改的檔案；
10. 說明最終頁面分別採用了哪些設計 DNA，又做了哪些原創調整。

請直接完成製作和驗收，不要在聊天裡貼上整段網頁程式碼。

兩步拆開以後，你可以在 AI 代理動手前先糾正設計方向。分析通過，再進入製作，返工會少很多。

不要讓 AI 代理下載對方的照片、Logo 或原始碼。最終頁面借鑑設計規律，名字、文字、圖片和品牌都來自自己的專案。

十二、第一版出來以後，怎樣繼續修改

第一版很少一次到位。你可能覺得頭像太小、黃色偏暗，或者按鈕顏色不夠亮。

按照前面學過的四步循環繼續：

四步循環

說清修改內容 → AI 代理修改 → 重新整理瀏覽器 → 檢查結果

例如：

提示詞（可直接複製給 AI 代理）

請繼續修改當前網頁：

1. 保留現有結構和文字；
2. 黃色背景再明亮一點；
3. 藍色和紅色按鈕提高亮度，但不要使用螢光色；
4. 頭像稍微放大，保持完整顯示；
5. 其他內容不要改動。

修改後重新檢查電腦版和手機版。

「做得高級一點」很難執行。顏色、位置、大小、間距和動態效果都可以說得更具體。

十四、部署上線：讓別人透過網址開啟

到這裡，網頁已經能在你的電腦上執行。但位址列裡的 localhost 只有你自己能存取。

部署，就是把專案檔案放到公開伺服器上。部署完成後，平台會給你一個公開網址，你可以把它發給任何人。

第一個純 HTML、CSS、JavaScript 專案，可以使用 GitHub Pages。官方入門流程支援從儲存庫分支直接發布。

最簡部署流程

  1. 登入 GitHub，新增一個公開儲存庫；
  2. 把專案裡的 index.html、css、js、images 和 README 上傳到儲存庫；
  3. 確認儲存庫最外層可以直接看到 index.html；
  4. 開啟儲存庫的 Settings → Pages；
  5. 在 Build and deployment 中選擇 Deploy from a branch；
  6. 選擇存放網頁檔案的分支和根目錄；
  7. 儲存設定，等待平台產生公開網址；
  8. 開啟網址，再檢查一次電腦版、手機版、圖片和按鈕。

你也可以讓 AI 代理帶著你完成：

提示詞（可直接複製給 AI 代理）

請檢查當前網頁是否適合部署到 GitHub Pages。

先完成這些檢查：
1. 確認 index.html 位於專案根目錄；
2. 檢查 CSS、JavaScript 和圖片是否全部使用相對路徑；
3. 檢查專案中有沒有密碼、API Key、私人地址或不應該公開的檔案；
4. 檢查電腦版和手機版沒有明顯錯誤。

檢查通過後，請按照 GitHub Pages 當前的官方流程，一步一步帶我部署。
每一步說明我要點選哪裡、應該看到什麼。
等我確認以後再進入下一步，不要替我猜帳號、儲存庫名或權限設定。

部署完成後，請幫我開啟公開網址並做一次最終檢查。

公開前再看一眼專案內容。私人電話、家庭地址、合約、公司內部資料、API Key 和沒有授權的圖片，都不要放進公開儲存庫。

當 GitHub 提供的網址能夠正常開啟時，你的網頁已經上線了。

這篇在說什麼

這是一篇寫給完全沒碰過網頁的人的入門課。前半段帶你親手做一個最小的網頁：建資料夾、寫幾行 HTML、加上 CSS 外觀、用 JavaScript 讓按鈕有反應；後半段示範怎麼交給 AI 代理（Agent），做出一個黃色的 Punk 個人首頁，最後放上 GitHub Pages 讓別人用網址打開。

作者的核心觀點是：現在叫 AI 做出第一版很容易，真正拉開差距的是「第二輪修改」。懂一點網頁結構的人，能把問題說清楚、把修改範圍框住，AI 代理就不用一直亂猜。

為什麼值得學

你不需要變成工程師，但需要一套「跟 AI 溝通的詞彙」。說「圖片怎麼沒了」，AI 只能猜；說「檢查 images 資料夾的相對路徑」，它馬上知道去哪裡找。作者說這些老術語，反而成了 AI 代理建站的實用寶典。

你可以帶走的重點

1. 一個網頁是三個檔案分工合作

HTML 管結構和內容（骨架），CSS 管外觀（皮膚），JavaScript 管互動（大腦）。想改文字找 HTML、想換顏色找 CSS、按鈕沒反應查 JavaScript。分得清楚，就知道該叫 AI 改哪裡。

2. 檔案路徑是新手最常出包的地方

網頁要讀圖片、CSS、JavaScript，都靠「路徑」告訴它檔案在哪。圖片裂開，多半是路徑、大小寫或副檔名不對。新手守住「三不」：不隨意刪除、不隨意移動、不隨意改名檔案；真的要改，路徑也要一起改。

就像搬家後沒改通訊地址：信（圖片）還是寄到舊地址，自然收不到。

3. 養成「修改、儲存、重新整理、驗證」的習慣

一次只改一個地方，改完存檔、重新整理瀏覽器、親眼確認。不滿意就再改一輪。這個習慣交給 AI 代理之後同樣適用：AI 說改好了，你還是要自己打開瀏覽器看。

4. 叫 AI 代理做網頁：先分析，再製作

作者把指令拆成兩步。第一步只讓 AI 分析你挑的參考網頁（配色、排版、字型、按鈕、動態效果、手機版），整理成一份「設計 DNA」，這時不准動任何檔案；你看過、追問、確認方向後，第二步才發製作指令。方向先對了，返工就少。

另外記得：只借鑑設計規律，不要讓 AI 下載別人的照片、Logo 或原始碼。

5. 修改要具體，驗收不能只聽 AI 說

「做得高級一點」很難執行。照作者的公式說：找到誰 → 改什麼 → 改成什麼，例如「黃色背景再明亮一點、頭像稍微放大、其他不要動」。完成後讓 AI 用電腦和手機兩種尺寸檢查、點過所有按鈕、看控制台有沒有錯誤，再截圖給你看。

6. 公開之前先檢查隱私

放上 GitHub Pages 前，確認私人電話、家庭地址、合約、公司內部資料、API Key 和沒有授權的圖片都不在專案裡。公開儲存庫，任何人都看得到。

怎麼開始

  1. 照第二章建一個 my-first-site 資料夾，裡面放 css、js、images 三個子資料夾和 index.html。
  2. 複製第五到七章的三段小程式碼，每加一段就存檔、重新整理，看見變化再往下。
  3. 去 Recent、Land-book 這類網站挑一兩個喜歡的網頁，記下你喜歡它哪裡。
  4. 打開你的 AI 程式設計工具，先貼「分析參考網頁」那段提示詞，確認設計 DNA 後再貼「製作指令」。
  5. 最後貼「最終檢查」與「部署」提示詞，讓 AI 一步一步帶你上線，每一步都由你確認。

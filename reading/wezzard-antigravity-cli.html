讓 Antigravity CLI 不再那麼難用的 9 個技巧

Gemini 4 是很強的模型，但 Google 的 Antigravity 用起來很痛苦。由於大多數開發者在遠端工作時偏好連進命令列介面（CLI），這篇文章聚焦在 Antigravity CLI（簡稱 agy），分享幾項能減少摩擦、讓它沒那麼難用的設定。

在日常的終端機工作裡，有四個痛點特別明顯：

  • 權限提示不停跳出來：跨資料夾讀取、寫入暫存檔、呼叫 MCP 工具，以及透過 npx skills 安裝的全域 Skills（技能），都會一再觸發核准對話框。
  • 脈絡視窗（context window）大小是固定的：Antigravity 沒有提供任何設定，讓你依工作量調整或微調脈絡視窗（context window）的上限。
  • 脈絡壓縮（compaction）做得很差：長時間的工作階段（session）一旦碰到壓縮（compaction）門檻，自動摘要就會漏掉重要細節，讓後續的回合品質變差。
  • 輸入框的快捷鍵打亂了終端機的肌肉記憶：在 agy 裡，和 Claude Code 或 Codex 不同，按一次 Esc 或按 Ctrl+C 不會清掉輸入框裡打好的字，按兩次 Esc（Esc Esc）也不會回溯（rewind）對話。

固定的脈絡視窗（context window）和差勁的壓縮（compaction），在 Google 更新工作環境（harness）本身之前都無解。為了讓 agy 現在就沒那麼難用，以下是分屬三個面向的九個實用修正：馴服權限提示；自訂介面、可觀測性（observability）與隱私；以及適應它的鍵盤快捷鍵。

先搞清楚 Antigravity CLI 把設定存在哪裡Know Where Antigravity CLI Stores Its Config

Antigravity 的 CLI（agy）和它的圖形介面（GUI）版本並不共用同一套設定檔或設定方式，因為兩者的架構與功能不同。舉例來說，圖形介面（GUI）支援生成式介面（Generative UI）這類豐富的視覺功能，而 agy 是一個獨立、輕量的 Go 執行檔（binary），為終端機和遠端 SSH 工作流程而設計。

重要（Important）：你在 Antigravity 圖形介面（GUI）用戶端裡改的任何權限預設或偏好設定，都不會套用到 agy。CLI 讀寫的是它自己放在 ~/.gemini/antigravity-cli/ 的設定檔。

  • CLI 的所有設定和權限允許清單（allowlist），都放在 ~/.gemini/antigravity-cli/settings.json：你可以直接在磁碟上編輯這個 JSON 檔，也可以在 agy 裡即時修改：用 /settings 改 Agent Mode、Sandbox Mode、Non-Workspace Access 和 Tool Permission，用 /permissions 改權限允許清單（allowlist）。
  • agy 的全域 skill 放在 ~/.gemini/antigravity-cli/skills/：放在這個資料夾（以及 ~/.gemini/skills/）以外的 skill，不是啟動時被漏掉，就是被當成外部檔案存取。

馴服一再出現的權限提示Tame Repetitive Permission Prompts

乍看之下，Antigravity 讓人很挫折，因為它的預設設定幾乎每個動作都要問你。不過，一旦你研究過它的各項控制是怎麼搭在一起的，就會發現 Antigravity 的權限模型是圍繞三個核心概念建立的：Project（專案）、Workspace（工作區）和 Sandbox（沙箱）：

  • Project：把磁碟上一個或多個實體儲存庫（repo）資料夾，歸到同一個專案底下（在 agy 裡用 /projects 或 --add-dir 設定；預設只有啟動時所在的那個資料夾，歸在 default-cli-project 底下）。
  • Workspace：由目前作用中 Project 裡設定的所有資料夾組成。Agent Mode（代理模式）設為 Auto 時，Antigravity 會把 Workspace 當成檔案操作唯一的預設範圍，連 Workspace 以外的 read_file 呼叫都會攔下來。
  • Sandbox：在 Workspace 外圍建一道作業系統層級的隔離邊界（在 agy 裡用 "enableTerminalSandbox": true 設定；macOS 上用 Apple Seatbelt 的 sandbox-exec，Linux 上用 bwrap 命名空間〔namespaces〕），讓你可以把 Tool Permission（工具權限）設成在沙箱（sandbox）內自動核准、在沙箱外詢問（"proceed-in-sandbox"），或到哪裡都自動核准（"always-proceed"）。

在預設狀態下（見下圖），就算 Agent Mode 設成 Auto，agy 執行時 Sandbox Mode（沙箱模式）是關閉的、Project 是只有一個資料夾的預設專案、Tool Permission 設為 Request review，而且 permissions.allow 清單是空的。所以存取旁邊的儲存庫（repo）、執行 shell 指令、寫 /private/tmp 暫存檔、讀系統 SDK，以及呼叫 MCP，都會一再停下來等你手動核准：

在介紹兩套完整的自動核准配方（recipe）之前，我們需要兩塊基礎：透過設定 Project，把相關的儲存庫（repo）加進 Workspace，以及在設定檔裡填好權限允許清單（allowlist），涵蓋常見的外部存取。

透過 Project 把其他儲存庫資料夾加進 WorkspaceAdd Other Repository Directories to the Workspace via Project

Antigravity 對 read_file 的預設規則是 Ask (Allowed in workspace)：在 Workspace 內自動允許，在 Workspace 外則會詢問，即使 Non-Workspace Access（非工作區存取）是開著的也一樣。因此，要停止跨相關儲存庫（repo，例如前端儲存庫、後端儲存庫和共用規格）的讀取提示，最乾淨的做法是設定一個 Project，把這些資料夾加進 Workspace 和 Sandbox 的邊界裡。

在 agy 裡，用 /projects（或 --project）設定 Project 底下的資料夾，或用 --add-dir 和 /add-dir 把額外的資料夾掛進目前的 Workspace：

bash

# Open a specific multi-directory Project directly at launch
agy --project=<project-id>

# Or mount extra directories into the active Workspace and Sandbox boundary on the fly
agy --add-dir ../backend --add-dir ../shared-specs

註解中譯：第一行「啟動時直接開啟指定的多資料夾 Project」；第二行「或臨時把額外資料夾掛進目前作用中的 Workspace 與 Sandbox 邊界」。

text

# Right after entering agy, configure and switch to your Project first
/projects
/add-dir ../shared-specs

註解中譯：「一進入 agy，就先設定並切換到你的 Project」。

  • 一進入 agy 就建立並切換 Project：在 agy 裡切換 Project 一定會開啟新的對話。如果你先開始聊、做到一半才切換 Project，目前的對話會留在舊的 Project 裡。
  • 建立 Project 之後記得切換過去：在 agy 裡建立新的 Project，不會自動啟用它。在你明確選擇 Switch to project（或用 agy --project=<project-id> 啟動）之前，工作階段（session）都還在預設的 default-cli-project 底下執行，跨資料夾讀取也會繼續跳出提示。
  • 作用中 Project 底下設定的資料夾，都會納入 Workspace：作用中 Project 裡的每個資料夾，都能自動執行 read_file、write_file 和沙箱（sandbox）內的 shell 指令，不會詢問。

在設定裡填好權限允許清單Populate the Permission Allowlist in Settings

有些操作落在你的 Project 儲存庫（repo）資料夾以外，原本會觸發 Ask 提示：MCP 伺服器、macOS 上 /private/tmp 底下的暫存檔存取，以及讀取系統 SDK 資料夾（例如 Apple 的 SDK 資料夾）或共用參考資料夾。針對這些操作，透過 /permissions，或直接在 ~/.gemini/antigravity-cli/settings.json 的 "permissions" 底下，填好 allow 權限允許清單（allowlist）（評估順序為 Deny > Ask > Allow）：

json

{
  "permissions": {
    "allow": [
      "mcp(playwright/*)",
      "mcp(chrome-devtools/*)",
      "mcp(cua/*)",
      "mcp(github/*)",
      "mcp(context7/*)",
      "write_file(/private/tmp)",
      "read_file(/Library/Developer/CommandLineTools/SDKs/)",
      "read_file(/Applications/Xcode.app/Contents/Developer/Platforms/)",
      "read_file(/path/to/shared-dir/)"
    ]
  }
}
  • 第 1 類：mcp(<server-name>/*) 一次核准受信任 MCP 伺服器上的所有工具：在 Antigravity 的權限表裡，MCP 呼叫預設是 Ask。替你常用的 MCP 伺服器加上萬用字元（wildcard），例如 mcp(playwright/*)、mcp(chrome-devtools/*)、mcp(cua/*)（電腦操作代理〔Computer-Use Agent〕）、mcp(github/*) 或 mcp(context7/*)，代理（agent）就能呼叫這些伺服器上的每個工具，不必停下來。
  • 第 2 類：write_file(/private/tmp) 讓 macOS 上 /private/tmp 底下的讀取和寫入提示都消失：在 macOS 上，/tmp 是指向 /private/tmp 的符號連結（symbolic link）。當工具解析出實際路徑 /private/tmp/... 時，Antigravity 會把它當成 Workspace 以外的路徑而詢問。根據官方的權限文件，允許 write_file(/private/tmp) 也會隱含授予 read_file(/private/tmp)，所以一條規則就能讓 /private/tmp 的讀取和寫入提示一起停下來。
  • 第 3 類：read_file(...) 授予系統 SDK 資料夾（例如 Apple 的 SDK 路徑）與共用參考資料夾的讀取權限：因為 Workspace 以外的路徑預設是 Ask，查看系統標頭檔或框架定義（例如 macOS 上的 /Library/Developer/CommandLineTools/SDKs/ 和 /Applications/Xcode.app/Contents/Developer/Platforms/），或共用參考資料夾，都會觸發權限提示。把這些系統 SDK 資料夾和參考資料夾加進 read_file(...)，會覆蓋 "allowNonWorkspaceAccess": false，讓每個專案都不再重複詢問讀取，並在終端機的 Sandbox 裡把這些路徑掛載成唯讀（read-only）。

在設定裡選一套自動核准配方Choose an Auto-Approval Recipe in Settings

Project 資料夾和 permissions.allow 清單都就位之後，在 agy 裡開啟 /settings（或編輯 ~/.gemini/antigravity-cli/settings.json），依你想要嚴格的邊界檢查還是不受限制的執行，從兩套完整的權限配方（recipe）中擇一：

配方一：在沙箱邊界內自動允許Recipe 1: Auto-Allow Inside the Sandbox Boundary

這套配方讓代理（agent）在你的 Workspace（包括加進 Project 的儲存庫〔repo〕）、終端機 Sandbox 和 permissions.allow 路徑之內執行時不跳提示；但只要它想讀寫你沒加進 Project 或允許清單（allowlist）的外部路徑，就會停下來請你確認（見下圖）。

用你的多資料夾 Project 啟動 agy（或臨時掛載旁邊的資料夾）：

bash

agy --project=<project-id>
# Or mount sibling directories for the session:
agy --add-dir ../backend --add-dir ../shared-specs

註解中譯：「或在這次工作階段臨時掛載旁邊的資料夾」。

再把完整的權限與允許清單（allowlist）設定放進 ~/.gemini/antigravity-cli/settings.json：

json

{
  "agentMode": "auto",
  "enableTerminalSandbox": true,
  "allowNonWorkspaceAccess": false,
  "toolPermission": "proceed-in-sandbox",
  "permissions": {
    "allow": [
      "mcp(playwright/*)",
      "mcp(chrome-devtools/*)",
      "mcp(cua/*)",
      "mcp(github/*)",
      "mcp(context7/*)",
      "write_file(/private/tmp)",
      "read_file(/Library/Developer/CommandLineTools/SDKs/)",
      "read_file(/Applications/Xcode.app/Contents/Developer/Platforms/)",
      "read_file(/path/to/shared-dir/)"
    ]
  }
}

配方二：到哪裡都直接執行Recipe 2: Always Proceed Everywhere

如果你在專用的雲端虛擬機（VM）或容器（container）裡工作，或單純想讓代理（agent）在 Workspace 和外部資料夾之間一路往前衝、不為檔案權限提示停下來，就把 "toolPermission" 設成 "always-proceed"，並把 "allowNonWorkspaceAccess" 設成 true。因為外部檔案的讀寫、/private/tmp 和 SDK 資料夾都會自動核准，你不需要設定多資料夾的 Project，也不需要檔案路徑的允許清單（allowlist）規則；permissions.allow 裡只要留下受信任的 MCP 伺服器規則就好（或用 agy --dangerously-skip-permissions 啟動，連 MCP 提示都跳過，見下方）：

json

{
  "agentMode": "auto",
  "enableTerminalSandbox": true,
  "allowNonWorkspaceAccess": true,
  "toolPermission": "always-proceed",
  "permissions": {
    "allow": [
      "mcp(playwright/*)",
      "mcp(chrome-devtools/*)",
      "mcp(cua/*)",
      "mcp(github/*)",
      "mcp(context7/*)"
    ]
  }
}

以下是兩套配方裡的核心設定如何互相作用：

  • 把 Agent Mode（"agentMode"）維持在 "auto"：雖然 Agent Mode 有 Default、Plan、Auto 和 Accept Edits 四種（用 Shift + Tab 循環切換），"auto" 是日常工作的標準選擇，會自動核准目前 Workspace 內的檔案讀寫（注意：Antigravity 的權限規則只定義了 read_file 和 write_file，沒有另外的 edit_file 權限動作）。
  • 開啟 Sandbox Mode（"enableTerminalSandbox": true）：agy 預設在 Sandbox 外執行。開啟 Sandbox Mode 後，終端機指令會被隔離：macOS 上用 Apple Seatbelt（sandbox-exec），Linux 上用 bwrap 命名空間（namespaces），擋下未經授權的網路存取和主機上的機密（例如 ~/.ssh），同時解鎖 Proceed in sandbox。
  • 在配方一中，把 Non-Workspace Access（"allowNonWorkspaceAccess"）維持在 false，避開「讀取會問、寫入不問」的陷阱：當 "allowNonWorkspaceAccess" 是 false，任何 Workspace 以外的存取都會跳出一個三選一的選單，其中第二個選項會永久開啟 Non-Workspace Access。很多使用者為了不再被一直詢問而選了第二個選項，這會在 Auto 模式下觸發一個違反直覺的陷阱：因為 Auto 模式會自動核准檔案編輯，而 read_file 退回 Ask (Allowed in workspace)，所以在 "proceed-in-sandbox" 底下把 "allowNonWorkspaceAccess" 改成 true，會讓 Antigravity 在讀取不在允許清單（allowlist）上的外部檔案時仍然詢問，卻在完全不跳提示的情況下，靜默建立或覆寫你 Workspace 以外的任何檔案（write_file）！反過來說，permissions.allow 規則的優先順序高於 "allowNonWorkspaceAccess": false：在配方一中，把 "allowNonWorkspaceAccess" 維持在 false，再把你信任的外部路徑加進 permissions.allow，這些列在允許清單（allowlist）上的路徑就能零提示通過，而沒列入的外部讀取和外部寫入都會被擋下。
  • 用 Tool Permission（"toolPermission"）選定你的配方：預設的 Request review 會在每次 git status、npm test 或 ls -la 之前詢問。改成 "proceed-in-sandbox"（配方一）會自動核准 Workspace、Sandbox 和 permissions.allow 清單內的一切，清單外則詢問；改成 "always-proceed"（配方二）會自動核准 Workspace 內外的檔案讀寫與指令。

修正 npx skills 安裝位置錯誤造成的權限提示Fix Permission Prompts Caused by the Wrong npx skills Install Directory

執行 npx skills add <owner/repo> -g，會把全域 skill 裝到 ~/.agents/skills/，而不是 ~/.gemini/antigravity-cli/skills/。因為 ~/.agents/skills/ 在你作用中的 Workspace 之外，讀取某個 skill 的 SKILL.md 或輔助指令碼（script）時，就會觸發外部檔案存取提示。

用 ln -sf 把 ~/.agents/skills 連結到 ~/.gemini/antigravity-cli/skills：

bash

ln -sf ~/.agents/skills ~/.gemini/antigravity-cli/skills

自訂介面、可觀測性與隱私Customize the UI, Observability, and Privacy

agy 預設會蒐集使用遙測（telemetry）、在頂端列顯示你的個人帳號資訊、在底部輪播使用小技巧，並把執行細節和工作階段（session）歷史收合起來。接下來四項設定能鎖好你的隱私，並把介面整理乾淨。

關閉遙測Turn Off Telemetry

Antigravity 預設開啟 Enable Telemetry 來蒐集使用資料。如果你在意 Workspace 和工作階段（session）的隱私，馬上把它關掉。

有一個地方要注意：用 Google 帳號登入時，Enable Telemetry 是存成雲端同步的帳號偏好設定，而不是從本機的 settings.json 讀取；用應用程式介面金鑰（API key）登入的工作階段（session），則會從 ~/.gemini/antigravity-cli/settings.json 讀取 "enableTelemetry": false（或 --disable_telemetry 旗標）。兩邊都關掉，不管哪種模式都有涵蓋到：

  1. 在 agy 工作階段（session）裡執行 /settings（或 /config），輸入 telemetry 篩選清單，把 Enable Telemetry 切換為 off。
  2. 在 ~/.gemini/antigravity-cli/settings.json 加上 "enableTelemetry": false：

json

{
  "enableTelemetry": false
}
  • 在 /settings 把 Enable Telemetry 切成 off，更新的是你帳號層級的設定：關閉後，登入你 Google 帳號的工作階段（session）就不會再送出使用遙測（telemetry）。
  • 在 settings.json 設定 "enableTelemetry": false，涵蓋本機與應用程式介面金鑰（API key）的工作階段：即使你沒有登入 Google 帳號就執行 agy，也能確保 CLI 層級的遙測（telemetry）維持關閉。

隱藏帳號資訊與啟動標誌Hide Account Info and the Startup Logo

啟動時，agy 會在終端機標頭左側印出一個彩色像素風的 ASCII 標誌，旁邊緊接著顯示你登入的 Google 帳號電子郵件（見下圖上方的視窗）。如果你會直播寫程式、錄製示範影片，或分享終端機截圖，這個標頭就會把你的個人電子郵件地址暴露給觀眾。

在 ~/.zshrc（或 ~/.bashrc）加上兩個環境變數，就能在每個工作階段（session）把它們藏起來（見下圖下方的視窗）：

bash

export AGY_CLI_HIDE_ACCOUNT_INFO=1
export AGY_CLI_HIDE_LOGO=1

如果你想在自己工作時保留預設標頭，只在直播或錄影時才隱藏，可以改成包在一個 shell 別名（alias）裡：

bash

alias agy-live='AGY_CLI_HIDE_ACCOUNT_INFO=1 AGY_CLI_HIDE_LOGO=1 agy'
  • AGY_CLI_HIDE_ACCOUNT_INFO=1 會在直播和截圖時隱藏你的帳號電子郵件：它會把標頭裡顯示登入電子郵件的那一行拿掉，讓你可以放心直播或錄下終端機畫面。
  • AGY_CLI_HIDE_LOGO=1 會隱藏 ASCII 啟動標誌：它會拿掉好幾行高的像素風標誌，讓標頭在窄的分割窗格和 tmux 視窗裡保持精簡。

關閉輪播的使用小技巧Turn Off Rotating Usage Tips

Gemini 4 產生回應時，agy 會在讀取動畫（spinner）下方輪播使用小技巧。等你熟悉快捷鍵之後，這些變來變去的文字就只是視覺干擾。

在 ~/.gemini/antigravity-cli/settings.json 把它關掉（或透過 /settings 把 Show Tips 切成 off）：

json

{
  "showTips": false
}

把詳細程度設為高，並讓對話選擇器依 Workspace 分組Set Verbosity to High and Group the Conversation Picker by Workspace

想完整看到代理（agent）在做什麼，並讓 /resume 的歷史紀錄在不同專案之間保持整齊，就在 /settings（或 ~/.gemini/antigravity-cli/settings.json）開啟兩個選項：

json

{
  "verbosity": "high",
  "pickerGrouping": "grouped"
}
  • "verbosity": "high"（Verbosity，詳細程度）讓你擁有完整的可觀測性（observability）：預設的 "medium" 會把相關的工具呼叫和思考過程收合成摘要。把 "verbosity" 設成 "high"，每個工具呼叫、背景指令和思考過程都會完整呈現。
  • "pickerGrouping": "grouped"（Conversation Picker Grouping，對話選擇器分組）讓 /resume 依 Workspace 分組：預設的 "none" 會把所有過去的對話依時間排成一整條平的清單。把 "pickerGrouping" 設成 "grouped"，/resume 選擇器就會依 Workspace 整理（你也可以在 /resume 裡按 Ctrl+F 隨時切換分組）。

適應非標準的鍵盤快捷鍵Adapt to the Non-Standard Keyboard Shortcuts

用兩次 Esc 清除輸入，用斜線指令回溯Use Double Esc to Clear Input and Slash Commands to Rewind

如果你是從 Claude Code 或 Codex 轉到 agy，一開始會覺得輸入框的快捷鍵壞掉了。根據官方的 CLI 參考文件，這是刻意的設計：agy 把 Esc 和 Ctrl+C 綁定到一個受保護的 cli.escape 動作，規則不一樣：

表格共三欄，手機上可左右滑動查看。

動作（Action）Claude Code／CodexAntigravity CLI（agy）
清除輸入框裡打好的字（Clear typed text in the prompt box）Ctrl+C 或按一次 Esc閒置時按兩次 Esc（Esc Esc）

以下為譯者整理，非原文內容。

這篇在說什麼

WeZZard 整理了 Google 的 Antigravity CLI（指令是 agy）九項設定，目標很單純：讓它少問你一點、少洩漏一點，用起來不要那麼卡。

作者先承認有兩個問題目前改不了：脈絡視窗（context window）大小固定、長對話的壓縮（compaction）會掉細節，只能等 Google 更新。其餘的痛點則分成三組處理：一是權限提示太多，靠 Project、Workspace、Sandbox 三個概念和一份允許清單（allowlist）解決；二是介面與隱私，包括關掉遙測（telemetry）、藏起帳號電子郵件、關掉輪播小技巧、把執行細節全部攤開；三是快捷鍵和 Claude Code、Codex 不一樣，要重新記。最後附上兩套可以直接複製的完整設定檔。

為什麼值得學

如果你正在用或打算試 Antigravity CLI，這篇幾乎可以照抄。就算你用的是別的 AI 代理工具，它把「權限到底怎麼判斷」拆開來講的方式也很有參考價值：先分清楚哪些範圍是自己人、哪些是外面，再決定要不要自動放行。讀的時候留意：文中的設定名稱、版本（例如畫面上的 Antigravity CLI 1.5.10）和預設值都可能隨更新改變；配方二會讓代理（agent）在你的電腦上幾乎不受限制地讀寫，作者建議只在專用的雲端虛擬機或容器裡用。

你可以帶走的重點

1. 先確認你改的是哪一份設定

Antigravity 的圖形介面（GUI）和 CLI 是兩套東西，設定不共用。你在圖形介面裡調好的權限，agy 完全不會理會。CLI 的設定都放在 ~/.gemini/antigravity-cli/：settings.json 管設定和權限，keybindings.json 管按鍵，skills/ 放全域 skill。改之前先確認位置，才不會白忙一場。

在 agy 裡也可以直接用 /settings 和 /permissions 即時修改，結果一樣寫進 settings.json。

2. 權限是三層同心圓：Project、Workspace、Sandbox

Project 決定「哪些資料夾算自己人」，可以一次放進前端、後端、共用規格等多個儲存庫（repo）；作用中 Project 的資料夾合起來就是 Workspace，代理（agent）在裡面讀寫不必問；Sandbox 再在外面加一道作業系統層級的沙箱（sandbox），讓 shell 指令也能放心自動執行。圈外的路徑，預設一律詢問。所以要少被問，最乾淨的做法不是到處開權限，而是把常用的資料夾收進 Project。

兩個小陷阱：在 agy 裡切換 Project 一定會開新對話，所以一進去就先切；新建的 Project 不會自動啟用，要記得選 Switch to project。

3. 兩套配方：看你要不要邊界

配方一（proceed-in-sandbox）適合在自己的電腦上用：Workspace、沙箱（sandbox）和允許清單（allowlist）裡的一切自動通過，碰到清單外的路徑才停下來問你。配方二（always-proceed）適合專用的雲端虛擬機或容器：內外全部自動放行，不必設定多資料夾 Project，允許清單只要留 MCP 規則。允許清單裡最實用的三類是：常用 MCP 伺服器的萬用字元、macOS 的 /private/tmp、系統 SDK 與共用參考資料夾。

一個省事的細節：macOS 的 /tmp 是指向 /private/tmp 的符號連結（symbolic link），而允許 write_file(/private/tmp) 會順便允許讀取，一條規則就解決讀寫兩種提示。

4. 小心「讀取會問、寫入不問」的陷阱

Workspace 以外的存取會跳出三選一的選單，很多人為了不再被問，選了第二個選項「永久開啟 Non-Workspace Access」。作者指出，在配方一的設定下這反而危險：讀外部檔案仍然會問，寫外部檔案卻完全不問，代理（agent）可以靜默建立或覆寫你 Workspace 以外的任何檔案。正確做法是把它維持在 false，再把信任的外部路徑一條條加進允許清單（allowlist）；清單的優先順序比它高，列進去的路徑零提示通過，沒列的讀寫都會被擋下。

這也是全文最值得記住的一句：想少被問，應該「明確列出信任的地方」，而不是「把整道門打開」。

5. 隱私與習慣：遙測關兩處，Esc 要重新記

遙測（telemetry）要關兩個地方：用 Google 帳號登入時，設定存在雲端帳號裡，要在 /settings 裡關；用應用程式介面金鑰（API key）時讀本機 settings.json，要加 "enableTelemetry": false。會直播或分享截圖的人，再加兩個環境變數藏起電子郵件和標誌，或做成 agy-live 別名（alias）只在錄影時用。介面上，關掉輪播小技巧、把 verbosity 設成 high 換來完整的可觀測性（observability），並讓 /resume 依 Workspace 分組。至於快捷鍵，下圖這三個差異最容易按錯。

按兩次 Ctrl+C 在 agy 裡不是清除，而是直接離開工作階段（session），從 Claude Code 轉過來的人特別要小心。

怎麼開始

  1. 打開 ~/.gemini/antigravity-cli/settings.json，確認你改的是 CLI 這一份，不是圖形介面（GUI）的設定。
  2. 一進入 agy 就用 /projects 把常一起用的儲存庫（repo）收進同一個 Project，並記得切換過去。
  3. 在自己的電腦上，從「完整的複製貼上設定」的配方一開始，把 /path/to/shared-dir/ 換成你自己的共用資料夾；只有在專用的雲端 VM 或容器裡才考慮配方二。
  4. 到 /settings 搜尋 telemetry 把遙測（telemetry）關掉，並在 ~/.zshrc 加上兩個隱藏帳號資訊的環境變數。
  5. 如果你用 npx skills add -g 裝過 skill，執行一次 ln -sf 那行指令，把資料夾連結過去。

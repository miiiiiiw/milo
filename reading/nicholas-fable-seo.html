開始之前：先更新 Claude Code，否則它不會吃進這個模型（Before we start: update Claude Code, or it won't take the model）

Fable 5.2 是一個新的模型 id，舊版 Claude Code 根本不知道它存在。

所以開頭這兩道指令很無聊，但你不能跳過：

指令（英文原文，可直接複製）

claude --model claude-fable-5-2 --effort high

中文說明

更新 Claude Code
用 Fable 5.2、費力等級 High 啟動

Fable 5.2 是從 Claude Code 2.1.321 開始支援的。執行 claude --version：再舊的版本就不認識這個模型。

接著記住，Fable 5.2 自己不會知道這些事：

  • 每個月有多少人搜尋「oak coffee table」
  • 你的點擊（click）、曝光次數（impressions）和排名
  • 今天 Google 在搜尋結果頁（SERP）上秀了什麼
  • 哪些競爭對手的頁面正在拿走你的流量

你還是問它的話，它會用訓練資料來回答。你在那個答案上蓋起來的一切，都只是猜測。

所以這份工作分成三塊：

  • Fable 5.2 是手。它負責規劃、撰寫、檢查。
  • ChatSEO 是腦。透過它的 MCP，它會帶進你的 Search Console、關鍵字搜尋量、即時的搜尋結果頁（SERP），以及競爭對手的頁面。
  • 你是老闆。沒有你點頭，什麼都不能上線。

要把腦接上去，先建立 ChatSEO 帳號、加入你的網站、連接 Search Console，然後把 MCP 加進 Claude Code：

指令（英文原文，可直接複製）

claude mcp add --transport http chatseo https://api.chatseo.app/mcp

把 ChatSEO 的 MCP 加進 Claude Code（以 HTTP 傳輸）

這樣，下面每一則提示詞（prompt）用的都是真實資料，而不是記憶。

1. 動筆之前，先挑會賺錢的關鍵字（1. Pick the keywords that pay before you write a word）

更好的模型，如果把頁面寫給錯的關鍵字，只會讓你更快得到零。

「What is a coffee table」（什麼是咖啡桌）會帶來訪客，但打這幾個字的人，沒有一個在買東西。

「Oak coffee table」是已經把信用卡拿在手上的人在打的。

你不需要工具來判斷搜尋意圖（intent），因為 Google 已經測試過了。搜那個關鍵字，看誰排在前面：

  • 部落格文章、上方還有定義框：這是資訊型（informational）。先跳過。
  • 產品頁、帶價格的分類頁：這是交易型（commercial）。這才是你的目標。

然後是第二道篩選，也是讓多數專案夭折的那一道：以你現在的規模，打得過這個搜尋結果頁（SERP）嗎？

提示詞（prompt）（英文原文，可直接複製）

Using ChatSEO, give me the best SEO strategy for my site. Then:

1. Keep only keywords where the current top 3 are product, category
   or landing pages. Drop anything blog posts dominate.
2. For each keyword left, tell me if sites my size rank in the top 10.
   If the top 10 are all big brands, mark it LATER.
3. Give me the 10 best keywords to start with: keyword, monthly
   volume, the page type Google wants.
4. Use only the volumes ChatSEO returns. Never estimate one.

中文翻譯

用 ChatSEO，為我的網站提出最好的 SEO 策略。然後：

1. 只保留目前前 3 名是產品頁、分類頁或到達頁（landing page）的關鍵字。
   部落格文章佔多數的，全部去掉。
2. 對剩下的每個關鍵字，告訴我跟我規模相近的網站有沒有排進前 10 名。
   如果前 10 名全是大品牌，標成 LATER。
3. 給我最適合先做的 10 個關鍵字：關鍵字、每月搜尋量、
   Google 想要的頁面類型。
4. 搜尋量只用 ChatSEO 回傳的數字。絕對不要自己估一個。

第 4 條是大家最常跳過的那一行。如果模型給你一個工具沒有提供的搜尋量，那就是它在猜。

讓我們栽了前幾個月的那個錯誤（The mistake that cost us the first months）

在 ChatSEO 之前，Paul 和我做過一個商業計畫產生器。

機會是真的：數以千計的查詢、競爭低、買家意圖也很明顯。

於是我們上線很快，發布也很快。

它從來沒排上去過，不是排得很慢，是從來沒有。

我們當時是全新網域，品牌搜尋是零，反向連結（backlinks）是零，發布速度看起來就像 Google 會歸到「大量產出」（generated at volume）底下的每一個網站。

→ 我們當時誰也不是，卻出現得很吵。

2024 年 3 月，Google 把「大規模內容濫用」（scaled content abuse）加進垃圾內容政策。無論內容是自動化、人工，還是兩者都有，都適用。

違規的不是數量。什麼都沒加上去的頁面才是。

更快的模型，只會讓你更便宜地重複這個錯誤，這正是為什麼你要先篩選。

2. 把 Fable 花在頁面上，不要花在整理資料（2. Spend Fable on the page, not on the sorting）

Fable 5.2 是昂貴的引擎，所以費力等級（effort level）是預算決定。

Medium 是 Claude Code 的預設。Anthropic 說，5.2 在 Medium 用掉的 token，比 5.1 更少。

在 Pro 和標準 Team 席次上，Fable 最多可佔你每週用量上限的 50%。如果把額度燒在整理關鍵字上，真正要寫的那一頁就沒剩了。

我自己會這樣拆工作：

  • Low：清理匯出檔、把關鍵字分組、重新命名欄位。
  • Medium：讀前三名的頁面，抽出大綱。
  • High：撰寫「oak coffee table」這一頁本身。
  • Xhigh：那一頁如果還出現在第四頁，你會覺得丟臉。

整理資料的工作，請開一個獨立工作階段，一開始就設成 Low：

指令（英文原文，可直接複製）

claude --model claude-fable-5-2 --effort low

中文說明

用 Fable 5.2、費力等級 Low 啟動一個工作階段

已經在一個工作階段裡了？輸入 /effort，選 Low，不用重開。

→ 同一個模型，用在不需要深度思考的工作上，成本只剩一小部分。

3. 一個關鍵字、一頁，而且要比前三名更好（3. One keyword, one page, better than the top 3）

最昂貴的錯誤，是去寫一頁你已經有的內容。

兩頁同時搶「oak coffee table」，會分散 Google 的注意力，結果兩頁都贏不了。

動筆之前，先做 Paul 會親手做的檢查：Search Console、效能（Performance）、用精確搜尋篩選，然後看「頁面」（Pages）分頁。如果已經有一頁出現了，你就去改它，而不是再寫一頁新的。

然後切到 High，根據已經排上去的結果來打造這一頁。

提示詞（prompt）（英文原文，可直接複製）

Using ChatSEO, pull the top 3 results for "oak coffee table" and read
their pages.

1. List every section all 3 have. My page needs each one.
2. List what only 1 of them has. Say if it is worth copying.
3. Find what none of them have that I could add, using only what I
   can really show (photos of the grain, real dimensions, a care
   guide, delivery times).
4. Write the outline: one H1 with the keyword, H2s, what goes in each.
5. Then write the page. Mark every fact you could not verify as
   [CHECK].

中文翻譯

用 ChatSEO，抓出「oak coffee table」的前 3 名結果，並讀他們的頁面。

1. 列出這 3 頁都有的每一個區塊。我的頁面每一個都要有。
2. 列出只有 1 頁才有的內容。說明值不值得抄。
3. 找出他們都沒有、但我可以補上的東西，而且只能用我真正拿得出來的
   （木紋照片、實際尺寸、保養指南、配送時間）。
4. 寫出大綱：一個帶關鍵字的 H1、各個 H2、每一段要放什麼。
5. 然後寫出這一頁。你無法核實的每一個事實，都標成 [CHECK]。

第 3 步才是整場比賽。一頁如果只是對齊前三名，就只是同一頁的第十個複製品，而 Google 已經有九個了。

Anthropic 說，5.2 比 5.1 表達得更清楚。這會讓草稿更好，但還不是完成品。

然後你要逐行改，連每一個 [CHECK] 都要改。頁面上掛的是你的名字，不是模型的名字。

4. 在 Google 看到之前，先檢查 Fable 寫了什麼（4. Check what Fable wrote before Google does）

多數排不上去的頁面，栽在一張清單本來就能抓到的問題上。

以「oak coffee table」這一頁為例，清單是：

  • Title tag。關鍵字靠近開頭，60 個字元以內，寫成讓人想點。
  • Meta description。一句話說讀者能得到什麼。
  • 一個 H1。帶關鍵字。只能有一個。
  • URL。短、帶關鍵字、不要日期。
  • 內部連結。至少有你的 2 個頁面連進來，錨點文字要能描述這一頁。
  • 圖片。有壓縮，alt 文字要說明圖裡是什麼。
  • 結構化資料（structured data）。用 Product，帶價格和庫存狀態。

把 Fable 對準上線後的 URL，跑這一段：

提示詞（prompt）（英文原文，可直接複製）

Read the HTML of [URL], my page targeting "oak coffee table".

Check it against this list and give me a pass/fail table:
title tag, meta description, single H1 with the keyword, URL,
internal links pointing in and out, image alt text, structured data.

For every fail, write the exact fix: the new title, the new meta,
the Product JSON-LD block ready to paste.

中文翻譯

讀取 [URL] 的 HTML，這是我針對「oak coffee table」的頁面。

對照這張清單，給我一張通過／失敗表：
title tag、meta description、唯一且帶關鍵字的 H1、URL、
連入和連出的內部連結、圖片 alt 文字、結構化資料。

每一項失敗，都寫出確切修法：新的 title、新的 meta、
可直接貼上的 Product JSON-LD 區塊。

JSON-LD 是模型真正值回票價的地方。沒有人會親手把結構化資料（structured data）寫第二次。

網站地圖（sitemap）的陷阱（The sitemap trap）

你的網站地圖（sitemap）告訴 Google 哪些頁面存在。

Paul 當時在測 ChatSEO 一個會讀網站 sitemap 的功能，它一直忽略他前一天才發布的頁面。頁面已經上線，但 sitemap 停更了。

沒有任何東西會警告你。每次發布之後，都要確認最新的頁面有寫進 sitemap。

5. 每個星期一，讓 Search Console 告訴 Fable 該修什麼（5. Every Monday, let Search Console tell Fable what to fix）

過了幾個星期，Google 會告訴你下一步該做什麼，只是多數人從來不問。

找平均排名（average position）在 5 到 15 之間的搜尋。Google 已經覺得你相關，所以你只差一次好的修改，就能上到第一頁。

提示詞（prompt）（英文原文，可直接複製）

Using ChatSEO, look at my Search Console for the last 28 days.

1. List the searches where my average position is between 5 and 15,
   with clicks, impressions and the page that ranks.
2. Group them by page.
3. For the 3 pages with the most impressions, tell me what to add or
   change so the page answers those searches better.
4. Skip any page I edited in the last 60 days. Google hasn't
   re-read it yet.

中文翻譯

用 ChatSEO，查看我過去 28 天的 Search Console。

1. 列出平均排名在 5 到 15 之間的搜尋，
   附上點擊、曝光次數，以及排名的是哪一頁。
2. 依頁面分組。
3. 針對曝光次數最多的 3 頁，告訴我該新增或修改什麼，
   才能讓頁面更好地回應這些搜尋。
4. 略過我在過去 60 天內改過的任何一頁。Google 還沒
   重新讀過它。

用 Medium 跑。這是在讀，不是在寫。

每週一小時。整條迴圈就是這樣。

以下為譯者整理，非原文內容。

這篇在說什麼

Fable 5.2 剛推出，大家都會拿去測寫程式；作者認為真正能賺錢的，是把它對準自己的 Search Console。

方法並不炫：用真實搜尋資料，挑出會成交的關鍵字，認真寫一頁贏過前三名的內容，再每週花一小時，修正最接近第一頁的頁面。模型是手，資料工具是腦，你是最後點頭的老闆。

為什麼值得學

這不是一篇「新模型有多強」的發表文，而是一套今晚就能做的順序。作者也很坦白：文中沒有任何 5.2 的排名成果，基準數字來自 Anthropic，而他們自己還有品牌優勢。值得帶走的，是那套順序，以及「先篩、少寫、寫完要改、每週再看數字」這個態度。

你可以帶走的重點

1. 錢在 Search Console，不在拿新模型寫程式

新模型一出，多數人會先拿它測寫程式。作者要說的是：把它對準你自己網站的搜尋數據，才是真的能帶來生意的地方。從一個會成交的關鍵字，寫到 Google 有理由讓它排名的一頁，每一步都有提示詞（prompt）。

全文例子是家具店要搶「oak coffee table」（橡木咖啡桌）。換成你自己的產品，這套順序一樣用得上。

2. 模型不知道你的點擊（click）和搜尋量，不接真實資料就是在猜

Fable 5.2 不會自己知道每個月有多少人在搜、你現在排第幾、今天的搜尋結果長什麼樣。你若直接問它，它只能用訓練資料回答，後面蓋上去的東西都是猜測。

所以要先更新 Claude Code（2.1.321 起才認得這個模型），再把 ChatSEO 的 MCP 接上，讓提示詞（prompt）吃的是 Search Console、搜尋量和即時結果，而不是記憶。

3. 動筆前先過兩道篩選：會成交，而且現在打得過

更好的模型寫錯關鍵字，只會讓你更快得到零。「什麼是咖啡桌」會帶來訪客，但那些人並不在買；「橡木咖啡桌」才是已經把卡拿在手上的人。

判斷意圖不必靠工具：搜看看誰排在前面。產品頁、帶價格的分類頁是交易型（commercial），留下；部落格和定義框是資訊型（informational），先跳過。第二道更狠：以你現在的規模，前 10 名裡有沒有跟你差不多的網站？全是大品牌，就標成以後再做。

提示詞（prompt）裡的第 4 條最常被跳過：搜尋量只能用工具回傳的數字，模型自己估的，就是在猜。

4. 大量產出（generated at volume）、卻沒加上新東西的頁面，會永遠排不上去

作者和 Paul 在做 ChatSEO 之前，做過商業計畫產生器。查詢多、競爭低、意圖也明顯，他們上線很快、發布也很快，結果從來沒排上去過。當時是全新網域，沒有品牌搜尋，也沒有反向連結（backlinks），發布速度看起來就像 Google 會歸到「大量產出（generated at volume）」的網站。

2024 年 3 月，Google 把「大規模內容濫用（scaled content abuse）」寫進垃圾內容政策，不管內容是機器寫的、人寫的，還是兩者都有。違規的不是數量，而是什麼都沒加上去的頁面。更快的模型，只是讓你更便宜地重複這個錯誤。

5. 費力等級（effort level）是預算，別把高檔燒在整理資料上

在 Pro 和標準 Team 席次上，Fable 最多可佔每週用量的一半。Medium 是 Claude Code 的預設，5.2 在這個等級用的 token 比 5.1 少。作者的拆法是：清理和分組用 Low，讀前三名、寫大綱用 Medium，真正寫那一頁才用 High；非贏不可的那一頁，才上 Xhigh。

整理資料請另開工作階段，一開始就設 Low；若已在對話裡，輸入 /effort 切過去就好，不用重開。

6. 一個關鍵字只寫一頁，而且要比前三名更好

最昂貴的錯誤，是再寫一頁你已經有的內容。兩頁搶同一個關鍵字，會分散 Google 的注意力，結果兩頁都贏不了。動筆前先在 Search Console 用精確搜尋檢查：已經有頁了，就去改它。

寫的時候要讀前三名：他們都有的區塊你也要有；只有一家有的，對買家有幫助才抄；大家都沒有、而你拿得出來的，才是優勢，例如木紋照片、實際尺寸、保養指南、配送時間。模型寫得再清楚，也只是更好的草稿。每一行、每一個 [CHECK]，都要你自己改。頁上掛的是你的名字。

7. 上線前用清單檢查，也別忘了網站地圖（sitemap）

多數排不上去的頁面，栽在一張清單就能抓到的問題：title、meta、只能有一個且帶關鍵字的 H1、短網址、至少兩條描述清楚的內部連結、壓過的圖和 alt、以及帶價格和庫存的 Product 結構化資料（structured data）。JSON-LD 特別適合交給模型寫，因為很少有人願意親手寫第二次。

還有一個常被忽略的陷阱：頁面已經上線，sitemap 卻停更了，Google 就當它不存在。每次發布後，都要確認最新那頁有寫進去。

8. 每個星期一花一小時，修最接近第一頁的那幾頁

過了幾個星期，Google 其實已經告訴你下一步該做什麼。找平均排名（average position）在 5 到 15 的搜尋：它已經覺得你相關，你只差一次好的修改。依頁面分組後，先改曝光（impressions）最多的三頁，並略過 60 天內才改過的頁面，因為 Google 可能還沒重新讀過。

這段用 Medium 就夠了，因為是在讀，不是在寫。整條迴圈，就是每週一小時。

怎麼開始

作者說，今晚就會照下面這個順序做。每一步都得先有前一步，才會有效。

  1. 執行 claude update，再用 High 啟動 Fable 5.2。
  2. 建立 ChatSEO 帳號、加入網站、連接 Search Console，並把 MCP 加進 Claude Code，讓答案來自真實資料。
  3. 挑 10 個關鍵字：買家已經把卡拿在手上，而且前 10 名不全是大品牌。搜尋量只用工具回傳的數字。
  4. 先確認 Search Console 裡沒有現成的頁。用 High 寫一頁，要比前三名更好，並逐行修改每一個 [CHECK]。
  5. 跑頁面內檢查，再確認 sitemap 裡有這頁。
  6. 之後每個星期一，用 Medium 修正最接近第一頁的 3 個頁面。

先更新，再挑會賺錢的，把力氣花在一頁上，檢查它，然後每個星期一再重複。

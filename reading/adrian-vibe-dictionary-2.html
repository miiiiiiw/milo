上篇解決了四個問題：

  • 頁面布局 Layout：頁面上的內容怎麼排。
  • 頁面結構 Page Structure：使用者先看到什麼，接著看到什麼。
  • 導覽 Navigation：使用者如何移動、跳轉和切換。
  • 元件 UI Components：使用者如何點選、展開和輸入。

下篇繼續解決另外四個問題：

  • 捲動與動作 Scroll & Motion：內容如何出現，頁面如何建立節奏。
  • 提示與載入 Feedback & Loading：等待、成功、失敗和空白狀態如何回饋。
  • 視覺風格 Visual Styles：網頁整體看起來屬於哪一種設計語言。
  • 高級效果與體驗 Advanced Effects & Quality：如何使用 3D、過渡和高級互動，同時兼顧效能與無障礙性。

每個詞條只保留三部分：概念說明、適用情境，以及可以直接複製給 AI 的提示詞。

第五章：捲動與動作 Scroll & Motion

捲動與動作決定頁面如何「活起來」。它回答的是：內容何時出現、使用者捲動時會發生什麼，以及頁面怎樣在不打斷閱讀的前提下建立節奏。

41. 捲動出現 Scroll Reveal

元素在進入視口時逐漸出現，常見變化包括淡入、輕微上移或縮放。它的作用是建立閱讀節奏，而不是讓每個元素都表演一次。

適合：長頁面、個人介紹、專案案例、資料區塊、章節過渡。

提示詞（可直接複製給 AI）

為 Punk 的個人網站新增 Scroll Reveal。
標題、正文、專案卡片進入視口時淡入並向上移動 16px，動畫時長控制在 400—600ms；
同一組卡片使用輕微交錯，不要讓整頁所有元素同時動畫；
使用者啟用 prefers-reduced-motion 時取消位移動畫，只保留即時顯示或輕微淡入。

42. 視差捲動 Parallax

前景、中景和背景以不同速度移動，製造空間深度。效果越大越容易干擾閱讀，因此適合用在局部視覺，而不是整頁持續晃動。

適合：Hero、品牌故事、作品封面、沉浸式章節、視覺型個人網站。

提示詞（可直接複製給 AI）

為 Punk 的首頁 Hero 新增輕量 Parallax。
背景抽象山形移動速度最慢，中層半透明網頁面板使用中等速度，前景標題保持接近正常捲動速度；
移動距離控制在較小範圍，禁止大幅縮放和快速位移；
行動版降低效果，reduced motion 模式下完全關閉視差。

43. 閱讀進度條 Scroll Progress Indicator

根據頁面捲動位置顯示閱讀進度，常見形式是頂部細線、側邊刻度或圓形百分比。它告訴使用者還剩多少內容。

適合：推特長文頁、部落格、案例研究、教程、文件。

提示詞（可直接複製給 AI）

在 Punk 的長篇文章頁頂部新增 Scroll Progress Indicator。
使用 3px 深綠色進度線，從左向右反映當前閱讀百分比；
導覽列保持 Sticky，進度條位於導覽底部；不要遮擋內容，並使用 requestAnimationFrame 或 CSS Scroll-driven Animation 實作平滑更新。

44. 捲動吸附 Scroll Snap

使用者捲動後，內容會自動停在預設位置，像翻頁一樣對齊到某一張卡片或某一個完整章節。

適合：橫向作品集、全螢幕章節、行動版卡片瀏覽、產品故事。

提示詞（可直接複製給 AI）

為 Punk 的精選作品區新增 CSS Scroll Snap。
橫向容器使用 scroll-snap-type: x mandatory，每個專案卡片使用 scroll-snap-align: center；
允許觸控滑動和觸控板捲動，保留自然慣性；
不要劫持整個頁面捲動，桌面版同時提供上一項和下一項按鈕。

45. 橫向捲動 Horizontal Scroll

內容沿水平方向瀏覽，可以顯示一排專案、時間軸或視覺畫廊。它應當有明確的方向提示，否則使用者容易不知道還能繼續滑動。

適合：專案畫廊、時間軸、客戶 Logo、行動版作品瀏覽、橫向敘事。

提示詞（可直接複製給 AI）

為 Punk 的專案檔案建立 Horizontal Scroll。
桌面版展示 3.5 張卡片，讓下一張卡片露出一部分作為繼續瀏覽提示；
支援觸控板和觸控滑動，並提供左右箭頭；
卡片保持鍵盤可聚焦，手機版使用自然橫向捲動。

46. 無限捲動 Infinite Scroll

使用者接近列表底部時自動載入下一批內容，不需要手動翻頁。它適合連續消費內容，但不適合需要精確定位和返回某一頁的任務。

適合：動態內容流、靈感牆、AI 圖片庫、社交列表、探索頁。

提示詞（可直接複製給 AI）

為 Punk 的 AI 靈感流實作 Infinite Scroll。
每次載入 12 個專案，在列表底部設定 sentinel，並使用 IntersectionObserver 在 sentinel 接近視口時請求下一頁；
載入期間顯示 Skeleton；載入失敗時顯示 Retry 按鈕；
儲存捲動位置，避免返回頁面時遺失當前位置。

47. 跑馬燈 Marquee

文字、Logo 或標籤持續橫向移動，形成動態資訊帶。現代網頁通常使用 CSS 動畫實作，而不是舊式 marquee 標籤。

適合：客戶 Logo、技能列表、活動資訊、品牌口號、作品標籤。

提示詞（可直接複製給 AI）

在 Punk 首頁的 Hero 下方新增一個循環 Marquee，內容為 Design、Frontend、AI Prototyping、Writing、Creative Tools；
兩組內容無縫銜接，移動速度緩慢；滑鼠懸停時暫停；
內容必須在動畫關閉時仍可閱讀，reduced motion 模式下改為普通換行標籤列表。

48. 懸停微互動 Hover Micro-interaction

滑鼠經過按鈕、連結或卡片時發生細小變化，例如上移、邊框加深、箭頭移動或圖片輕微放大。微互動用於確認「這個東西可以點」。

適合：專案卡片、按鈕、連結、導覽項目、圖片畫廊。

提示詞（可直接複製給 AI）

為 Punk 的專案卡片新增 Hover Micro-interaction。
滑鼠進入時卡片上移 4px，邊框由淺灰變為深綠色，封面圖輕微放大到 1.03，右下角箭頭向右移動 4px；
動畫使用 180—240ms ease-out；
鍵盤 focus-visible 狀態提供同等清晰回饋，不要只依賴 hover。

49. 交錯動畫 Staggered Animation

同一組元素不是同時出現，而是按很短的間隔依次進入。它能強化順序和節奏，但間隔過長會讓頁面顯得遲鈍。

適合：卡片網格、選單項、資料列表、Logo 牆、功能模組。

提示詞（可直接複製給 AI）

為 Punk 的四張能力卡片新增 Staggered Entrance。
第一張進入視口後開始動畫，其餘卡片每隔 70ms 依次淡入並上移 12px；總等待時間不要超過 300ms；
重複捲動時不要反覆播放；reduced motion 模式下讓所有卡片直接顯示。

50. 捲動驅動動畫 Scroll-driven Animation

動畫進度由捲動位置決定，而不是由固定時間決定。例如捲動到章節中段時，進度線正好走到一半。

適合：進度圖、產品拆解、數字敘事、背景變化、章節動畫。

提示詞（可直接複製給 AI）

在 Punk 的專案案例頁使用 Scroll-driven Animation。
捲動經過 Process 章節時，左側進度線隨章節閱讀進度增長，右側三個原型面板依次從低透明度變為完全可見；
優先使用 CSS animation-timeline 和 view()，為不支援的瀏覽器提供 IntersectionObserver 降級方案，並尊重 reduced motion。

第六章：提示與載入 Feedback & Loading

提示與載入決定使用者等待時看到什麼、出錯時怎麼辦、操作完成後如何確認。它回答的是：系統現在處於什麼狀態，以及使用者下一步應該做什麼。

51. 骨架屏 Skeleton Screen

真實內容載入前，先顯示與最終布局相似的灰色佔位結構。它不能讓網路變快，但能減少頁面突然跳動和空白等待感。

適合：專案卡片、文章列表、Dashboard、詳情頁、圖片畫廊。

提示詞（可直接複製給 AI）

為 Punk 的專案列表設計 Skeleton Screen。
骨架結構必須與最終卡片尺寸一致，包含封面佔位、標題線、兩行文字和標籤佔位；
使用低對比度灰綠色，不要顯示虛假文字；
內容載入完成後使用短暫淡入替換，避免布局位移。

52. 懶載入 Lazy Loading

首屏之外的圖片、影片或模組在接近視口時才載入，減少初始頁面需要下載的資源。

適合：長頁面、圖片庫、作品集、嵌入影片、文章推薦區。

提示詞（可直接複製給 AI）

為 Punk 的作品集實作 Lazy Loading。
首屏 Hero 圖片正常載入，不要設定 lazy；
首屏以下的 img 和 iframe 使用 loading="lazy"；為圖片預先設定 width、height 或 aspect-ratio，避免布局跳動；
重要專案封面提供合適的 srcset 和 sizes，不要把所有資源都延遲載入。

53. 載入轉圈 Loading Spinner

用循環旋轉圖示表示系統正在處理，但不說明還需要多久。它只適合等待時間短、進度不可預測的任務。

適合：短請求、局部重新整理、按鈕處理、圖片生成準備階段。

提示詞（可直接複製給 AI）

Punk 網站提交短請求時顯示 Loading Spinner。
Spinner 只出現在正在更新的局部區域，不要遮罩整個頁面；
同時顯示「正在載入專案」文字；
超過 8 秒後追加更明確的等待說明和取消入口；
動畫在 reduced motion 模式下改為靜態狀態圖示。

54. 進度條 Progress Bar

顯示任務已經完成多少，適合能夠計算進度的上傳、生成或多步驟任務。確定型進度條比不斷轉圈更能建立預期。

適合：檔案上傳、AI 生成、匯出、資料同步、安裝流程。

提示詞（可直接複製給 AI）

為 Punk 的 AI 圖片匯出任務新增 Determinate Progress Bar。顯示 0—100% 進度、當前階段名稱和取消按鈕；
進度條只向前移動，不要偽造倒退；
完成後切換為 Success State，失敗後保留當前進度並顯示 Retry；使用 role="progressbar" 提供無障礙狀態。

55. 載入按鈕 Loading Button

使用者點選提交後，按鈕進入處理中狀態，通常停用重複點選，並把原文字替換為載入圖示和狀態說明。

適合：儲存、發布、登入、生成、上傳、表單提交。

提示詞（可直接複製給 AI）

Punk 的聯絡表單點選 Send Message 後，把按鈕切換為 Loading Button：停用重複提交，文字改為「Sending…」並顯示小型 Spinner；
保持按鈕寬度不變，避免介面跳動；
請求成功後顯示「Sent」，失敗後恢復可點選狀態並顯示錯誤原因。

56. 空狀態 Empty State

列表或頁面沒有內容時的正式介面，而不是一片空白。好的空狀態會解釋為什麼為空，並給出下一步行動。

適合：新使用者後台、搜尋無結果、收藏夾、專案列表、通知中心。

提示詞（可直接複製給 AI）

為 Punk 的新專案頁面設計 Empty State。
中心顯示一個簡潔抽象圖形、標題「還沒有專案」、一句說明和「建立第一個專案」按鈕；
如果是篩選導致無結果，改為「沒有符合的專案」，並提供清除篩選按鈕；不要使用消極或責備使用者的文案。

57. 錯誤狀態 Error State

任務失敗後明確告訴使用者發生了什麼、哪些內容受到影響，以及是否需要重新操作。錯誤狀態不應只有紅色或一個錯誤代碼。

適合：表單失敗、載入失敗、權限問題、斷網、404 與 500 頁面。

提示詞（可直接複製給 AI）

為 Punk 的專案載入失敗設計 Error State。
顯示清晰標題「專案暫時無法載入」、簡短原因、Retry 按鈕和返回專案列表連結；保留已經載入的其他內容，不要清空整個頁面；
錯誤資訊使用圖示、文字和顏色共同表達，並透過 role="alert" 或合適的 live region 通知輔助技術。

58. 重試狀態 Retry State

錯誤發生後提供重新執行操作的入口，並在重試過程中顯示新的載入狀態。它是錯誤恢復流程，而不僅是一顆按鈕。

適合：網路請求、圖片上傳、AI 生成、同步任務、列表載入。

提示詞（可直接複製給 AI）

Punk 的圖片上傳失敗後顯示 Retry State。
保留失敗檔案的縮圖和檔名，標出「上傳失敗」，提供 Retry 和 Remove 兩個操作；
點選 Retry 後只重新上傳該檔案，並切換為進度狀態；
成功後替換為完成狀態，不要要求使用者重新選擇所有檔案。

59. 樂觀更新 Optimistic UI

使用者操作後，介面先假設操作會成功並立即更新，再在後台傳送請求。失敗時需要復原變更並說明原因。

適合：點贊、收藏、簡單狀態切換、排序、輕量編輯。

提示詞（可直接複製給 AI）

Punk 的專案收藏按鈕使用 Optimistic UI。
點選後立刻把圖示切換為已收藏並更新計數，同時後台傳送請求；
請求失敗時恢復原狀態，顯示非阻塞錯誤提示並提供重試；
不要把支付、刪除帳號等不可逆或高風險操作做成樂觀更新。

60. 行內驗證 Inline Validation

使用者輸入時或離開欄位後，在輸入框附近顯示具體錯誤，而不是提交後只在頁面頂部說「表單有問題」。

適合：註冊、聯絡表單、支付、設定、搜尋條件。

提示詞（可直接複製給 AI）

為 Punk 的 Contact Form 新增 Inline Validation。
電子郵件欄位在 blur 後檢查格式，錯誤資訊顯示在輸入框下方並說明如何修正；輸入正確後顯示簡潔確認狀態；
不要在使用者輸入第一個字元時立刻報錯；提交失敗時把焦點移動到第一個錯誤欄位，並在頂部提供錯誤摘要。

第七章：視覺風格 Visual Styles

視覺風格決定頁面給人的第一印象。它回答的是：頁面看起來克制還是張揚、像雜誌還是像工具、是輕盈通透還是厚重直接。風格必須服務內容，而不是把所有流行效果堆在一起。

61. 極簡主義 Minimalism

減少非必要顏色、裝飾和元件，透過留白、字型層級和少量重點內容建立秩序。極簡不等於什麼都沒有，而是每個元素都有理由存在。

適合：個人首頁、設計師作品集、產品介紹、寫作網站、高級品牌。

提示詞（可直接複製給 AI）

為 Punk 設計一個 Minimalist Portfolio。
使用米白背景、黑色正文和單一深綠色強調色，限制字型、圓角和陰影種類；首頁只保留姓名、身份、精選專案和聯絡入口；
透過大留白和清晰排版建立層級，不要加入多餘漸層、發光效果或裝飾圖示。

62. 編輯雜誌風 Editorial Design

借鑑雜誌和出版物的排版方式，強調大標題、圖文比例、版塊節奏、頁碼和引語。

適合：個人品牌、文章站、攝影集、案例研究、文化內容。

提示詞（可直接複製給 AI）

為 Punk 的 Journal 設計 Editorial Layout。
使用超大文章標題、窄正文欄、跨欄圖片、章節編號、首字下沉和 pull quote；正文保持舒適行長和行高；
不要把每段內容都放進卡片，讓頁面更接近現代獨立雜誌。

63. 瑞士風 Swiss Style

強調網格、無襯線字型、客觀排版、清晰對齊和有限顏色。它通常看起來理性、精確、系統化。

適合：設計工作室、建築網站、作品目錄、品牌系統、活動海報頁。

提示詞（可直接複製給 AI）

為 Punk 的作品索引使用 Swiss Style。
採用嚴格的 12 欄網格、左對齊無襯線字型、明顯編號和細分隔線；
顏色僅使用米白、黑和深綠色；
專案資訊按年份、類別和角色對齊排列，避免裝飾性手寫字型與複雜陰影。

64. 玻璃擬態 Glassmorphism

使用半透明面板、背景模糊、細邊框和層疊關係，營造玻璃浮動感。玻璃面板必須有足夠對比度，不能讓文字融進背景。

適合：AI 產品、科技首頁、資料面板、空間化 Hero、控制中心。

提示詞（可直接複製給 AI）

為 Punk 的 AI 工具首頁新增克制的 Glassmorphism。
深綠色抽象背景上疊加兩到三層半透明面板，使用 backdrop-filter: blur(16px)、低透明白色背景和細亮邊框；
正文區域保持高對比度，不要讓所有卡片都透明，也不要使用過度霓虹發光。

65. 新野獸派 Neo-brutalism

使用粗邊框、高對比配色、直接排版和明顯陰影，保留原始感，但比早期網頁野獸派更系統、更適合產品介面。

適合：創作者網站、實驗產品、活動頁、年輕品牌、獨立工具。

提示詞（可直接複製給 AI）

為 Punk 的實驗專案頁使用 Neo-brutalist Style。
採用粗黑邊框、硬陰影、大字級標題和深綠色重點按鈕；
元件保持清晰網格與可讀性

66. 深色模式 Dark Mode

使用深色背景與淺色文字，降低暗環境中的強光感。它不是簡單把黑白反轉，而是要重新調整對比度、陰影、邊框和圖片。

適合：開發者工具、創作後台、媒體產品、夜間閱讀、AI 應用。

提示詞（可直接複製給 AI）

為 Punk 網站實作完整 Dark Mode。使用 prefers-color-scheme 讀取系統偏好，並提供手動切換和本機儲存；
深色背景避免純黑，正文使用柔和淺灰，深綠色調整為更亮的可見色；表單、捲軸和原生控制項同步 color-scheme；
檢查兩種模式下的對比度和圖片表現。

67. 單色與雙色 Monochrome / Duotone

用一種主色或兩種顏色控制整個視覺系統，透過明度、面積和材質變化建立層次。

適合：品牌主頁、攝影網站、作品目錄、專題頁、極簡產品。

提示詞（可直接複製給 AI）

為 Punk 的個人網站使用 Monochrome + Duotone 視覺系統。
全站以米白、黑和深綠色構成，專案圖片轉換為低飽和綠色雙色調，
滑鼠懸停後恢復少量原色；保證文字、邊框和按鈕層級清楚，不要讓所有元素使用相同深淺。

68. 網格漸層 Gradient Mesh

多個柔和色塊在頁面中交融，形成具有空間感的抽象背景。它比普通線性漸層更自然，但容易搶走正文注意力。

適合：Hero 背景、AI 產品、活動頁、抽象個人品牌、登入頁。

提示詞（可直接複製給 AI）

為 Punk 首頁 Hero 建立低飽和 Gradient Mesh 背景。
使用米白、灰綠和深綠色的柔和色團，邊緣模糊並緩慢漂移；
文字區域保持相對平靜，確保標題對比度；動畫幅度很小，行動版使用靜態背景，reduced motion 模式下關閉漂移動畫。

69. 顆粒與噪點 Grain / Noise Texture

在純色或漸層上疊加細小顆粒，減少數位畫面的塑膠感，增加印刷、底片或紙張質感。

適合：編輯設計、品牌網站、抽象背景、海報式 Hero、作品封面。

提示詞（可直接複製給 AI）

在 Punk 網站的米白背景和深綠色 Hero 上新增非常輕的 Grain Texture。
噪點透明度保持低，使用可重複的小型紋理或 CSS/SVG filter，不影響文字清晰度；不要給表單和正文區域增加明顯顆粒；
行動版控制紋理資源大小，避免使用超大背景圖片。

70. 新擬態 Neumorphism / Soft UI

透過同色系的亮暗陰影，讓按鈕和面板像從背景中凸起或凹下。它視覺柔和，但邊界和無障礙性容易不足。

適合：小型控制元件、播放器、實驗介面、展示型儀表板。

提示詞（可直接複製給 AI）

為 Punk 的實驗性音樂控制器使用局部 Neumorphism。
僅對播放、音量和模式按鈕使用同色亮暗陰影，保留清晰文字、圖示和 focus outline；
主要導覽、表單與長文字不要使用新擬態；按下狀態需要透過陰影、位置和顏色共同表達。

第八章：高級效果與體驗 Advanced Effects & Quality

高級效果不等於更複雜。真正成熟的網頁會同時考慮表現力、無障礙性、相容性和效能。它回答的是：哪些效果值得做，以及怎樣避免效果反過來傷害體驗。

71. 自訂游標 Custom Cursor

用自訂圓點、文字或預覽替代或補充系統游標，常用於展示當前可執行動作，例如 View、Drag 或 Open。

適合：創意作品集、圖片畫廊、實驗網站、拖拽區域。

提示詞（可直接複製給 AI）

為 Punk 的桌面作品畫廊新增 Custom Cursor。
預設顯示小型綠色圓點，懸停專案圖片時擴充並顯示「View」，進入橫向畫廊時顯示「Drag」；
保留原生游標作為可用後備，觸控螢幕裝置不啟用；不要讓自訂游標產生明顯延遲，也不要遮擋表單與正文。

72. 磁吸按鈕 Magnetic Button

滑鼠靠近按鈕時，按鈕或內部文字輕微朝游標方向移動，形成被吸引的感覺。

適合：主要 CTA、作品入口、聯絡按鈕、創意首頁。

提示詞（可直接複製給 AI）

為 Punk 首頁的 View Work 按鈕新增輕量 Magnetic Effect。
只有當游標距離按鈕較近時，按鈕內容最多偏移 6px，滑鼠離開後快速回到原位；按鈕本身不能逃離點選區域；
觸控螢幕和 reduced motion 模式下關閉磁吸，只保留普通 hover 狀態。

73. 三維傾斜卡片 3D Tilt Card

卡片根據游標位置輕微旋轉，並改變內部層次或高光，形成具有深度的立體回饋。

適合：精選專案、產品卡片、收藏卡、視覺作品、實驗性主頁。

提示詞（可直接複製給 AI）

為 Punk 的 Featured Project 卡片新增 3D Tilt。
游標移動時 rotateX 和 rotateY 最大不超過 5deg，封面、文字和高光使用很小的 Z 軸層次；滑鼠離開後平滑歸位；
行動版和 reduced motion 模式關閉傾斜，卡片點選區域保持穩定。

74. 聚光燈懸停 Spotlight Hover

游標經過大卡片或網格時，局部出現柔和光斑，突出當前區域並弱化周圍內容。

適合：Dashboard、深色介面、功能網格、專案卡片、定價表。

提示詞（可直接複製給 AI）

在 Punk 的深色功能網格上新增 Spotlight Hover。
使用滑鼠位置控制徑向漸層，光斑範圍只覆蓋當前卡片附近，亮度克制；
焦點進入卡片時提供靜態高亮替代；不要使用持續追蹤的強烈發光，也不要降低文字對比度。

75. 圖片與文字遮罩 Image / Text Mask

讓圖片或動態紋理只顯示在文字、圓形或自訂形狀內部，製造強烈但可控的視覺焦點。

適合：Hero 大標題、專案封面、章節數字、品牌標語。

提示詞（可直接複製給 AI）

為 Punk 首頁標題「MAKE IDEAS VISIBLE」新增 Text Mask，低飽和抽象動畫只顯示在文字內部；
在不支援 background-clip: text 的環境中回退為深綠色實心文字；
標題必須保持可選擇、可讀和語義化，不要把重要文字只做成圖片。

76. 裁切揭示 Clip-path Reveal

元素透過圓形、矩形或多邊形裁切區域逐漸展開，像幕布被拉開一樣展示圖片或頁面。

適合：專案切換、圖片入場、章節過渡、按鈕預覽、全螢幕選單。

提示詞（可直接複製給 AI）

為 Punk 的專案封面新增 Clip-path Reveal。
圖片進入視口時從 inset(0 100% 0 0) 過渡到完整顯示，持續 500ms；
動畫只播放一次；為不支援或 reduced motion 使用者直接顯示完整圖片；不要同時疊加大幅位移和縮放。

77. WebGL / Three.js Hero

使用 GPU 渲染即時 3D、粒子、材質或互動情境，可以創造普通 CSS 難以實作的空間視覺。

適合：科技產品、AI 品牌、實驗作品集、資料藝術、互動敘事。

提示詞（可直接複製給 AI）

為 Punk 的首頁製作一個輕量 Three.js Hero。
情境包含一個低多邊形抽象球體和三層半透明介面平面，跟隨滑鼠產生非常輕微視差；限制幾何體數量、紋理尺寸和像素比；
頁面隱藏時暫停渲染；行動版使用簡化情境，低效能或 WebGL 不可用時顯示靜態海報圖。

78. 檢視轉場 View Transitions

頁面或介面狀態切換時，讓舊內容與新內容平滑銜接，例如專案卡片自然放大為詳情頁封面。

適合：專案列表到詳情頁、SPA 狀態切換、多頁網站導覽、圖片畫廊。

提示詞（可直接複製給 AI）

Punk 的專案卡片點選後使用 View Transition 進入詳情頁。
卡片封面與詳情頁 Hero 共享 view-transition-name，讓圖片從卡片位置自然擴充；過渡控制在 300—450ms；瀏覽器不支援時正常導覽；
不要讓過渡影響焦點、閱讀位置或返回按鈕行為，並在 reduced motion 下跳過動畫。

79. 減少動態 Reduced Motion

當使用者系統開啟「減少動態效果」時，網站降低或移除非必要位移、縮放、視差和自動播放，保留功能與資訊回饋。

適合：所有包含動畫、捲動態效果果、視差或 3D 的網頁。

提示詞（可直接複製給 AI）

為 Punk 網站完整支援 prefers-reduced-motion: reduce。
關閉 Parallax、磁吸按鈕、3D Tilt、自動 Marquee 和大範圍頁面過渡；
Scroll Reveal 改為直接顯示或短淡入；Carousel 停止自動播放；所有功能仍可操作，不能因為關閉動畫而隱藏內容或遺失狀態回饋。

80. 效能預算 Performance Budget

在開發前為腳本、圖片、字型、請求數量和關鍵效能指標設定上限，避免視覺效果無限增加導致網站越來越慢。

適合：圖片型作品集、動畫網站、AI 產品、行銷頁、WebGL 專案。

提示詞（可直接複製給 AI）

為 Punk 的個人網站制定 Performance Budget：
行動版首屏 JavaScript 儘量控制在 170KB gzip 以內，首屏關鍵圖片使用現代格式並嚴格壓縮，WebGL 情境延遲到需要時載入，字型不超過兩個家族和必要字重；
在 CI 中執行 Lighthouse 或等價檢查，超過預算時提示優化，不要為了動畫犧牲核心內容載入。

一段可以直接複製的完整提示詞

完整提示詞（可直接複製給 AI）

請為 Punk 設計並實作一個響應式個人作品網站的體驗增強版本。

注意：Punk 是人物姓名和網站署名，不是朋克文化或朋克視覺風格。不要自動使用皮衣、莫霍克髮型、塗鴉、鉚釘或反叛海報元素。

【捲動與動作】
首頁和專案案例使用輕量 Scroll Reveal，元素進入視口時淡入並向上移動 16px。
精選專案區使用 Horizontal Scroll 與 CSS Scroll Snap。
長篇文章頂部顯示 Scroll Progress Indicator。
AI 靈感流使用 Infinite Scroll，並透過 IntersectionObserver 在接近底部時載入下一批內容。
技能標籤使用緩慢 Marquee，但 reduced motion 模式下改為靜態標籤。
卡片 hover 只使用輕微上移、邊框變化和箭頭移動。
所有捲動動畫都必須支援 prefers-reduced-motion。

【提示與載入】
專案列表載入前顯示與最終布局一致的 Skeleton Screen。
首屏以下圖片和 iframe 使用 Lazy Loading，並預設尺寸避免布局跳動。
短任務使用局部 Spinner，可計算進度的任務使用 Progress Bar。
提交按鈕進入 Loading Button 狀態，防止重複提交。
專案為空時顯示 Empty State，並提供建立專案按鈕。
載入失敗時顯示 Error State 和 Retry 操作。
收藏等低風險操作可以使用 Optimistic UI。
表單使用 Inline Validation，並透過合適的 live region 通知狀態變化。

【視覺風格】
整體採用 Minimalism 與 Editorial Design 的組合。
米白背景、黑色正文、深綠色強調，嚴格控制顏色數量。
使用清晰網格、大標題、編號、跨欄圖片和充足留白。
Hero 可以局部使用克制 Glassmorphism 和低飽和 Gradient Mesh。
背景可以加入極輕的 Grain Texture。
不要把所有元素都做成透明玻璃卡片，也不要使用家居產品擺拍。

【高級效果】
桌面版作品畫廊可以使用 Custom Cursor，但觸控螢幕裝置保持原生互動。
主要 CTA 可以使用輕量 Magnetic Button。
精選專案卡片可以使用最大 5deg 的 3D Tilt。
圖片進入視口時可以使用一次性的 Clip-path Reveal。
首頁允許使用輕量 Three.js 抽象情境，但必須提供靜態回退圖。
專案卡片到詳情頁使用 View Transitions，並為不支援瀏覽器正常降級。
完整支援 prefers-reduced-motion。
制定效能預算，限制腳本、字型、圖片和 WebGL 資源，不要為了視覺效果犧牲首屏載入和無障礙性。

【技術要求】
使用語義化 HTML、現代 CSS 和少量必要 JavaScript。
優先使用 CSS Scroll Snap、CSS Scroll-driven Animations、IntersectionObserver、原生 lazy loading 和 View Transition API。
所有互動支援鍵盤操作、清晰焦點狀態和螢幕閱讀器。
動畫不能隱藏重要內容，也不能成為完成任務的必要條件。

這篇在說什麼

這是《Vibe Coding 視覺詞典》的下篇。上篇的 40 個詞處理「網頁長什麼樣、怎麼移動」；下篇再補 40 個詞（第 41 到 80 條），處理「網頁怎麼動、怎麼回應、看起來像什麼風格，以及做特效時怎麼不出事」。每個詞一樣附說明、適用情境和可直接複製給 AI 的提示詞。

四章分別是：捲動與動作（內容怎麼出現）、提示與載入（等待、成功、失敗時使用者看到什麼）、視覺風格（整體設計語言）、高級效果與體驗（3D、轉場等特效，以及效能和無障礙）。

為什麼值得學

上篇讓 AI 做出「對的版面」，下篇讓網頁「用起來舒服」。很多 AI 做的網頁看起來沒問題，一用就露餡：按了送出沒反應、載入時一片空白、出錯只跳一行紅字、動畫多到頭暈。這些都是下篇的詞彙在處理的事。

作者的提示詞也示範了一種成熟的態度：每加一個特效，幾乎都同時寫出「什麼情況要關掉它」。

你可以帶走的重點

1. 動畫是為了節奏，不是表演

捲動出現（Scroll Reveal）、交錯動畫（Staggered Animation）都在幫讀者建立閱讀順序。作者給的數字很克制：捲動出現只上移 16px；交錯動畫每張間隔 70ms，總等待不超過 300ms。動得太多太久，反而讓頁面顯得遲鈍。

2. 每一種「等待」和「失敗」都要有畫面

短等待用轉圈（Spinner）、能算進度就用進度條（Progress Bar）、清單載入前用骨架屏（Skeleton Screen）、沒有內容時用空狀態（Empty State）、失敗時說清楚原因並提供重試（Retry）。使用者最怕的不是慢，而是不知道發生了什麼。

好比餐廳上菜慢：服務生來說一聲「還要十分鐘」，客人就安心多了；什麼都不說，客人只會一直張望。

3. 風格要服務內容，不是越潮越好

極簡、雜誌風、瑞士風、玻璃擬態、新野獸派……作者提醒每種風格的副作用：玻璃擬態容易讓文字融進背景，新擬態邊界不清楚，網格漸層會搶走正文的注意力。他自己的完整提示詞選的是「極簡＋雜誌風」，玻璃擬態和網格漸層只在首屏局部、克制地使用。

4. 每加一個特效，就寫好它的「關閉條件」

自訂游標在觸控裝置不啟用、3D 傾斜在手機上關閉、Three.js 首屏在不支援時改用靜態圖，而且只要使用者在系統開了「減少動態效果」（Reduced Motion），視差、磁吸按鈕、3D 傾斜、自動跑馬燈和輪播全部停掉，但功能照樣能用。高級感來自收放有度，而不是全開。

5. 先訂效能預算，再談炫技

效能預算（Performance Budget）就是開工前先規定：腳本多大、圖片多大、字型幾種（作者的例子是行動版首屏 JavaScript 盡量在 170KB gzip 以內、字型不超過兩個家族）。超過就要優化，不能為了動畫犧牲核心內容的載入速度。

怎麼開始

  1. 先替你現有的網頁補「狀態」：送出按鈕加上載入按鈕（Loading Button），清單加上空狀態（Empty State）與錯誤狀態（Error State）。這是投資報酬率最高的一步。
  2. 只挑一個風格，例如極簡主義（Minimalism），把對應提示詞裡的顏色與字型換成你的。
  3. 最多加一兩個動態效果，例如捲動出現（Scroll Reveal）與懸停微互動（Hover Micro-interaction）。
  4. 每段提示詞最後都加一句：「支援 prefers-reduced-motion，行動版簡化效果。」
  5. 想一次到位，就用文末的完整提示詞，它把 40 個詞分成四段要求，可以直接改名使用。

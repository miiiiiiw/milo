步驟 1：一張圖看懂整個系統（Step 1: The system in one picture）

以下是每天都會發出去的東西：

  • 當天那支影片的每一個版本，各發成一則 Instagram 試用 Reels（trial reels）（大約 6 則）
  • 1 則 TikTok，用它自己的剪法

另外每兩天：

  • 觀看數最高的那則試用 Reels（trial reels），會以全新上傳的方式發到我們的 Instagram 主帳號

算一下一個月的量。

大約 180 則試用 Reels（trial reels）、30 則 TikTok、15 則主帳號 Reels。

一個月 200 則以上的貼文。

試用 Reels（trial reels）是測試實驗室。它們會推給沒有追蹤你的人，所以你的粉絲不會影響結果，每支影片都靠自己定輸贏。主帳號的 Reels 只放已經證明有效的內容。

沒有系統的話，每天做這些事就是一份全職工作：拍片、剪輯、匯出 6 個版本、加音樂、一則一則上傳、寫文案、看觀看數、把贏家重新上傳。

漏掉兩天，整件事就停擺了。

所以我們圍繞著它建了一套系統。我們負責創意的部分，其餘交給系統。

流程是這樣的：

  1. 我們集中大量拍攝
  2. Claude Code 把每支影片剪成 6 個版本
  3. 在 Edits 裡加上聲音
  4. Claude 一次排好整個月
  5. 所有內容自動發布
  6. 我們每兩天挑出一個贏家

步驟 2：幾天拍完一個月的片（Step 2: Film a month in a few days）

每天拍片是第一個會崩掉的環節。生病的日子、出差的日子、懶惰的日子，就沒有影片了。

所以我們集中大量拍攝。

我們空出 2 到 3 天，把整個月的內容一次拍完，大約 30 支影片。

我們的做法：

先寫好鏡頭清單（shot list）。看看競爭對手哪些內容有效、其他利基（niche）裡哪些內容有效，以及你自己的試用 Reels（trial reels）裡哪些已經在贏。把每一個都變成清單上的一種格式。

每種格式用幾種不同的方式拍。不同的角度、不同的開場、不同的情緒能量。每種格式的原始素材越多，之後能做出的版本就越多。

多拍一些 B-roll（輔助畫面）。手部、螢幕、反應、走路的鏡頭、特寫。B-roll（輔助畫面）就是讓一支影片能變成六支的關鍵。

好好替檔案命名。像是 format-name_take-1.mov 這樣。很無聊，但系統就是靠這個才能整理你的素材，不用你在旁邊顧著。

拍不同格式之間換衣服。3 天拍完的一個月內容，不應該看起來像 3 天拍完的。

接著，所有素材依格式各放進一個資料夾。這些資料夾就是整套系統的輸入。

步驟 3：系統把每支影片剪成 6 個版本（Step 3: The system cuts every video into 6）

我們的速度就是從這裡來的。

我們用 Claude 來剪片。就像我在置頂指南裡說的，以前剪半支影片的時間，現在可以剪完 6 支。

現在它變成一套系統在跑。

每支影片會變成大約 6 個版本，每個版本改動的是：

  • 開場鉤子（hook）（前 1 到 3 秒）
  • 長度
  • 用哪些片段
  • 片段的順序
  • 畫面上的文字

每個版本都是一次測試。一週後，你就會知道哪些開場鉤子（hook）有效、哪種長度留得住人，以及哪些開場會失敗。

設定：Claude Code＋ffmpeg（The setup: Claude Code + ffmpeg）

Claude Code 在你的電腦上執行，所以它能打開你的素材資料夾、執行 ffmpeg。ffmpeg 是一個免費工具，可以用命令列來剪短、接合影片，以及在影片上加文字。

你不需要懂 ffmpeg。Claude 會寫好指令並執行。

設定步驟：

  1. 安裝 ffmpeg（免費）和 Claude Code
  2. 每種格式一個資料夾，原始片段放在裡面
  3. 一份讓 Claude 每次都照著做的配方檔（recipe）

我們的配方大概長這樣：

配方（recipe）原文

For each folder in /footage, make 6 vertical 9:16 versions.
Version 1: 7 seconds, fast cuts, hook text from hooks.txt line 1.
Version 2: 12 seconds, open on the reaction clip, a different hook.
Version 3: 15 seconds, original clip order, no text for the first second.
Versions 4 to 6: shuffle the clip order and test 3 new hooks from hooks.txt.
Also make one shorter, faster TikTok cut per format.
Save to /exports/[format]/ and name each file with the hook and length.

中譯

/footage 裡的每個資料夾，都做出 6 個 9:16 直式版本。
版本 1：7 秒，快速剪接，開場鉤子文字用 hooks.txt 第 1 行。
版本 2：12 秒，用反應片段開場，換一個開場鉤子。
版本 3：15 秒，維持原本的片段順序，第一秒不放文字。
版本 4 到 6：打亂片段順序，測試 hooks.txt 裡 3 個新的開場鉤子。
每種格式另外做一個更短、節奏更快的 TikTok 版本。
存到 /exports/[格式]/，每個檔名都寫上開場鉤子與長度。

30 支影片進去，出來大約 180 個 Instagram 版本和 30 個 TikTok 版本。

我們晚上讓它跑，早上起床就有一整個月的版本。

讓它每週越來越好的兩件事：

hooks.txt。每當某個開場鉤子（hook）在試用 Reels（trial reels）上勝出，它就會被加進這個檔案。下次 Claude 會從這裡取用。這個開場鉤子庫（hook bank）每一週都會變得更強。

依平台分開剪的版本。TikTok 要更短、更腦腐（brain rot）、更不費力；Instagram 要更長、品質更高、節奏更慢。這寫在配方裡，所以我們從不把同一個版本同時匯出給兩個平台。

有些影片太亂，Claude 剪不好，那些我們就自己剪。還是省下好幾個小時。

為什麼不用剪輯切片工具（clipping tool）？這類工具大多是設計來從很長的 Podcast 和 YouTube 影片裡擷取短片段的。我們的影片本來就很短。我們需要的是把同一支影片用 6 種不同方式重新剪，而這正是 Claude Code＋ffmpeg 在做的事。

步驟 4：在 Edits 裡完成每個版本（Step 4: Finish every version in Edits）

Claude 幫你剪好片，聲音則是最後一道工序。

每個版本在排程之前，都會先經過 Instagram 的 Edits App。

為什麼用 Edits：

  • 它是免費的，而且是 Instagram 自家的剪輯工具
  • 匯出很乾淨，沒有浮水印（watermark）
  • 以我們的經驗，多次發布相似的影片時，比較不容易被系統標記；而且 Instagram 對在 Edits 裡完成的影片待遇不錯

Edits 剛推出 Mac 版，所以現在這變成坐在桌前就能做的事：一邊是素材資料夾，另一邊是 Edits。

流程：

  1. 匯入這個版本
  2. 加上聲音
  3. 如果這個版本需要，就加上自動字幕
  4. 匯出到同一個名為 /ready 的資料夾

聲音是你最重要的測試槓桿之一，所以我們自己挑。讓工具盲選聲音，會讓你損失觀看數。

關於聲音有一條規則：用 Edits 音樂庫裡的免版稅音樂，或你自己的音訊。有授權的歌曲可能會在匯出時被拿掉，或之後被靜音，而你會在貼文上線之後才發現。

TikTok 的版本要把聲音直接做進檔案裡。排程發布的 TikTok，會用影片本身已經有的音訊上線。

這是整個月裡唯一需要真的坐下來花時間的部分。專心一天就能處理完整批。

步驟 5：分發（distribution）才是真正的瓶頸（bottleneck）（Step 5: Distribution is the real bottleneck）

這是沒人會告訴你的事。

一旦你能集中大量拍攝、把每支影片都剪成 6 個版本，做內容就不再是問題了。

把它發出去，才變成問題。

一個月 200 次以上的上傳。每一次都要用對的版本、對的平台、對的文案、對的時間，以及對的設定（試用 Reels〔trial reels〕還是主帳號 Reels）。

每天用手機做這些事，就是一致性（consistency）死掉的地方。我們第一次就是這樣每個月少賺了 2 萬美元。沒有結構。

所以發文是我們完全交出去的部分。Postiz 就是幫我們做這件事的。

Postiz 是一個排程工具，可以從同一個月曆發文到 Instagram、TikTok、YouTube、X 等一大堆平台。你排好時間，它就在那個時間發布。不用手機，不用提醒。

我們拿它來做這些事：

一個月一張月曆。每一則試用 Reels（trial reels）、每一則 TikTok、每一則主帳號 Reels，都在同一個畫面上。哪裡有空檔一眼就看得出來。

試用 Reels（trial reels），自動發。排程 Instagram Reels 時有一個 Trial Reel 開關（先只分享給非粉絲）。你可以選擇它怎麼轉正（graduation）：手動，或依成效自動。我們設定成手動，因為我們會把贏家重新全新上傳。

TikTok 直接發布（direct post）。它會在你設定的時間直接發到個人檔案上，不會有東西卡在你的收件匣，等你去把它完成。

每個平台用不同的版本。每個頻道都有自己的影片和文案，所以 TikTok 版本發到 TikTok，Instagram 版本發到 Instagram。

時段（time slots）。設定每個帳號平常發文的時間，月曆就會圍繞這些時段來規劃。

Instagram 的首則留言（first comment）。在你自己的貼文底下排程一則留言，時間可設在貼文上線後 1 分鐘到 2 小時之間。很適合在每則貼文放一行簡短的 CTA（行動呼籲），不用每次都記得去做。

每則貼文的數據分析。每則貼文、每個帳號的觀看、按讚、留言和分享，全都在同一個地方。

步驟 6：一次排好整個月（Step 6: Schedule the whole month in one go）

Postiz 可以連接 Claude。你可以從 Claude 的連接器（connectors）裡加入 Postiz，Claude Code 也會一併取用。或者在終端機下一行指令：

終端機指令（terminal）

claude mcp add --transport http postiz https://mcp.postiz.com/mcp-oauth-dynamic

指令說明：在 Claude Code 加入一個名為 postiz、以 HTTP 傳輸的 MCP 伺服器，網址為 Postiz 的動態 OAuth 端點。

它會打開一個瀏覽器分頁，你登入 Postiz，就完成了。不需要應用程式介面金鑰（API key）。

我們也裝了 Postiz 的命令列工具（CLI）（npm install -g postiz），讓 Claude 可以直接從 /ready 資料夾上傳檔案。

現在 Claude 看得到我們的帳號，可以上傳影片，也可以排程每一則貼文。

所以排好一個月只需要一則訊息：

給 Claude 的訊息（原文）

Upload everything in /ready to Postiz. For each day, schedule that day's 6 Instagram versions as trial reels with manual graduation, spaced out across our time slots. Schedule the TikTok cut of that day's video as a direct post at 6pm. Use the caption in each file name.

中譯

把 /ready 裡的所有東西上傳到 Postiz。每一天，把當天的 6 個 Instagram 版本排成試用 Reels，設定為手動轉正，分散在我們的各個時段。把當天影片的 TikTok 版本排在下午 6 點直接發布。文案用每個檔名裡寫的那段。

Claude 會把整個月建好。每一則試用 Reels（trial reels）都用這個設定發出：

json

{"post_type":"post","is_trial_reel":true,"graduation_strategy":"MANUAL"}

欄位說明：post_type 是貼文類型（一般貼文）；is_trial_reel 為 true 表示這是試用 Reels；graduation_strategy 為 MANUAL 表示手動轉正。

接著我們用月檢視打開月曆，檢查一遍，把不喜歡的拖到別的位置，就完成了。

Postiz 會在設定的時間把所有內容發出去，就算筆電闔上也一樣。

設定過程中學到的三個訣竅：

第一週先設成草稿。叫 Claude 把第一週排成草稿。在月曆上檢查過，再把它們開啟。之後你就會信任它了。

注意你的時區。Postiz 用的是你瀏覽器的時區。如果你的觀眾在別的地方，就照他們的時間設定時段。

把檔案留在 Postiz 裡。你上傳的所有東西都會放在媒體庫裡，所以步驟 7 重新上傳贏家只要點一下。

你一個月的發文工作，會從每天在手機上花好幾個小時，變成一個下午的設定。

步驟 7：每兩天挑出贏家（Step 7: Pick the winner every second day）

整個系統都是為了這一個決定。這是我們這個月裡唯一會動手的事。

每兩天：

  1. 在 Instagram 洞察報告（insights）裡查看試用 Reels（trial reels）的觀看數
  2. 找出觀看數最高的版本
  3. 在 Postiz 把那個檔案排成主帳號的一般 Reels（或者跟 Claude 說：「把這個排成今晚 7 點的主帳號 Reels」）
  4. 把它的開場鉤子（hook）加進 hooks.txt

把贏家當成全新影片上傳。不要直接把那則試用 Reels（trial reels）公開。

有時候全新上傳的觀看數反而比較少。如果它本來觀看數就不錯，它有可能得到更大的推力。自己拿捏。

然後寫下它為什麼贏。是開場鉤子（hook）？聲音？長度？第一個片段？這份筆記決定下個月要拍什麼。

也要用錢來評判每一個贏家。觀看數較少的影片，如果轉換率比較好，還是可能賺得更多。在贏家發出去的那幾天，看看下載數和營收。

每兩天 5 分鐘。

一個月的全貌（The month at a glance）

第 1 天和第 2 天：拍攝
前一晚寫好鏡頭清單（shot list）。把所有東西拍完，倒進各個格式資料夾。

第 3 天：剪輯
Claude Code 整晚跑配方（recipe）。大約 180 個 Instagram 版本和 30 個 TikTok 版本。

第 4 天：完成並排程
在 Edits 加上聲音和字幕。所有東西放進 /ready。Claude 把整個月載入 Postiz。檢查月曆。

每天：10 分鐘
回覆留言，看一眼觀看數。

每兩天：5 分鐘
挑出贏家，排到主帳號上。

每週結束：30 分鐘
回顧哪些贏了。更新 hooks.txt。開始寫下個月的鏡頭清單（shot list）。

幾天的工作，換來一整個月的貼文。

完整系統（The complete system）

所有東西整理在一起：

  1. 集中大量拍攝。2 到 3 天就涵蓋整個月
  2. Claude Code 把每支影片剪成 6 個版本。不同的開場鉤子（hook）、長度、片段順序，再加上一個獨立的 TikTok 版本
  3. 在 Edits 裡完成。聲音和字幕，匯出到 /ready
  4. Claude 把整個月載入 Postiz。試用 Reels（trial reels）、TikTok、文案、時段（time slots）
  5. Postiz 自動發布所有內容。每天、準時、每個帳號
  6. 每兩天挑出贏家。最好的試用 Reels（trial reels）以全新上傳的方式發到主帳號
  7. 每週回顧。更新開場鉤子庫（hook bank）、寫下一份鏡頭清單（shot list），再跑一次

拍攝、剪輯、測試、挑出贏家，是這些讓我們在廣告費 0 元的情況下做到每月 4 萬美元。自動化則是讓它每天持續運轉的東西。

譯註：開頭說年度經常性收入（ARR）突破 20 萬美元（換算約每月 1.7 萬美元），這裡寫的是每月 4 萬美元，原文沒有說明兩個數字的差別，譯文照原文保留。

一旦你能大量做內容，瓶頸（bottleneck）就在於每天準時把所有內容發出去、而且不中斷。這就是 Postiz 替我們跑的那一段。

這週就開始（Start this week）

  • 寫一份鏡頭清單（shot list），集中拍攝一天
  • 把 Claude Code 和 ffmpeg 設定好，替你的第一支影片做出 6 個版本
  • 開始 Postiz 的試用，連上 Instagram 和 TikTok，把一週的內容排成草稿
  • 每兩天挑出贏家，全新上傳

第一個月不會完美，也不需要完美。

系統讓發文變成自動的，但它不會幫你拍影片。

最難的是一致性（consistency）。如果你沒辦法保持一致，這套方法就不會有用。

以下為譯者整理，非原文內容。

這篇在說什麼

Nicholas 公開他們替自家 App 做短影音行銷的整套流程：幾天集中拍完一個月的素材，讓 Claude Code 用 ffmpeg 把每支影片剪成約 6 個版本，在 Edits 加上聲音，再請 Claude 透過 Postiz 一次排好整個月的貼文，之後每兩天挑一個贏家重新上傳到主帳號。

作者說這套做法每月發出 200 則以上的貼文，而他們真正動手的只有拍攝、加聲音和挑贏家。他也提醒，這是他們自己摸索出來的做法，讀者應該把流程想清楚，再請 AI 幫忙搭出自己的版本。

為什麼值得學

多數短影音教學停在「每天發」「多測試」這種原則。這篇把原則拆成具體的分工：哪幾天集中做、哪些交給 Claude Code 和排程工具、哪些一定要人自己判斷（聲音、挑贏家）。就算你的內容不是影片，也可以照「想清楚流程、再請 AI 幫你搭」的做法套用。

文中的數字（年度經常性收入〔ARR〕20 萬美元、每月 4 萬美元、每天 100 萬次觀看）都是作者自己公布的成績，不是保證；文末推薦的 Postiz 也是作者實際使用、並附上試用連結的工具。

你可以帶走的重點

1. 一支影片剪成 6 個版本，每個版本都是一次測試

作者讓每支影片在開場鉤子（hook）、長度、用哪些片段、片段順序和畫面文字上各不相同，一週後就知道哪些開場有效、哪種長度留得住人。關鍵在拍攝時就多拍：每種格式用幾種方式拍，再多拍 B-roll（輔助畫面），之後才有素材剪出六種版本。

TikTok 和 Instagram 也分開剪：TikTok 要短、要快；Instagram 要長一點、品質高一點、節奏慢一點。這條規則直接寫進配方檔（recipe），所以不會一個版本兩邊共用。

2. 試用 Reels 當測試實驗室，贏家才上主帳號

試用 Reels（trial reels）只推給沒有追蹤你的人，所以粉絲不會影響結果，每個版本都靠自己定輸贏。作者每兩天看一次洞察報告（insights），把觀看數最高的版本當成全新影片上傳到主帳號，而不是直接把那則試用 Reels（trial reels）公開。

挑完還要寫下它為什麼贏（開場鉤子、聲音、長度還是第一個片段），把勝出的開場鉤子（hook）加進 hooks.txt。他也提醒要用營收判斷贏家：觀看數較少、但轉換率較好的影片可能賺得更多。

3. 內容做得出來之後，瓶頸在分發

作者說，一旦能集中拍攝、每支剪 6 個版本，做內容就不再是問題，把內容發出去才是瓶頸（bottleneck）：每月 200 次以上的上傳，每一次都要選對版本、平台、文案、時間和設定。用手機每天手動發，一致性（consistency）就會在這裡斷掉；他們第一次就因為沒有結構，每月少賺 2 萬美元。

所以他們把發文整段交給排程工具 Postiz：同一張月曆看全部貼文、試用 Reels（trial reels）開關、TikTok 直接發布（direct post）、每個帳號的時段（time slots）、自動排首則留言（first comment）放 CTA（行動呼籲）。

4. 讓 Claude Code 照配方檔批次剪片

Claude Code 跑在自己的電腦上，可以打開素材資料夾、替你寫好並執行 ffmpeg 指令，你不需要懂 ffmpeg。設定只有三件事：裝好 ffmpeg 和 Claude Code、每種格式一個資料夾、一份每次都照做的配方檔（recipe）。晚上讓它跑，30 支影片進去，早上出來約 180 個 Instagram 版本和 30 個 TikTok 版本。

兩個細節讓它每週變好：開場鉤子庫（hook bank）hooks.txt 會累積勝出的開場；檔名寫上開場鉤子與長度，系統就能自己整理素材。太亂的影片作者還是自己剪。

5. 把一個月壓成幾天的集中工作

作者的月曆是這樣分的：第 1、2 天拍攝，第 3 天讓 Claude Code 整晚剪片，第 4 天在 Edits 加聲音和字幕、請 Claude 把整個月載入 Postiz。之後每天只花 10 分鐘回留言、看觀看數，每兩天 5 分鐘挑贏家，每週末 30 分鐘回顧並更新 hooks.txt、開始寫下個月的鏡頭清單（shot list）。

他也特別說明兩件事不交給工具：聲音要自己挑（用免版稅音樂或自己的音訊），第一週先排成草稿、在月曆上檢查過再開啟。系統讓發文自動化，但不會替你拍片；最難的仍然是一致性（consistency）。

可以怎麼開始

  1. 先寫一份鏡頭清單（shot list），參考競爭對手、其他利基（niche）和你自己表現好的影片，集中拍攝一天。
  2. 裝好 Claude Code 和 ffmpeg，寫一份配方檔（recipe），替第一支影片做出 6 個版本。
  3. 開一個 hooks.txt，之後每個勝出的開場鉤子（hook）都記進去。
  4. 接上排程工具，把第一週排成草稿，在月曆上檢查過再開啟。
  5. 每兩天挑出觀看數最高的版本，全新上傳到主帳號，並寫下它贏的原因。

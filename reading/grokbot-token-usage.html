GrokBot 用量指南：十個步驟，讓你再也不會撞上上限

GrokBot Token Usage: how to never hit your limit again in 10 step

作者：vartekx（@vartekxx）

原文：https://x.com/vartekxx/status/2119105285851656535

日期：2026-11-07（UTC 16:30；台北時間 2026-11-08 00:30）

備註：繁體中文翻譯，僅供個人閱讀。

用量已達 100%。還有 4 天才重置。不會另外幫你重置。

聽起來很熟嗎？

這就是 11 月 1 日，Grok Bot 使用者一覺醒來的處境。Musk 的回應是：這套 Bot「難以持續」（unsustainably）昂貴。

舊的上限不會回來了。但你的用量池（pool），大多從來不是花在真正的工作上。它流進了空跑的 Routines、Bot 反覆重讀好幾週的對話，以及四個 Bot 回答同一個問題。

把這 10 處漏洞補上，同一個用量池就能撐完整週。

Grok Bot 是大多數人用過最好的代理（agent）。它有自己的電腦，會登入你的工具，還能在你睡覺時自己跑工作。

這也正是它很吃用量的原因。每一則回覆、每一次 Routine 執行、每一則 Bot 之間的訊息，都要花費。而自從上限收緊之後，以前一週還夠用的設定，現在兩天就見底。

01. 先搞懂到底改了什麼（Understand what actually changed）

萬聖節週末（10 月 31 日至 11 月 1 日），X、Reddit 和 Cursor 論壇上的使用者紛紛回報：每週用量計（meter）直接跳到 100%，距離重置還有好幾天。

有人看到從 50% 跳到 100%，有人從 35% 跳到 78%，也有人幾乎沒有 Bot 活動卻同樣暴增。

有一位使用者在還有四天重置時就碰到 100%，向 Elon Musk 請求重置。

對方沒有承諾重置，SpaceXSI 也尚未公布新的上限數字。

Elon Musk（@elonmusk）

2026-11-02 04:34（台北時間）　原文連結

回覆 @DogecoinNorway 詢問是否能為 Grok Bot 重置用量。

相對於營收，營運 Grok Bot 的成本高到難以持續。

多數人沒注意到的一點：那是同一個用量池（The part most people miss: it's one pool）

在 The X Subscription（X 訂閱方案）上，Grok 聊天、Grok Bot 和 Cursor 都從同一個每週用量池扣打。跟 Grok 聊一小時，或開一場很長的 Cursor 工作階段，留給你 Bot 的就更少。

02. 找出你的用量計，盤點是什麼在燒它（Find your meter and audit what burns it）

砍任何東西之前，先看數字。用量計會顯示一個每週百分比，以及你的重置日期。

它不會依 Bot 或 Routine 拆開用量，所以沉重的工作得自己找。

接著，讓 GrokBot 告訴你它整週都在做什麼。把這段傳給你的主要 Bot（Primary Bot）。它會協調你的其他 Bot，所以也能幫你把那些清單收齊。

提示詞（英文原文，可直接複製）

Audit what is using my weekly Grok Bot usage.

1. List every routine you and my other Bots own in a table:
   Bot, routine name, schedule or trigger, runs per day, runs per week, last run.
2. List recurring jobs I ask for by hand at least twice a week.
3. List group chats where more than one Bot replies.
4. Mark the 5 items most likely to use the most usage and explain why in one line each.

Don't change anything yet. Wait for my OK.

中文翻譯

盤點我的每週 Grok Bot 用量都花在哪裡。

1. 用表格列出你和我其他 Bot 擁有的每一項 Routine：
   Bot、Routine 名稱、排程或觸發、每天執行次數、每週執行次數、上次執行。
2. 列出我每週至少親手交代兩次的重複工作。
3. 列出有超過一個 Bot 會回覆的群組聊天。
4. 標出最可能最吃用量的 5 項，各用一行解釋原因。

先不要改任何東西。等我點頭。

03. 把 Routines 放慢（Slow down your routines）

最大的隱藏成本（Biggest hidden cost）

SpaceXAI 的文件寫得很直接：每一次 Routine 執行都會消耗用量，測試按鈕（Test）也不例外。

一個每 15 分鐘檢查一次的 Routine，一天會跑 96 次、一週 672 次，即使根本沒有新東西。

Lauren Tan（@poteto）——SpaceXAI 團隊成員——在 X 上也給了同樣的建議：對大多數 Routines 來說，每小時一次、或一天幾次就夠了。

lauren（@poteto）

2026-08-23 11:34（台北時間）　原文連結

我控制 Grok Bot 用量的第一建議，是避免讓排程 Routines 跑得太勤。舉例來說，一個 15 分鐘一次的 Routine 一天差不多跑 100 次，而每次執行都會消耗 token。對大多數情況，每小時一次、或一天幾次通常就夠了。

你和 Bot 的對話長度，也會讓 Routines 貴很多。若是反覆執行的工作，試著交給一個新的 Bot，你則繼續跟主要的 Bot 聊天（像一位幕僚長那樣）。

把這則貼文交給你的 Bot，請它幫忙！

提示詞（英文原文，可直接複製）

Using the audit, suggest the slowest schedule for each routine that still does its job.

Rules:
- Nothing runs more often than once an hour unless I approve it.
- Work routines run only Monday to Friday, during my working hours.
- Merge routines that read the same source into one run.
- Delete one-time "watch for X" routines whose job is done.
- If a routine only waits for something to happen, mark it "switch to trigger".

Show a before/after table with runs per week.
Apply the changes only after I say OK.

中文翻譯

根據這次盤點，為每一項 Routine 建議仍能完成工作的最慢排程。

規則：
- 除非我同意，否則任何項目都不得超過每小時一次。
- 工作類 Routine 只在週一到週五、我的工作時間內執行。
- 讀取同一來源的 Routine 合併成一次執行。
- 刪掉已經完成任務的一次性「盯著 X」Routine。
- 若一項 Routine 只是在等某件事發生，標成「改為觸發」。

用表格列出每週執行次數的調整前後對照。
等我說可以，再套用變更。

04. 把排程換成事件觸發（Swap schedules for event triggers）

排程就算什麼都沒變，也會把你的 Bot 叫醒。觸發（trigger）只有在真的發生事情時才會叫醒它。

一位 Cursor 工程師是這樣說的：cron（定時排程）就算沒事做，也會把它叫醒。

eric zakariasson（@ericzakariasson）

2026-08-26 00:04（台北時間）　原文連結

如何讓你的 Grok Bot 方案撐得更久：

1）能用事件觸發就用。Slack、GitHub、一個反應都可以。Bot 只在真的發生事情時才執行（cron 就算什麼都沒變也會把它叫醒）

2）指示 Bot：一旦無法繼續推進或卡住，立刻通知你。這樣你作為人，才能幫它重新回到正確方向

3）能用連接器（connectors）就不要用瀏覽器！在網站上點來點去，會堆出一堆截圖和步驟。連接器一次呼叫就能拿到同樣的資料，而且更順、更快、更穩

4）讓 Skills 保持精簡，但把真正會引導執行的細節寫進去。太含糊，Bot 可能會遊蕩、重試，最後比稍微寫長一點還貴。太具體，你又得確保那些細節真的正確

5）不要在 Bot 聊天裡寫程式！對儲存庫派出一個雲端代理，或請它用 Cursor／Grok 的 build CLI 來做

6）一次性的監看不必再留的時候就刪掉（Grok Bot 會提醒你這件事）

提示詞（英文原文，可直接複製）

Change the routine "[routine name]" from a schedule to an event trigger.

Trigger: [a Slack message in #channel that mentions you / a new GitHub issue with label "bug" / an email to your address / a webhook].

Rules:
- Run only on new activity.
- If the event isn't relevant to this job, stop right away and don't reply.
- Never post "nothing new" messages.

Tell me which trigger you set and how I can test it once.

中文翻譯

把 Routine「[routine 名稱]」從排程改成事件觸發。

觸發條件：[在 #頻道 提到你的 Slack 訊息 / 一則標了 "bug" 的新 GitHub issue / 寄到你地址的一封信 / 一個 webhook]。

規則：
- 只在有新活動時執行。
- 若這件事跟這份工作無關，立刻停止，不要回覆。
- 永遠不要發「沒有新消息」的訊息。

告訴我你設了哪一種觸發，以及我可以怎麼測試一次。

05. 把做很久的工作交給新的 Bot（Move long jobs to a fresh Bot）

根據 Cursor 人員在論壇上的說明，每一次回覆都會重讀該 Bot 的整段對話。大部分會被快取，但一個你已經聊了六週的 Bot，會把那些內容帶進每一個答案、每一次 Routine 執行。

目前還沒有手動的 compact（壓縮對話）按鈕。摘要只有在接近模型上限時才會啟動。

解法是：當一個 Bot 已經為同一件工作跑了好幾週，請它寫一份簡短的交接筆記（handoff note），再把這份工作交給一個全新的複本。

提示詞（英文原文，可直接複製）

Write a handoff note for a fresh Bot that will take over "[job]".

Include:
- the goal and what "done" looks like
- the rules and preferences I gave you for this job
- the apps and accounts it uses
- current state and open items
- mistakes we already made, so it doesn't repeat them

Max 300 words. No chat history, no small talk.

中文翻譯

為即將接手「[工作]」的新 Bot 寫一份交接筆記。

請包含：
- 目標，以及怎樣叫做「完成」
- 我為這份工作給你的規則和偏好
- 它會用到的應用程式和帳號
- 目前狀態與未竟事項
- 我們已經犯過的錯，免得它再犯

最多 300 字。不要聊天紀錄，不要客套。

06. 停止群組聊天稅（Stop the group chat tax）

SpaceXAI 的文件寫道：每一則 Bot 回覆都會計入用量，包括群組聊天裡的回覆，以及 Bot 彼此傳送的訊息。

把四個 Bot 放進同一個聊天室，問一個問題，你可能要為四個答案付費。一位 Grok Bot 負責人在上次效率更新之後，給的提醒很短：小心群組聊天。

Jediah Katz（@jediahkatz）

2026-09-18 02:35（台北時間）　原文連結

更新：我們已對 Grok Bot 推出更多優化，讓你再多出約 10% 的有效用量。

這一輪主要是減少子代理被過度使用、降低 Bot 之間吵雜的對話，以及為低費力的批次工作做更聰明的路由。

另外一個實用提醒：小心群組聊天！它們非常消耗 token，而且坦白說，我不太確定對多數人來說值不值得。群組越大，成本越高。如果你在意價格，大多數工作我會避免用群組。在我們把它控制住之前，或許得先限制這類用法。

沒有任何設定能阻止 Bot 互傳訊息，所以規則得在聊天裡訂。把這段傳給你的主要 Bot：

提示詞（英文原文，可直接複製）

New rules for how my Bots work together. Save them to memory and share them with my other Bots.

1. One owner per job. In group chats only the owner replies. Others stay silent unless I @mention them.
2. Hand off once, with the finished result. No progress updates to each other.
3. Max 2 Bot-to-Bot messages per task. If you need more, ask me instead.
4. Don't start helper Bots or subagents for small tasks you can finish yourself.
5. If you have nothing new to add, don't reply.

Confirm each rule back in one line.

中文翻譯

關於我的 Bot 如何共事，這是新規則。存進記憶，並分享給我的其他 Bot。

1. 一件工作只有一個負責人。在群組聊天裡只有負責人回覆。除非我 @提到，否則其他人保持沉默。
2. 交接一次，交出完成的結果。不要互相傳進度更新。
3. 每項任務最多 2 則 Bot 之間的訊息。若還需要更多，改問我。
4. 自己做得到的小任務，不要再叫幫手 Bot 或子代理。
5. 若沒有新的內容要補充，就不要回覆。

請用一行確認每一條規則。

07. 寫任務時給它一條終點線（Write tasks with a finish line）

Grok Bot 會自己挑選模型，而文件指出：用量取決於任務的性質，以及它要花多少力氣。

像「研究一下我們的流失（churn）」這種模糊任務沒有盡頭，所以 Bot 會一直探索下去。一個有範圍、有終點線（finish line）、有停止規則的任務，會比較早結束。

Cursor 自己的說明頁也這樣說：從小型、範圍緊縮的任務開始。

把停止規則設成常態，這樣就不必每次重講：

提示詞（英文原文，可直接複製）

Remember these rules for every task:
- If the same step fails twice, stop and tell me what's blocking you. Don't keep retrying.
- If I didn't give you something you need, ask once. Don't search for workarounds.
- Final results only. No progress messages unless the task takes more than an hour.

中文翻譯

記住這些規則，適用於每一項任務：
- 若同一個步驟失敗兩次，就停下來，告訴我你卡在哪裡。不要一直重試。
- 若我沒有給你需要的東西，問一次就好。不要自己找變通辦法。
- 只給最終結果。除非任務超過一小時，否則不要傳進度訊息。

提示詞（英文原文，可直接複製）

Task: [one sentence]
Scope: only [files / channel / inbox / list]. Don't touch anything else.
Done when: [concrete finish line].
Stop if: the same step fails twice, or something I didn't give you is missing. Then message me what's blocking you.
Don't: research alternatives, open extra tabs, or start helper Bots.
Output: [format], max [N] words.

中文翻譯

任務：[一句話]
範圍：只限 [檔案／頻道／收件匣／清單]。不要碰其他東西。
完成條件：[具體的終點線]。
若下列情況就停止：同一個步驟失敗兩次，或缺少我沒有提供的東西。然後傳訊告訴我你卡在哪裡。
不要：研究替代方案、多開分頁，或叫幫手 Bot。
輸出：[格式]，最多 [N] 字。

08. 用應用程式連線，少用點擊（Use app connections instead of clicking）

當 Bot 透過它的電腦做事時，它會打開網站、截圖、找到按鈕、點擊和捲動，每一步都是額外的工作。

當同一件工作改走已連結的應用程式，或 MCP 伺服器，就只是一次直接呼叫。

Cursor 論壇上的進階使用者把這當成最容易省到用量的方法之一。SpaceXAI 沒有公布數據，所以就把它當成一條很有用的經驗法則（rule of thumb）。

提示詞（英文原文，可直接複製）

Go through the jobs you do for me on your computer or in the browser.

For each one, tell me:
- the job
- how you do it now (which site, roughly how many steps)
- the app connection or MCP server that could do it directly
- what I need to authorize

Sort by how often the job runs. From now on, if a connected app can do a step, use it instead of the browser.

中文翻譯

檢視你在自己的電腦或瀏覽器裡幫我做的工作。

每一項請告訴我：
- 這份工作是什麼
- 你現在怎麼做（哪個網站，大約多少步驟）
- 哪個應用程式連線或 MCP 伺服器可以直接做
- 我需要授權什麼

依這份工作執行的頻率排序。從現在起，只要已連結的應用程式能做某一步，就用它，不要走瀏覽器。

09. 把重複的工作變成 Skills（Turn repeat work into skills）

如果你每週一都要把同一份週報重新解釋一遍，Bot 每週一都會從頭摸索。Skill 是一組存起來、Bot 可以重複使用的步驟，而且會在你所有 Bot 之間共享。你示範一次，之後用名字叫它即可。

還沒有 Teach a task（教一項任務）按鈕？先在聊天裡做完一次，然後傳這段：

提示詞（英文原文，可直接複製）

Save what you just did as a skill called "[name]".

Write it as short numbered steps. Include:
- the inputs it needs from me
- the exact output format
- the apps to use (use connected apps, not the browser, where possible)
- the mistakes we hit this time and how to avoid them

Keep it under 200 words. Next time I'll just write @[name].

中文翻譯

把你剛剛做的事存成一個名叫「[名稱]」的 Skill。

請寫成簡短的編號步驟。包含：
- 它需要我提供的輸入
- 確切的輸出格式
- 要使用的應用程式（盡量用已連結的應用程式，不要用瀏覽器）
- 這次碰到的錯誤，以及如何避免

控制在 200 字以內。下次我只要寫 @[名稱]。

10. 為用量設上限，並為 100% 預作打算（Cap your spend and plan for 100%）

當每週用量池用完，會發生兩種情況之一。若額外用量（extra usage）是關閉的，你的 Bot 會停到重置為止。

若是開啟的，它們會繼續用付費點數（credits）運作，除非你自己設上限，否則沒有封頂。在這件事發生之前，先決定你要哪一種。

當你用到 80%，切換到低用量模式（When you're at 80%, switch to low-usage mode）

撞上上限之前不會有預警（Cursor 人員說這項功能已在規劃，但沒有日期）。所以在一週過到一半時查看用量計，若用量偏高，就傳這段：

提示詞（英文原文，可直接複製）

I'm at [80]% of my weekly usage and it resets on [date].
Until then, switch to low-usage mode:

- Pause every routine except: [list the ones that matter].
- Only do work I ask for directly.
- No group chat replies unless I @mention you.
- Final results only, as short as possible.

Keep a list of everything you paused. On [reset date], show me the list and turn them back on after my OK.

中文翻譯

我的每週用量已經用到 [80]%，會在 [日期] 重置。
在那之前，切換到低用量模式：

- 暫停所有 Routine，除了：[列出重要的幾項]。
- 只做我直接交代的工作。
- 除非我 @提到你，否則不要在群組聊天回覆。
- 只給最終結果，越短越好。

把你暫停的所有項目列成清單。在 [重置日期] 當天把清單給我看，等我同意後再重新開啟。

問題出在你的方案嗎？（Is your plan the problem?）

如果你已經做完第 2 到第 9 步，仍然每週都碰到 100%，那就不是設定太浪費，只是你需要更大的用量池。

結論（Conclusion）

你的用量池沒有變大，所以 Bot 必須變精簡。大多數浪費是看不見的：Routines 空跑、Bot 重讀六週的對話、四個 Bot 回答一個問題、Bot 在網站上點來點去，但其實一個應用程式呼叫就能讀到資料。

今天就把盤點提示詞跑一遍。修好它找出的最大三項。週三再看一次用量計。光是這樣，多數人就能回到上限以內。

把這篇存起來，等下次用量計又往上跳的時候用。

這篇在說什麼

2026 年 11 月 1 日，很多 Grok Bot 使用者一覺醒來，發現每週用量已經 100%，距離重置還有好幾天。Musk 的說法是，這套 Bot 的營運成本高到難以持續；舊的上限也不會回來。

作者要說的是：你不見得是「用太多」，而是「用錯地方」。多數用量漏在看不見的地方——空轉的 Routines、越聊越長的對話、群組裡好幾個 Bot 搶著回答。文中列出 10 處漏洞，並附上可直接複製的提示詞。把漏洞補上，同一個用量池就能撐完整週。

為什麼值得學

你不必會寫程式，也不必先搞懂模型怎麼計費。這篇教的是一種很生活化的方法：先看數字，再請 Bot 自己盤點，然後只改最浪費的幾項。

就算你只用一兩個 Bot，裡面關於「把工作寫清楚、給它終點、重複的事只教一次」的作法，跟其他 AI 工具相處時也用得上。更實際的是，文末那三步今天就能做：跑盤點、修好最大三項、週三再看一次用量計。

你可以帶走的重點

1. 上限收緊了，而且不會變回來

萬聖節週末，X、Reddit 和 Cursor 論壇上都有人回報：用量計在短時間內跳到 100%，有人從一半跳到全滿，也有人幾乎沒在用 Bot 卻同樣暴增。有人向 Musk 請求重置，但沒有得到承諾，新的上限數字也還沒公布。

作者的前提很明確：舊的上限不會回來，所以要改的是你怎麼用，而不是等配額變大。

2. 同一個池子，三種用法一起花

多數人沒注意到：在 The X Subscription（X 訂閱方案）上，Grok 聊天、Grok Bot 和 Cursor 抽的是同一份每週用量池。跟 Grok 聊一小時，或開一場很長的 Cursor 工作階段，留給 Bot 的就更少。

用量計只顯示一個百分比和重置日期，不會告訴你是哪個 Bot、哪一項 Routine 在燒。所以要自己去找。

3. 先看用量計，再請主要 Bot 盤點

砍任何東西之前，先看數字。網頁在 grok.com/dashboard → Usage，應用程式在 Settings → Usage & Billing。

接著把文中的盤點提示詞傳給主要 Bot（Primary Bot）。請它列出所有 Routine、你常親手交代的重複工作，以及有兩個以上 Bot 會回覆的群組，並標出最吃用量的五項。重點是：先不要改，等你點頭。

4. 最隱形的成本，是 Routines 在空轉

每一次 Routine 執行都會消耗用量，連測試按鈕（Test）也不例外。一個每 15 分鐘檢查一次的 Routine，一週會跑 672 次，即使什麼都沒發生。

SpaceXAI 團隊的 Lauren Tan 也公開建議：對大多數 Routines 來說，每小時一次、或一天幾次就夠了。文中還有一段提示詞，會依盤點結果建議「仍能完成工作的最慢排程」，例如工作類只在平日上班時間跑、把讀同一來源的項目合併，並刪掉已經完成的一次性監看。

5. 能改事件觸發，就不要用排程

排程的問題是：就算什麼都沒變，也會把 Bot 叫醒。事件觸發（event trigger）只有在真的發生事情時才跑——例如有人在 Slack 提到它、出現新的 GitHub issue，或有信寄到 Bot 的地址。

文中用一個「收件匣監看」當例子：同一個工作日裡，每小時排程會叫醒 13 次；改由新郵件觸發，只叫醒 3 次。記得加上規則：只在有新活動時執行，無關的事件立刻停止，也不要回報「沒有新消息」。

6. 做很久的工作，交給新 Bot，並附上交接筆記

每一次回覆，Bot 都會重讀整段對話。你已經聊了六週的 Bot，會把那些內容帶進每一個答案、每一次 Routine。目前還沒有手動的 compact（壓縮對話）按鈕，摘要也要接近模型上限才會啟動。

解法很單純：請它寫一份短短的交接筆記——目標、怎樣算完成、規則、用哪些帳號、未竟事項，以及已經犯過的錯——然後把工作交給一個全新的複本。也可以複製 Bot（會帶著設定和 Skills，但不帶聊天紀錄），或在存好規則後重置對話。

7. 群組聊天會重複計費，要先指定負責人

每一則 Bot 回覆都算用量，包括群組裡的回覆，以及 Bot 彼此傳的訊息。四個 Bot 放在同一個聊天室，問一個問題，你可能要為四個答案付費。一位 Grok Bot 負責人在效率更新後給的提醒很短：小心群組聊天。

沒有開關能關掉 Bot 互傳訊息，所以規則得在聊天裡訂：一件工作一個負責人，其他人除非被 @提到否則保持沉默；交接一次就交出結果；每項任務最多兩則 Bot 之間的訊息。

8. 任務要有終點線，也要有停止規則

Grok Bot 會自己挑模型，用量取決於任務的性質，以及它要花多少力氣。像「研究一下我們的流失（churn）」這種沒有盡頭的問題，它會一直探索下去。

寫清楚這幾項，任務就會比較早結束：一句話說明任務、範圍只限哪裡、怎樣叫做完成、失敗兩次或少了東西就停下來問你、輸出要什麼格式、最長多少字。把「失敗兩次就停、缺東西就問一次、只給最終結果」設成常態，就不必每次重講。

9. 能接應用，就不要讓它在網頁上點來點去

Bot 若透過自己的電腦做事，就得打開網站、截圖、找按鈕、點擊、捲動，每一步都是額外工作。同一件事走已連結的應用程式或 MCP 伺服器，通常只是一次直接呼叫。

SpaceXAI 沒有公布省下多少，但論壇上的進階使用者把這當成最容易省到用量的方法之一。文中有一段提示詞，會請 Bot 列出它現在用瀏覽器做的事，以及改走哪一個已連結的應用。

10. 重複的工作，示範一次就存成 Skill

如果你每週一都要把同一份週報重新解釋一遍，Bot 每週一都會從頭摸索。Skill 是一組存起來、所有 Bot 都能重複使用的步驟：示範一次，之後用名字叫它即可。

目前若還沒有 Teach a task（教一項任務）按鈕，就先在聊天裡做完一次，再請它把步驟、你要提供的輸入、輸出格式、該用的應用，以及這次犯過的錯存起來。控制在 200 字以內，下次只要寫 @名稱。

11. 先決定 100% 時要停，還是繼續花點數

用量池用完會走兩條路：額外用量（extra usage）關閉，Bot 會停到重置；開啟的話，會繼續用付費點數跑，除非你自己設上限，否則沒有封頂。這件事發生前，先選好你要哪一種。

撞上上限之前目前沒有預警。作者建議一週過到一半就看用量計；到了 80%，就切換到低用量模式：只留真正重要的 Routines，只做你直接交代的事，群組裡除非被點名否則不回，回覆也盡量短。

12. 漏洞都補了還是不夠，才是方案問題

如果你已經做完第 2 到第 9 步，仍然每週都碰到 100%，那就不是設定太浪費，只是需要更大的用量池。原文附上各方案對照：Plus（每月 8 美元）完全不含 Grok Bot；Premium、Super、Ultra 分別是基礎用量池的 4 倍、15 倍、50 倍，且都包含 Grok Bot。

怎麼開始

這三步直接來自原文結論，今天就能做。

  1. 今天，把盤點提示詞傳給你的主要 Bot。請它列出所有 Routine、重複工作和群組聊天，並標出最吃用量的五項。先不要改，等你看過再決定。
  2. 只修好它找出的最大三項。常見會是：把過勤的排程放慢或改成事件觸發、把做很久的工作交給新 Bot，以及減少群組裡重複的回覆。
  3. 週三再看一次用量計。原文說，光是這樣，多數人就能回到上限以內。下次用量又突然往上跳時，把這篇拿出來再走一遍。

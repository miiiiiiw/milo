當 Loop Engineering 遇上 Jev Engineering：如何把 Claude 帳單從每月 765 美元降到 3 美元

替 Claude Code 做的 Jev 工程（jev engineering）：一道 100 毫秒的安全閘門、一個知道工作何時真正完成的 Stop hook，以及一個只在有東西要修時才叫醒 Claude 的分類（triage）過濾器。完整程式碼、實際做法，還有帳單。

讓一個 Claude 迴圈整夜運轉，早上再讀它的紀錄稿（transcripts）。大多數回合都以一個小問題開頭。這個指令安全嗎？下一個是哪個檔案？那個測試輸出有什麼意義嗎？目標達成了嗎，還是該繼續？

每一個這樣的問題，都丟給了那個幫你寫程式碼的同一個模型。在 Fable 5.1 上，針對 4,000 token 的狀態（state）做一次是非判斷，大約要 4 美分，還要花上好幾秒。

一個忙碌的迴圈一晚大約要問 600 個這種問題，結果花在「做決定」上的錢，比花在「建造」上的還多。

9 月 15 日，TypeSafe AI 推出了 Jev，一個只負責做決定的模型。它寫不出一個句子。它讀取你的狀態（state），回答有型別的問題，並在每個答案後附上一個機率，通常大約 100 毫秒就完成。輸入每百萬 token 0.042 美元，輸出免費。

把它放在 Claude 旁邊，分工就很清楚：Claude 負責建造，Jev 負責判斷。把迴圈裡的每一個判斷都從 Claude 移到 Jev，就是大家開始稱為 Jev 工程的做法，而它可以直接接上 Claude Code 既有的 hooks。

1／只回答問題的模型1/ The Model That Only Answers Questions

Jev 出自 Diogo Almeida 之手，他是 InstructGPT 的共同作者——這項研究教會了 GPT-3 遵循指令，後來成為 ChatGPT 的基礎。TypeSafe 結束隱身模式（stealth）時，宣布完成由 DCVC 領投的 4,000 萬美元種子輪（seed）。

原文此處嵌入 Diogo Almeida（@CompleteSkeptic）2026-09-16（台北時間）的發表貼文：https://x.com/CompleteSkeptic/status/2099925682726002904。貼文開頭寫道：「在共同發明 ChatGPT 之後，我一直問自己：為什麼超越人類的聊天模型沒有帶來 AGI？」並宣布推出 Jev（號稱快 20–200 倍、便宜 40–400 倍、輸出 token 免費）。

對迴圈來說最重要的特性是校準（calibration）。TypeSafe 用 RLCD（reinforcement learning for calibrated decisions，針對校準（calibration）決策的強化學習（reinforcement learning））來訓練 Jev，當機率與現實相符時就給予獎勵。

當 Jev 說 0.9，放到你所有資料上看，它大約十次對九次。以人類評分訓練的聊天模型，則會漸漸偏向「聽起來很有把握」。一個經過校準（calibration）的數字，才是你的程式碼能在凌晨 3 點、沒人盯著時據以行動的東西。

在 TypeSafe 自己的工作流程評測（evals）中，Jev 比 GPT-6 Astra 和 Fable 5.1 的平均快 193.6 倍、便宜 444.6 倍。

公司說這些數字是預期範圍的上限。就算只拿十分之一，任何整夜運轉的迴圈帳單還是會不一樣。

Claude Code 團隊的迴圈指南，把每個迴圈都歸結成兩個問題：什麼啟動一次執行，什麼結束它。這兩者之間，還有一道對工作的檢查。三者都是決定，而在預設設定下，全都由 Claude 自己回答。

Jev 工程把最右邊那一欄從 Claude 身上移走。Claude 保留需要文字的工作：程式碼、計畫、說明。每一次啟動、停止和把關，都變成一次有型別、十分之一秒就回來的呼叫。

下面三個實作，涵蓋了最花錢的三種決定：安全閘門、停止條件和觸發器。

3／實作一：替每個 Bash 指令加一道 100 毫秒的安全閘門3/ Build One: A 100-ms Safety Gate for Every Bash Command

Claude Code 會在每一次工具呼叫前執行 PreToolUse hook。這個 hook 從 stdin 以 JSON 收到這次呼叫，回答 allow（允許）、deny（拒絕）或 ask（詢問）。把 Jev 放進去，每個指令在執行前都會先被分類。

.claude/hooks/jev_gate.py（英文原文）

#!/usr/bin/env python3
# .claude/hooks/jev_gate.py
import json, sys
from typesafe_sdk import Choice, TypeSafeClient

event = json.load(sys.stdin)
cmd = event["tool_input"].get("command", "")

def answer(decision, why):
    print(json.dumps({"hookSpecificOutput": {
        "hookEventName": "PreToolUse",
        "permissionDecision": decision,
        "permissionDecisionReason": why}}))
    sys.exit(0)

# exact rules stay in code, Jev never sees these
for pattern in ("rm -rf /", "git push --force", "| sh", "| bash"):
    if pattern in cmd:
        answer("deny", f"blocked by rule: {pattern}")

r = TypeSafeClient(model="jev-1.13.0").system_one(
    state={"command": cmd, "cwd": event.get("cwd")},
    questions={"risk": Choice(
        instructions="What happens if `command` runs inside `cwd`?",
        criteria={
            "read_only": "Only reads, lists, searches files or runs tests",
            "local_edit": "Changes files inside the project that git can restore",
            "destructive": "Deletes data, rewrites git history or touches files outside the project",
            "external": "Sends data out, pushes, deploys, installs from the internet or spends money",
            "other": "None of the above fits",
        })},
)
a = r.answers["risk"]
if a.choice in ("read_only", "local_edit") and a.confidence >= 0.9:
    answer("allow", f"jev: {a.choice} {a.confidence:.2f}")
if a.choice == "destructive" and a.confidence >= 0.9:
    answer("deny", f"jev: destructive {a.confidence:.2f}")
answer("ask", f"jev: {a.choice} {a.confidence:.2f}")

有三個細節，讓它可以放心整夜運轉。硬性規則在 Jev 之前就由程式碼執行，因為 Jev 會相信狀態（state）裡的任何文字，而指令是可以被刻意寫來誤導分類器的。

任何對外的動作，不論信心值（confidence）多高，一律交給你決定。而 other 永遠不會被自動核准。

忙碌的一晚有 300 次 bash 呼叫，每次約 500 token，總共 150,000 token。用 Jev，整晚只要 0.0063 美元。

LangChain 使用者可以直接拿到現成的同款閘門：langchain-typesafe 的 AutoModeMiddleware 會在每次工具呼叫執行前檢查風險。

4／實作二：一個知道 Claude 何時完成的 Stop hook4/ Build Two: A Stop Hook That Knows When Claude Is Done

以目標為基礎的迴圈，成敗全看停止條件。迴圈指南裡最關鍵的警告在這裡也適用：一個評分自己工作的代理（agent），往往會稱讚自己。Claude 說「完成了」，測試也通過了，但 README 描述的還是上週的參數。

每次 Claude 想結束時，Claude Code 都會執行 Stop hook。如果 hook 回答 block 並附上理由，Claude 就會繼續工作。精確的部分交給程式碼，測試看不到的部分交給 Jev 判斷。

.claude/hooks/jev_done.py（英文原文）

#!/usr/bin/env python3
# .claude/hooks/jev_done.py - runs every time Claude tries to stop
import json, subprocess, sys
from pathlib import Path
from typesafe_sdk import Noul, TypeSafeClient

counter = Path(".claude/.pushes")
pushes = int(counter.read_text()) if counter.exists() else 0

def let_stop():
    counter.unlink(missing_ok=True)
    sys.exit(0)

def keep_going(reason):
    counter.write_text(str(pushes + 1))
    print(json.dumps({"decision": "block", "reason": reason}))
    sys.exit(0)

if pushes >= 5:                                        # turn cap lives in code
    let_stop()

checks = subprocess.run(["bash", ".claude/checks.sh"], capture_output=True, text=True)
if checks.returncode != 0:                             # failing tests need no model
    keep_going("checks.sh fails. Fix the failing checks, then try to finish again.")

r = TypeSafeClient(model="jev-1.13.0").system_one(
    state={"goal": Path("GOAL.md").read_text(), "checks": checks.stdout[-20_000:]},
    questions={"done": Noul(
        instructions="Does `checks` show evidence for every condition listed in `goal`?")},
)
done = r.answers["done"].noul

if done >= 0.9:
    let_stop()
if done >= 0.5:                                        # unsure: stop and flag it
    Path("REVIEW.md").write_text(f"jev put done at {done:.2f}\n\n{checks.stdout[-3000:]}")
    let_stop()
keep_going(f"Goal not met (jev: {done:.2f}). Compare GOAL.md with the output "
           "of .claude/checks.sh and finish the missing conditions.")

checks.sh 是你印出證據的地方：測試結果、在變更過的檔案中 grep 出的 TODO、README 的 diff、Lighthouse 分數。

證據越豐富，Jev 判斷得越好，而它只看得到腳本印出來的東西。

每次檢查只花不到一美分的零頭，而且在 Claude 察覺之前就回來了。迴圈會在工作真正完成時停下——這正是以目標為基礎的迴圈的全部承諾。

5／實作三：只在有工作時才叫醒 Claude5/ Build Three: Only Wake Claude When There's Work

/loop 15m: triage new issues 這樣可以運作，但每一次觸發都是一個完整的 Claude 回合，包括什麼事都沒發生的那幾次。在它前面放一個跑 Jev 的 cron 工作，Claude 就只會在需要寫程式碼的項目上啟動。

triage.py（英文原文）

#!/usr/bin/env python3
# triage.py - cron: */10 * * * *
import json, subprocess
from typesafe_sdk import Choice, TypeSafeClient

jev = TypeSafeClient(model="jev-1.13.0")
gh = lambda *a: subprocess.run(["gh", *a], capture_output=True, text=True).stdout

KINDS = {
    "code_fix": "A reproducible bug with steps, an error message or a failing case",
    "question": "The author asks how to use something that already works",
    "junk": "Repeats a known issue, advertises something or has no real content",
    "feature": "Asks for new behavior",
    "other": "None of the above fits",
}

for it in json.loads(gh("issue", "list", "--label", "new", "--json", "number,title,body", "--limit", "30")):
    a = jev.system_one(state={"issue": it}, questions={"kind": Choice(
        instructions="What does `issue` need from the maintainers?", criteria=KINDS)}).answers["kind"]
    label = a.choice if a.confidence >= 0.9 and a.choice != "other" else "needs-human"
    gh("issue", "edit", str(it["number"]), "--remove-label", "new", "--add-label", label)
    if label == "code_fix":
        subprocess.run(["claude", "-p", "--permission-mode", "acceptEdits",
                        f"Fix issue #{it['number']}. Reproduce it, add a failing test, "
                        "make it pass and open a draft PR."])

6／帳單6/ The Bill

一個整夜運轉的迴圈，200 個回合，每回合三個決定：安全嗎、下一步是什麼、完成了嗎。共 600 個決定，每個都讀約 4,000 token 的狀態（state），輸出 50 token。以牌價計算，30 個晚上。

Fable 5.1 的快取讀取（cache reads）只要四分之一價格，能讓它那一欄降到接近 225 美元，但仍是 Jev 帳單的 75 倍。

Claude 花在建造上的費用不變。上面那些全是 Jev 幫你省掉的額外開銷。

在 Max 方案上，效果會反映在用量上限（usage limits）而不是金額上：Claude 過去花在判斷上的回合，回到了真正的工作上。

7／大家已經做出了什麼7/ What People Have Already Built

  • Claude 工作階段的壓縮（Compaction for Claude sessions）：tamara 的即時壓縮（instant compaction）會問 Jev，一個工作階段裡哪些工具呼叫仍然相關。在 Alex Volkov 的測試中，一個 Claude 工作階段在大約一秒內從將近 100 萬 token 降到 86K。對於很長的 Claude Code 工作階段，這是最該先照著做的實作。
  • 逐步的電腦操作（Computer use, step by step）：awlevin 用 Jev 選擇桌面任務的每一步：每次決定 0.0002 美元，相較之下 Opus 5 要 0.032 美元；耗時 0.13 到 0.38 秒，相較之下是 5.2 秒。
  • 瀏覽器代理（Browser agents）：Browser Use 的 jev-ultrafast 每一步都會從一份新的清單中挑出下一個動作和元素。它在 7.1 秒內、花 0.0039 美元，找到了從蘇黎世飛往倫敦的航班。
  • 大量分類（Sorting at volume）：1kpapers.com 以 0.08 美元、中位數 256 毫秒，把 1,018 篇論文歸入 24 個主題。Riley Brown 用 3.5 美分分類了 500 封電子郵件。
  • 交易（Trading）：Jarrod Watts 的 jev-trader 每個區塊做一次決定，模型延遲（latency）約 81 毫秒。

每個實作都是同一個形狀。選項清單在每一步都從即時狀態（state）重建，Jev 挑一個，接下來的事交給程式碼或更大的模型。

8／Jev 工程的七條規則8/ Seven Rules of Jev Engineering

  1. 意義寫在指示裡（Meaning lives in the instructions）：問題的 ID 從來不會送給模型，所以一個叫 is_safe 的鍵，對 Jev 毫無意義。
  2. 一個問題只問一個判斷（One judgment per question）：「這是破壞性的、而且在儲存庫之外嗎」是兩個問題。兩個都問，再用程式碼組合。
  3. 描述情況，不要描述情緒（Describe situations, not moods）：「刪除資料或改寫 git 歷史」是可以檢查的。「非常危險」則不是，而只用數字當等級更糟。
  4. 每個 Choice 都要有出口（Give every Choice an exit）：other 會接住不符合的情況，讓不確定性保持誠實。
  5. 所有問題一次問完（Ask everything in one call）：同一個請求裡的問題共用狀態（state）。在 TypeSafe 的測試中，針對同一份文件的 13 個問題一次問完，比分成 13 次呼叫便宜 12.2 倍、快 10 倍。
  6. 數學、日期和硬性規則留在程式碼裡（Keep math, dates and hard rules in code）：Jev 把日期當文字讀，量一大就會數錯。在程式碼裡算好，再把結果傳進去。
  7. 鎖定版本，先跑影子模式（Pin the version and shadow first）：門檻（threshold）調好之後，用 jev-1.13.0，不要用 jev-latest。先跑一週由 Jev 貼標籤、但由舊流程做決定，再開啟那些對得上的信心值（confidence）區間。

9／錢在哪裡9/ Where the Money Is

  • 替 Claude Code 團隊做迴圈稽核（Loop audits for Claude Code teams）：讀一個團隊的紀錄稿（transcripts），列出每一個判斷，把它們移到 Jev，再交出改善前後的帳單。第 6 節那張表，換成他們的數字重做一次，就是整套銷售話術。
  • 給小型開發團隊的 hook 套件（Hook packs for small dev teams）：架好閘門、Stop hook 和分類（triage）的 cron，然後按月收取顧問費（retainer），根據紀錄調整門檻（threshold）。每個讓 Claude Code 整夜運轉的團隊，都需要同樣這三樣東西。
  • 你自己的迴圈（Your own loops）：同一個方案能做更多真正的工作。當 Claude 的回合不再花在是非題上，同一份 Claude 訂閱就能撐得更久。

以下為譯者整理，非原文內容。

這篇在說什麼

讓 Claude 這類 AI 整夜自動工作時，它其實花很多錢在回答一堆「小是非題」：這個指令安全嗎？做完了嗎？要不要開工？作者主張把這些判斷交給一個叫 Jev 的專用模型——它不會寫字，只會回答選擇題並附上機率，又快又便宜。Claude 只負責真正需要寫字的工作。

文章附了三個可以直接用的實作：執行指令前的安全閘門、判斷「真的做完了沒」的停止檢查、只在有事要做時才叫醒 Claude 的分類器，並估算帳單能從每月約 765 美元降到約 3 美元。

為什麼值得學

就算你從不用 Jev，這篇也點出一個很實用的觀念：不是每個問題都需要最強的模型。很多自動化流程裡的步驟其實只是「選 A 或 B」，交給又大又慢的模型，等於請資深工程師整天幫你按「確定」。把判斷和建造分開，能同時省錢、省時間，也讓流程更可控。

你可以帶走的重點

1. 會算機率的判斷，才能放心交給程式

Jev 的賣點是校準（calibration）：它說 0.9，長期來看大約就是十次對九次。這讓你能寫出明確規則，例如「信心值（confidence）≥ 0.9 才自動放行，否則問人」。一般聊天模型則傾向「聽起來很有把握」，數字不能直接拿來當門檻（threshold）。

2. 硬性規則先用程式碼擋，AI 只處理灰色地帶

三個實作有共同結構：絕對不能做的（例如 rm -rf /、強制推送）先用程式碼直接拒絕；測試失敗就直接要求繼續，不必問模型；剩下需要「看情況」的部分才交給 Jev。對外的動作和「其他」類，一律交回給人。

3. 別讓 AI 自己宣布「做完了」

AI 評自己的作業，常常會給自己高分。Stop hook 的做法是：先跑檢查腳本印出證據，再請 Jev 判斷「證據是否涵蓋目標的每一項」。機率高就停、中間就停下並留一份 REVIEW.md 給人看、低就退回去繼續做，而且最多退回 5 次，避免無限迴圈。

4. 最便宜的 AI 回合，是根本不用開始的那一個

與其讓 Claude 每 15 分鐘醒來看一次有沒有事，不如先用便宜的分類（triage）把新議題分成「要修的錯誤／問題／垃圾／功能需求／交給人」，只有真正要寫程式碼的才叫醒 Claude。作者的例圖裡，30 個議題只觸發了 3 次 Claude。

5. 問題要問得「可檢查」

作者的七條規則裡，最通用的是：一個問題只問一件事；描述具體情況（「刪除資料或改寫 git 歷史」），不要用感覺（「非常危險」）；每個選擇題都留一個「其他」；日期和數學交給程式碼算；新門檻（threshold）先「影子模式（shadow）」跑一週，確認對得上再正式啟用。

怎麼開始

  1. 先讀一份自己 AI 流程的紀錄稿（transcripts），把所有「是非題」或「選擇題」型的步驟圈出來。
  2. 從風險最低的一個開始，例如自動分類新議題或郵件，先讓 Jev（或任何便宜的判斷模型）只貼標籤、不做決定。
  3. 觀察一週，看信心值（confidence）在哪個門檻（threshold）以上幾乎都對，再讓它自動處理那一段。
  4. 硬性禁令永遠寫在程式碼裡，不要交給任何模型判斷。

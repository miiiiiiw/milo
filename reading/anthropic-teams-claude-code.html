Anthropic 團隊如何使用 Claude Code

原文標題：How Anthropic teams use Claude Code

作者：Anthropic

原文：https://claude.com/resources/articles/how-anthropic-teams-use-claude-code

日期：2025-07-24

備註：繁體中文翻譯，僅供個人閱讀。

Anthropic 各團隊使用 Claude Code 的範圍很廣，從除錯正式環境（production）的問題、熟悉陌生的程式碼庫（codebase），到打造客製化的自動化工具都有。以下是他們的做法。

像 Claude Code 這樣的代理式程式開發（agentic coding）工具，能幫助開發者加快工作流程（workflow）、自動化重複性的任務，並處理複雜的程式專案。隨著這個領域不斷演進，我們每天都從使用者身上學到新的應用方式，其中也包括我們自己的員工。

為了進一步了解，我們訪談了 Anthropic 各個部門的員工，了解他們在工作中如何使用 Claude Code。

他們的許多使用情境在意料之中——除錯、瀏覽程式碼庫（codebase）、管理工作流程（workflow）——但也有一些讓我們驚訝。律師打造了電話語音選單（phone tree）系統。行銷人員在幾秒內產生數百種廣告變體。資料科學家不懂 JavaScript，也做出了複雜的視覺化。

規律逐漸清晰：代理式程式開發（agentic coding）不只是在加速傳統的開發工作。它正在消弭技術工作與非技術工作之間的界線，讓任何能描述問題的人，都成為能打造解決方案的人。

以下是我們的發現。

瀏覽與理解程式碼庫Codebase navigation and understanding

公司各團隊用 Claude Code 幫助新進員工，甚至資深員工，快速熟悉我們的程式碼庫（codebase）。

我們基礎設施（Infrastructure）團隊的新進資料科學家，會把整個程式碼庫（codebase）餵給 Claude Code，好快速上手。Claude 會讀取該程式碼庫（codebase）的 CLAUDE.md 檔案、找出相關的檔案、說明資料管線（data pipeline）的相依關係，並指出哪些上游來源會流入儀表板，取代了傳統的資料目錄（data catalog）工具。

我們產品工程（Product Engineering）團隊把 Claude Code 稱為任何程式任務的「第一站」。他們請它找出在修復錯誤、開發功能或做分析時該檢視哪些檔案，省去了在開發新功能之前、手動蒐集脈絡（context）這段耗時的過程。

測試與程式碼審查Testing and code review

代理式程式開發（agentic coding）工具特別受歡迎，是因為它們能自動化兩項重要卻繁瑣的程式任務：撰寫單元測試（unit tests）與審查程式碼。

產品設計（Product Design）團隊用 Claude Code 為新功能撰寫完整的測試。他們透過 GitHub Actions 把合併請求（Pull Request）的留言自動化，由 Claude 自動處理格式問題與測試案例的重構（refactoring）。

安全工程（Security Engineering）團隊把他們的工作流程（workflow）從「設計文件 → 粗糙拼湊的程式碼 → 重構（refactor）→ 放棄寫測試」，轉變成請 Claude 先寫虛擬碼（pseudocode）、引導它以測試驅動開發（test-driven development）的方式進行，並定期檢查進度。這讓程式碼更可靠、也更容易測試。

代理式程式開發（agentic coding）也能把測試翻譯成其他程式語言。例如，推論（Inference）團隊需要用自己不熟的語言（如 Rust）測試功能時，只要說明想測什麼，Claude 就會用程式碼庫（codebase）原生的語言寫出測試邏輯。

除錯與疑難排解Debugging and troubleshooting

正式環境（production）的問題需要快速解決，但在壓力下去推敲不熟悉的程式碼，往往會造成延誤。對公司裡許多團隊而言，Claude Code 會即時分析堆疊追蹤（stack traces）、文件與系統行為，加快診斷與修復。

發生事故（incident）時，安全工程團隊會把堆疊追蹤（stack traces）與文件餵給 Claude Code，讓它在程式碼庫（codebase）中追蹤控制流程（control flow）。這類問題原本通常要手動掃描 10 到 15 分鐘，現在的解決速度是原來的 3 倍。

有了 Claude Code，產品工程團隊有信心去處理不熟悉的程式碼庫（codebase）裡的錯誤。他們問 Claude：「你可以修好這個錯誤嗎？這是我看到的行為」，然後審閱它提出的解法，不需要靠其他工程團隊協助。

有一次，Kubernetes 叢集（cluster）不再排程 Pod，資料基礎設施（Data Infrastructure）團隊用 Claude Code 診斷問題。他們把儀表板截圖餵給它，Claude 便一個選單接一個選單地帶著他們操作 Google Cloud 的使用者介面（UI），直到找出 Pod IP 位址耗盡的原因。接著 Claude 提供了建立新 IP 集區（pool）並加入叢集（cluster）的確切指令，在系統中斷（outage）期間為他們省下 20 分鐘的寶貴時間。

原型設計與功能開發Prototyping and feature development

開發新功能傳統上需要深厚的技術知識與大量的時間投入。Claude Code 能做到快速製作原型（prototyping），甚至完整的應用程式開發，讓團隊不論程式能力高低，都能快速驗證想法。

產品設計團隊的成員會把 Figma 設計檔餵給 Claude Code，再建立自主迴圈（autonomous loops）：由 Claude Code 為新功能寫程式、執行測試，並持續迭代（iterate）。他們給 Claude 抽象的問題、讓它自主運作，最後在做最終修飾之前審閱解法。有一次，他們讓 Claude 在幾乎沒有人工審閱的情況下，為自己打造 Vim 按鍵綁定（key bindings）。

有了 Claude Code，產品設計團隊發現了一種意想不到的用法：梳理錯誤狀態（error states）、邏輯流程（logic flows）與系統狀態（system statuses），在設計階段就找出邊界情況（edge cases），而不是等到開發時才發現。這從根本上提升了他們最初的設計品質，也為日後省下數小時的除錯時間。

儘管資料科學家並不熟悉 TypeScript，他們仍用 Claude Code 打造完整的 React 應用程式，用來視覺化強化學習（RL）模型的表現。在沙箱（sandbox）環境中進行單次提示（one-shot prompting）之後，這個工具會從零寫出完整的 TypeScript 視覺化，而他們自己並不理解那些程式碼。由於任務很單純，如果第一次的提示不夠用，他們就稍微調整後再試一次。

譯註：原文這句的主詞有些含糊（「without understanding the code themselves」），這裡依上下文理解為資料科學家自己不理解那些程式碼。

文件與知識管理Documentation and knowledge management

技術文件常常散落在 wiki、程式碼註解，以及團隊成員的腦袋裡。Claude Code 透過 MCP 與 CLAUDE.md 檔案，把這些知識整合成容易取用的形式，讓需要的人都能取得專業知識。

推論團隊中沒有機器學習（ML）背景的成員，會靠 Claude 解釋模型專屬的函式。這件事原本通常要花一小時上 Google 搜尋，現在只要 10 到 20 分鐘——研究時間減少了 80%。

安全工程團隊讓 Claude 讀入多個文件來源，產生 Markdown 格式的維運手冊（runbooks）與疑難排解指南。這些精簡過的文件會成為除錯真實正式環境（production）問題時的脈絡（context），通常比翻遍完整的知識庫（knowledge bases）更有效率。

自動化與工作流程最佳化Automation and workflow optimization

代理式程式開發（agentic coding）工具能幫助團隊打造客製的自動化，這在過去通常需要專屬的開發人力，或昂貴的軟體。

成長行銷（Growth Marketing）團隊打造了一套 AI 代理工作流程（agentic workflow），能處理包含數百則廣告的 CSV 檔案、找出表現不佳的廣告，並在嚴格的字元數限制內產生新的變體。這個系統使用兩個專門的子代理（subagents），能在幾分鐘內產生數百則新廣告，而不是花上數小時。

他們還開發了一個 Figma 外掛（plugin），能辨識畫框（frames），並以程式方式替換標題與描述文字，最多產生 100 種廣告變體，把原本要花上數小時的複製貼上，縮減為每批廣告半秒鐘。

在一個特別獨特的使用情境中，法務（Legal）團隊打造了原型（prototype）版的電話語音選單（phone tree）系統，幫助同事聯繫到 Anthropic 裡合適的律師，示範各部門即使沒有傳統的開發資源，也能打造客製化的工具。

用 Claude Code 解鎖新的可能Unlocking new possibilities with Claude Code

這些故事揭示了一個規律：當你專注在 Claude Code 能夠增強的人類工作流程（workflows）上時，它的效果最好。最成功的團隊把 Claude Code 當成思考夥伴（thought partner），而不是程式碼產生器。

他們探索各種可能性、快速製作原型（prototype），並在技術與非技術的使用者之間分享發現。這種人與 AI 協作的方式，創造出我們才剛開始理解的機會。

以下為譯者整理，非原文內容。

這篇在說什麼

Anthropic 訪談了自家各部門的員工，整理出大家怎麼用 Claude Code（Anthropic 的程式開發 AI 代理工具）：熟悉程式碼、寫測試、除錯、做原型、整理文件、做自動化。文章也提到，律師、行銷人員、資料科學家這些不是專職工程師的人，也用它做出了自己需要的工具。

文章依序介紹六類用法，每一類都附上具體團隊的做法，最後用一個結論收尾：把 Claude Code 當成思考夥伴，而不是只會產生程式碼的工具。

為什麼值得學

你不必會寫程式，也能從中學到「怎麼向 AI 代理交辦事情」：把你手上的線索（錯誤訊息、截圖、設計檔、文件）直接交給它，用白話描述你要什麼，第一次不夠好就微調再試。讀的時候留意一點：文中的「快 3 倍」「省下 20 分鐘」「研究時間減少 80%」都是各團隊的自述，原文沒有說明怎麼量測，也沒有附對照資料，當作參考經驗就好。

你可以帶走的重點

1. 把它當思考夥伴，從「它能幫上忙的人工流程」下手

原文結論說，Claude Code 在你專注於它能增強的人類工作流程（workflows）時效果最好，最成功的團隊把它當思考夥伴（thought partner），而不是程式碼產生器。他們探索可能性、快速做出原型（prototype），並在技術與非技術的同事之間分享發現。

例：成長行銷（Growth Marketing）團隊把「處理數百則廣告、找出表現不佳的、產生新變體」做成 AI 代理工作流程（agentic workflow），法務（Legal）團隊做出電話語音選單（phone tree）原型。

2. 面對陌生的東西，先問它

原文有兩種「先問它」：一是進入陌生的程式碼庫（codebase）時，產品工程（Product Engineering）團隊把 Claude Code 當成「第一站」，請它指出該看哪些檔案，省去手動蒐集脈絡（context）的時間；二是遇到不熟的領域時，推論（Inference）團隊中沒有機器學習（ML）背景的人，請 Claude 解釋模型專屬的函式，原本要花一小時搜尋，現在只要 10 到 20 分鐘。

例：基礎設施（Infrastructure）團隊的新進資料科學家把整個程式碼庫（codebase）交給它，請它說明資料管線（data pipeline）的相依關係。

3. 請它先寫草案，再一步步檢查，不要一次交出全部

安全工程（Security Engineering）團隊以前的流程是「設計文件、粗糙拼湊的程式碼、重構、放棄寫測試」，現在改成請 Claude 先寫虛擬碼（pseudocode），引導它以測試驅動開發（test-driven development）的方式進行，並定期檢查進度，程式碼因此更可靠、也更容易測試。

4. 出狀況時，把手上看得到的線索都餵給它

原文的例子是 Kubernetes 叢集（cluster）不再排程 Pod：資料基礎設施（Data Infrastructure）團隊把儀表板截圖餵給 Claude Code，它帶著他們一個選單接一個選單地操作 Google Cloud 介面，找出 Pod IP 位址耗盡，再給出建立新 IP 集區並加入叢集的確切指令，在系統中斷期間省下 20 分鐘。安全工程團隊也是在事故（incident）時把堆疊追蹤（stack traces）與文件餵給它。

怎麼開始

  1. 挑一件你每週重複做、又很耗時的事，像原文裡處理廣告的行銷團隊那樣，先用一句白話說清楚「問題是什麼」。
  2. 把手邊的資料（檔案、截圖、錯誤訊息、文件）一起交給 Claude Code，請它先做出第一版。
  3. 第一版不夠好，就稍微調整你的描述再試一次，原文的資料科學家就是這樣做的。
  4. 遇到不熟的東西，先問它「該從哪裡看起」，再自己決定要不要深入。
  5. 做出有用的成果，就分享給同事，包括不寫程式的同事。原文說，這種跨技術與非技術使用者的分享，是最成功團隊的共通做法。

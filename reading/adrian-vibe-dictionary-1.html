Vibe Coding 視覺詞典（上篇）：布局、頁面結構、導覽與常用元件

作者：Adrian Punk（@AdrianPunk115）

原文：https://x.com/AdrianPunk115/status/2084538166577602899

備註：原文為簡體中文，已轉為台灣用語繁體中文；繁體中文翻譯，僅供個人閱讀。

很多人讓 AI 做網頁時，只會說：

幫我做一個高級、簡潔、有設計感的網站。

問題在於，「高級」「簡潔」「有設計感」都不是明確的網頁結構。AI 不知道內容應該怎麼排，也不知道使用者應該怎麼瀏覽和操作。

一個完整網頁可以先拆成四層：

  • 頁面布局 Layout：頁面上的內容怎麼排。
  • 頁面結構 Page Structure：使用者先看到什麼，接著看到什麼。
  • 導覽 Navigation：使用者如何移動、跳轉和切換。
  • 元件 UI Components：使用者如何點選、展開、輸入和獲得回饋。

下面所有範例都以 Punk 的個人網站為例子。每個詞條只保留三部分：概念說明、適用情境、可直接複製給 AI 的提示詞。

第一章：頁面布局 Layout

頁面布局決定內容如何佔據螢幕：是整齊排列、錯落排列、左右分割畫面，還是由大小不同的模組組成。它回答的是「頁面上的東西怎麼排」。

1. 卡片式布局 Card-based Layout

把內容拆成一張張獨立卡片，每張卡片承載一個專案、一篇文章、一項服務或一組資訊。卡片之間邊界清楚，瀏覽速度快，也是 AI 最容易穩定實作的布局之一。

適合：作品集、部落格列表、功能介紹、工具導覽、商品列表、個人首頁。

提示詞（可直接複製給 AI）

為 Punk 的個人網站建立一個響應式卡片式布局，
專案區展示 6 張獨立卡片，每張卡片包含專案封面、專案名稱、兩行簡介、技術標籤和「查看專案」按鈕；
桌面版三欄，平板版兩欄，手機版單欄；
使用米白背景、深綠色強調色、細邊框、克制圓角和輕微陰影。

2. 瀑布流 Masonry Layout

卡片寬度大致一致，但高度不統一，內容像瀑布一樣自然錯落。它不會強迫每一列嚴格對齊，因此特別適合不同尺寸的圖片和視覺作品。

適合：AI 生圖作品集、攝影集、靈感牆、案例封面、視覺型部落格。

提示詞（可直接複製給 AI）

為 Punk 建立一個瀑布流作品畫廊，
使用三欄 Masonry Layout 展示不同寬高比的 AI 作品，保留圖片原始比例，不要裁切成統一高度；
桌面版三欄，平板版兩欄，手機版單欄；
圖片進入視口附近時再載入，點選後開啟全螢幕預覽。

3. 便當盒布局 Bento Grid

用大小不同的矩形模組組成頁面。最大的區域負責展示核心內容，小模組放技能、文章、聯絡方式、數字或狀態，依靠尺寸差異建立視覺優先順序。

適合：個人首頁、產品首頁、SaaS 首頁、創作者網站、AI 工具展示頁。

提示詞（可直接複製給 AI）

為 Punk 設計一個 Bento Grid 個人首頁，
左側使用一張大型 Hero 卡片展示姓名、身份介紹和主要按鈕，右側使用大小不同的模組卡片展示 About、Skills、Latest Writing 和 Contact，底部放一張橫向 Featured Project 卡片；
不要做成平均九宮格，要透過模組大小突出主次關係。

4. 分割畫面布局 Split-screen Layout

把頁面分成左右兩部分，常見形式是左邊文字、右邊視覺，或者一邊固定、另一邊捲動。它能讓資訊和視覺同時成為主角。

適合：個人首頁、產品介紹、登入頁、創意作品集、對比頁面。

提示詞（可直接複製給 AI）

為 Punk 的個人首頁設計一個 Split-screen Hero，
左側佔 45%，展示姓名、身份、簡介和兩個操作按鈕，右側佔 55%，
展示抽象的網頁介面與空間化視覺；
桌面版保持左右分割畫面，手機版改為上下結構，文字在前、視覺在後。

5. CSS 網格布局 CSS Grid Layout

按照明確的列與欄組織頁面，適合處理二維關係。它可以讓不同模組佔據不同欄寬，建構規則或非對稱的複雜頁面。

適合：複雜首頁、雜誌排版、Dashboard、非對稱作品集、響應式模組。

提示詞（可直接複製給 AI）

使用 CSS Grid 建構 Punk 的作品頁面，
桌面版採用 12 欄網格，主專案佔 8 欄，專案說明佔 4 欄，其餘專案每張佔 4 欄；
900px 以下改為 6 欄，640px 以下改為單欄；
使用 grid-template-columns 和 gap，不要用絕對定位硬拼布局。

6. 彈性布局 Flexbox

讓一組元素沿一個主要方向排列，最適合處理一列或一欄中的對齊、間距和順序。它常出現在導覽列、按鈕組和卡片內部。

適合：頂部導覽、工具列、按鈕組、標籤、頭像與文字組合、卡片內部。

提示詞（可直接複製給 AI）

Punk 網站的頂部導覽使用 Flexbox，左側顯示 Punk Logo，右側顯示 Work、About、Writing、Contact 和主題切換按鈕；
使用 justify-content: space-between 和 align-items: center，
小螢幕時隱藏文字導覽並顯示 Hamburger Menu。

7. 側邊欄布局 Sidebar Layout

頁面一側長期保留一條欄，另一側顯示主要內容。側邊欄可以承載個人資訊、分類、目錄、篩選器或後台導覽。

適合：部落格、文件網站、後台、作品歸檔、設定頁。

提示詞（可直接複製給 AI）

為 Punk 的 Journal 頁面新增左側 Sidebar，寬度為 260px，
包含頭像、個人簡介、文章分類、標籤和社群連結，右側為文章列表；
桌面版側邊欄保持 Sticky，手機版把側邊欄內容摺疊到頂部篩選按鈕中。

8. 儀表板布局 Dashboard Layout

通常由側邊導覽、頂部工具列、統計卡片、圖表、表格和最近活動構成，強調資訊密度與任務效率。

適合：個人內容後台、專案管理、數據產品、CMS、AI 工具控制台。

提示詞（可直接複製給 AI）

為 Punk 製作一個個人創作後台 Dashboard，
左側導覽包含 Overview、Projects、Writing、Analytics 和 Settings，
頂部包含搜尋框、通知和頭像，主內容區展示 4 張統計卡片、最近專案列表和造訪趨勢圖；
桌面版側欄固定，手機版轉換為 Drawer。

9. 響應式布局 Responsive Layout

同一個網頁根據螢幕尺寸重新排列，而不是把桌面頁面整體縮小。桌面、平板和手機應該有不同的布局狀態。

適合：幾乎所有公開網頁。

提示詞（可直接複製給 AI）

讓 Punk 的個人網站完全響應式，設定 desktop、tablet、mobile 三種布局狀態；
桌面版內容最大寬度為 1200px，平板版卡片兩欄，手機版單欄並把頂部導覽改成 Hamburger Menu；
保證正文不出現橫向捲動，所有按鈕在觸控螢幕裝置上都有清晰點選區域。

10. 全出血布局 Full-bleed Layout

圖片、影片或顏色區域一直延伸到螢幕邊緣，不受普通內容容器限制。它常被用來製造沉浸式首屏或章節過渡。

適合：品牌首頁、作品開場、攝影網站、產品發布頁、沉浸式故事。

提示詞（可直接複製給 AI）

為 Punk 的首頁建立一個 Full-bleed Hero，
背景視覺鋪滿瀏覽器寬度並佔據 90vh，不受主內容 max-width 限制，
前景放置大標題、簡短介紹和 View Work 按鈕；
Hero 下方的正文重新回到 1120px 的居中容器，並保證文字與背景有足夠對比度。

第二章：頁面結構 Page Structure

頁面結構決定使用者先看到什麼、接著看到什麼，以及一個頁面如何講完一件事。它回答的是「內容按什麼順序出現」。

11. 單頁網站 Single-page Website

所有主要內容都放在同一頁面中，使用者透過捲動或錨點導覽瀏覽 Hero、About、Projects、Writing 和 Contact。

適合：個人名片、輕量作品集、活動頁、早期產品介紹、資訊量不大的官網。

提示詞（可直接複製給 AI）

為 Punk 製作一個單頁個人作品網站，頁面順序為 Hero、About、Selected Work、Writing、Contact 和 Footer；
頂部導覽透過 Anchor Links 跳轉到對應區塊，
使用平滑捲動但尊重 prefers-reduced-motion，每個區塊都設定清晰的 id 和語義化標題。

12. 多頁網站 Multi-page Website

不同內容擁有獨立頁面和網址，例如首頁、作品列表、專案詳情、關於、文章和聯絡頁面。它更適合長期擴充。

適合：成熟作品集、部落格、企業官網、內容站、專案較多的網站。

提示詞（可直接複製給 AI）

把 Punk 的網站設計為多頁網站，包含 Home、Work、Project Detail、About、Journal、Article 和 Contact；
所有頁面共享統一的 Header 與 Footer，
當前導覽項目顯示 active 狀態，專案卡片點選後進入獨立詳情頁。

13. 到達頁 Landing Page

圍繞一個明確目標組織頁面，使用者被引導完成註冊、購買、預約、下載或聯絡。頁面中的每一部分都服務於同一個行動。

適合：AI 產品、課程、活動、Newsletter、個人服務、作品發布。

提示詞（可直接複製給 AI）

為 Punk 的 AI 設計服務製作一個 Landing Page，唯一目標是引導訪客預約諮詢；
頁面包含 Hero、服務價值、工作流程、三個案例、客戶評價、FAQ 和最終 CTA，所有主要按鈕統一使用「預約一次溝通」，
不要加入與轉換目標無關的複雜導覽。

14. 案例研究頁 Case Study Page

不僅展示最終效果，還講清專案背景、問題、過程、關鍵決策、方案、結果和回顧。

適合：設計師作品集、開發者專案、產品專案、品牌案例、求職作品集。

提示詞（可直接複製給 AI）

為 Punk 建立一個專案案例研究頁，
包含專案概覽、背景問題、Punk 的職責、設計過程、關鍵決策、最終方案、結果數據和回顧；
頂部使用大封面，正文保持窄閱讀寬度，過程圖片可全寬穿插，桌面版右側提供 Sticky Table of Contents。

15. 首屏 Hero Section

使用者打開頁面最先看到的區域，負責快速回答你是誰、你做什麼、為什麼值得繼續看，以及下一步該點哪裡。

適合：幾乎所有首頁和 Landing Page。

提示詞（可直接複製給 AI）

為 Punk 的個人首頁建立一個清晰的 Hero Section，
主標題為「Punk designs and builds AI-native experiences.」，副標題控制在兩行以內，包含 View Work 和 Contact 兩個按鈕；
右側使用抽象、低飽和的網頁介面意象，不要使用辦公桌、家居產品或商業相簿人物。

16. 功能網格 Feature Grid

用三到六個並列模組介紹能力、服務或產品功能，每個模組通常包含圖示、標題和短說明。

適合：能力介紹、產品功能、服務清單、優勢展示。

提示詞（可直接複製給 AI）

在 Punk 的 About 區塊下方新增一個四欄 Feature Grid，四項內容為 Design、Frontend、AI Prototyping 和 Writing，每項包含一個線性圖示、標題和不超過兩行的說明；桌面版四欄，平板兩欄，手機單欄，避免誇張陰影。

17. 固定敘事區 Sticky Storytelling

一側內容固定，另一側隨著捲動依次出現不同階段，讓複雜過程像講故事一樣被閱讀。

適合：產品故事、專案過程、時間軸、複雜功能解釋、品牌敘事。

提示詞（可直接複製給 AI）

為 Punk 的專案詳情頁設計一個 Sticky Storytelling Section，桌面版左側 38% 區域保持 Sticky 並展示當前階段標題和說明，右側依次捲動展示 Discover、Design、Build 三個內容面板；當前階段進入視口時更新左側文字，手機版取消 Sticky 並改為正常縱向排列。

18. 時間軸 Timeline

用一條線和多個節點按時間順序展示經歷、版本、里程碑或專案進展。

適合：職業經歷、專案里程碑、產品版本、公司歷史、學習路徑。

提示詞（可直接複製給 AI）

在 Punk 的 About 頁面新增一條 Vertical Timeline，每個節點包含年份、事件名稱和兩行說明；桌面版內容位於時間軸右側，手機版保持單欄；使用細綠色線條和圓形節點，不要做成複雜路線地圖。

19. 常見問題 FAQ Section

把常見問題集中放在頁面末段，通常透過摺疊面板展開答案，幫助使用者快速消除疑慮。

適合：服務說明、產品定價、課程、合作流程、常見疑問。

提示詞（可直接複製給 AI）

在 Punk 的 Contact 頁面之前新增 FAQ Section，
包含 6 個問題，例如 Punk 接受什麼專案、合作週期多久、是否提供開發、如何開始合作；
答案預設摺疊，同一時間只允許開啟一個問題，使用原生 button 並正確設定 aria-expanded。

20. 頁尾 Footer

頁面最底部的收尾區域，用來承載網站導覽、社群連結、聯絡方式、版權資訊和訂閱入口。

適合：所有完整網站。

提示詞（可直接複製給 AI）

為 Punk 的個人網站設計一個完整 Footer，左側顯示 Punk Logo 和一句簡介，中間分為 Explore、Connect、Elsewhere 三組連結，
右側顯示電子郵件和 Newsletter 訂閱框，底部顯示版權與隱私連結；
使用深綠色背景和米白文字，與頁面主體形成明確收尾。

第三章：導覽與切換 Navigation

導覽決定使用者怎樣在頁面和內容之間移動。它回答的是「我在哪裡、我還能去哪裡、點選後會發生什麼」。

21. 固定導覽 Sticky Navbar

頁面向下捲動時，頂部導覽仍然保持可見，適合長頁面和需要頻繁跳轉的內容。

適合：長頁面、單頁網站、文件、Landing Page、作品集。

提示詞（可直接複製給 AI）

為 Punk 的網站新增 Sticky Navbar，
初始狀態使用透明背景，捲動超過 40px 後變為米白背景並增加細邊框和輕微 backdrop blur；
導覽高度保持穩定，行動版使用 Hamburger Menu。

22. 漢堡選單 Hamburger Menu

手機版右上角常見的三條橫線按鈕，點選後展開或滑出完整導覽。

適合：行動版網站、小螢幕介面、極簡導覽、導覽項目較少的網站。

提示詞（可直接複製給 AI）

Punk 網站在 768px 以下使用 Hamburger Menu，
右上角顯示三條橫線按鈕，點選後從右側滑出 Drawer，
包含 Home、Work、About、Writing 和 Contact；
開啟後鎖定背景捲動，支援 Esc 關閉、點選遮罩關閉和鍵盤焦點管理。

23. 麵包屑 Breadcrumb

在頁面頂部顯示層級路徑，例如「首頁 › 作品 › AI 工具 › 專案詳情」，幫助使用者理解當前頁面在網站結構中的位置。

適合：多層級網站、電商、部落格、文件、專案詳情頁。

提示詞（可直接複製給 AI）

在 Punk 的專案詳情頁頂部新增 Breadcrumb，
路徑為 Home › Work › AI Tools › Project Detail；
使用 nav aria-label="Breadcrumb" 和有序列表，
最後一項表示當前頁面，不設定連結，並新增 aria-current="page"。

24. 錨點跳轉 Anchor Link

點選導覽後不打開新頁面，而是移動到當前頁面中的指定區塊。

適合：單頁網站、長文章、Landing Page、文件目錄、頁面內目錄。

提示詞（可直接複製給 AI）

為 Punk 的單頁網站新增 Anchor Links，About、Work、Writing、Contact 分別連結到對應 section id；
點選後平滑捲動，到達區塊時預留 Sticky Header 高度，
並讓當前所在區塊對應的導覽項目顯示 active 狀態。

25. 標籤切換 Tabs

多個標籤共用同一塊內容區域，一次只顯示其中一個同等級檢視。

適合：內容分類、數據檢視、設定、作品分類、月度與年度圖表。

提示詞（可直接複製給 AI）

在 Punk 的作品區新增 Tabs，標籤為 All、Web、AI、Experiments，預設顯示 All；
切換標籤時只更新下方專案網格，不重新整理整個頁面；
使用 tablist、tab 和 tabpanel 語義，支援左右方向鍵切換並顯示清晰 active 狀態。

26. 側邊導覽 Sidebar Navigation

把主要導覽長期放在頁面左側或右側，適合入口較多、層級較深的系統。

適合：後台、文件、設定頁、複雜工具、個人內容管理。

提示詞（可直接複製給 AI）

為 Punk 的創作後台新增 Sidebar Navigation，
包含 Overview、Projects、Posts、Media、Analytics 和 Settings，當前頁面使用綠色背景和圖示強調，二級選單允許摺疊；
桌面版固定顯示，手機版收起為 Drawer。

27. 超級選單 Mega Menu

點選主導覽後展開一個面積較大的多欄選單，可以同時展示分類、子頁面和精選內容。

適合：內容很多的網站、產品矩陣、資源中心、複雜作品分類。

提示詞（可直接複製給 AI）

Punk 網站的 Work 導覽項目使用 Mega Menu，
展開後顯示 Projects、Experiments、Resources 三欄，並在右側增加一個 Featured Project 預覽；
選單透過點選開啟，不依賴 hover，支援鍵盤導覽和 Esc 關閉，手機版改為 Accordion Menu。

28. 底部導覽 Bottom Navigation

在手機螢幕底部長期顯示三到五個最重要的入口，適合需要頻繁切換核心區域的行動產品。

適合：行動版 Web App、Dashboard、內容工具、創作工具。

提示詞（可直接複製給 AI）

為 Punk 的行動版創作工具新增 Bottom Navigation，
固定在螢幕底部，包含 Home、Projects、Create、Notes 和 Profile，
當前項使用綠色填充圖示，並考慮 iPhone safe-area-inset-bottom；
桌面版不顯示該元件。

29. 分頁 Pagination

把長列表拆成多個固定頁面，使用者透過頁碼或上一頁、下一頁進行切換。

適合：部落格歸檔、搜尋結果、後台表格、作品列表、資料量較大的列表。

提示詞（可直接複製給 AI）

為 Punk 的 Journal 文章列表新增 Pagination，
每頁顯示 10 篇文章，底部顯示 Previous、頁碼和 Next，
當前頁具有明顯狀態，並在 URL 查詢參數中儲存頁碼，例如 ?page=2；
按鈕使用真實連結，便於重新整理、分享和返回。

30. 返回頂部 Back to Top

頁面捲動到一定距離後，右下角出現返回頂部按鈕，幫助使用者快速回到頁面開頭。

適合：長文章、長作品頁、文件、長列表。

提示詞（可直接複製給 AI）

為 Punk 的長篇文章頁新增 Back to Top 按鈕，
捲動超過 800px 後淡入顯示並固定在右下角，點選後返回頁面頂部；
按鈕提供 aria-label="返回頂部"，並在 reduced motion 模式下取消平滑動畫。

第四章：常用元件 UI Components

元件是頁面中的局部互動單元。它回答的是「點選、輸入、展開、關閉和回饋應該如何發生」。

31. 模態框 Modal

一個覆蓋在當前頁面之上的對話框，背景被遮罩，使用者需要先處理或關閉它才能回到頁面。

適合：聯絡表單、確認操作、登入、快速預覽、必須立即處理的任務。

提示詞（可直接複製給 AI）

Punk 網站點選 Contact 後開啟 Modal，
Modal 內包含姓名、電子郵件、專案類型和留言；
開啟時把鍵盤焦點移動到標題或第一個輸入框，關閉後把焦點返回觸發按鈕；
使用原生 dialog 和 showModal()，支援 Esc 關閉，並阻止背景內容被鍵盤存取。

32. 抽屜 Drawer

一個從螢幕左側、右側或底部滑出的面板，可以展示導覽、篩選、設定或詳情。

適合：行動版導覽、篩選、設定、詳情預覽、購物車、通知中心。

提示詞（可直接複製給 AI）

Punk 的專案列表點選卡片後，從右側開啟一個 Project Detail Drawer，桌面版寬度為 420px，
顯示封面、簡介、技術堆疊和造訪連結；
頁面主體仍然可見但不可操作，手機版讓 Drawer 從底部開啟並接近全螢幕。

33. 手風琴 Accordion

多組標題縱向排列，點選標題後展開或收起對應內容。

適合：FAQ、行動版選單、篩選器、課程目錄、分組說明。

提示詞（可直接複製給 AI）

為 Punk 的 FAQ 建立 Accordion，每個標題使用 button，
右側顯示加號或箭頭，展開時更新 aria-expanded，並透過 aria-controls 關聯內容面板；
同一時間只展開一個專案，動畫控制在 200ms 左右。

34. 氣泡提示 Tooltip

滑鼠懸停或鍵盤聚焦到圖示時，旁邊出現一小塊簡短說明。它只適合補充簡短資訊。

適合：圖示解釋、術語補充、按鈕名稱、圖表數據說明。

提示詞（可直接複製給 AI）

在 Punk 的專案卡片圖示上新增 Tooltip，滑鼠 hover 或鍵盤 focus 時顯示，
內容控制在一句話以內，Tooltip 不獲得獨立焦點，離開觸發元素或按 Esc 後消失；
不要只支援 hover，觸控螢幕裝置需要提供可理解的替代方式。

35. 輕提示 Toast

完成操作後在頁面角落短暫出現的狀態訊息，不會像 Modal 一樣中斷使用者。

適合：儲存、複製、發布、刪除、網路狀態和輕量操作回饋。

提示詞（可直接複製給 AI）

Punk 後台儲存文章後，在右上角顯示 Success Toast「文章已儲存」，
Toast 包含狀態圖示、文字和關閉按鈕，4 秒後自動消失；
錯誤 Toast 不要快速自動消失，並提供重試操作；
使用 aria-live 向輔助技術宣告狀態。

36. 輪播圖 Carousel

在有限空間中輪流展示多個專案，通常帶有左右箭頭、圓點指示和當前序號。

適合：精選專案、客戶評價、產品截圖、活動 Banner。

提示詞（可直接複製給 AI）

在 Punk 首頁新增 Featured Projects Carousel，
一次展示 1 個主專案和下一專案的一小部分預覽，提供 Previous、Next 按鈕和 01 / 05 序號；
預設不自動播放，支援觸控滑動和鍵盤操作，使用者啟用 reduced motion 時取消滑動動畫。

37. 圖片燈箱 Lightbox

點選縮圖後，在遮罩層上放大顯示原圖，並支援關閉、切換和查看標題。

適合：攝影、AI 作品、插畫、專案截圖、視覺作品集。

提示詞（可直接複製給 AI）

為 Punk 的 AI Gallery 新增 Lightbox，
點選縮圖後全螢幕顯示原圖，支援左右切換、Esc 關閉和圖片標題，開啟後鎖定背景捲動；
縮圖使用 button 或 link 觸發，所有圖片提供準確的 alt 文字。

38. 表單 Form

由輸入框、標籤、選擇器、核取方塊和提交按鈕組成，用來完成聯絡、訂閱、登入或設定等任務。

適合：聯絡、訂閱、登入、搜尋、預約、設定。

提示詞（可直接複製給 AI）

為 Punk 的 Contact 頁面建立一個符合無障礙的聯絡表單，
欄位包括 Name、Email、Project Type、Budget Range 和 Message；
每個輸入框都有可見 label，必填項和錯誤資訊清晰，
提交中顯示 loading 狀態，成功後顯示 Toast，並在確認提交成功前保留使用者輸入內容。

39. 命令面板 Command Palette

按下快捷鍵後彈出的快速搜尋與操作面板，使用者可以透過鍵盤跳轉頁面或執行命令。

適合：開發者工具、文件網站、複雜個人網站、Dashboard、效率工具。

提示詞（可直接複製給 AI）

為 Punk 的網站新增 Command Palette，使用者按 Command+K 或 Ctrl+K 後開啟，可以搜尋並執行 Go to Work、Open About、Read Journal、Toggle Theme 和 Contact Punk；支援上下方向鍵選擇、Enter 執行、Esc 關閉，並按頁面與操作分組顯示結果。

40. 浮動操作按鈕 Floating Action Button

固定在介面角落的主要操作按鈕，不隨內容滾走，通常代表新增、建立或快速聯絡。

適合：Dashboard、行動工具、創作應用、快速聯絡、主要新增操作。

提示詞（可直接複製給 AI）

在 Punk 的專案後台右下角新增 Floating Action Button，
使用加號圖示並固定在視口右下角，點選後展開 New Project、New Post 和 Upload Image 三個快捷操作；
按鈕不能遮擋底部導覽或重要內容，並考慮行動版安全區域。

一段可以直接複製的完整網頁提示詞

完整網頁提示詞（可直接複製給 AI）

請為 Punk 設計並實作一個響應式個人作品網站。

網站包含 Home、Work、Project Detail、About、Journal 和 Contact。

首頁使用 Split-screen Hero：左側展示 Punk 的姓名、身份介紹、簡介和主要按鈕，右側展示抽象的網頁介面與空間化視覺。Hero 下方使用 Bento Grid，展示 Featured Project、About、Skills、Latest Writing 和 Contact。

作品頁面使用響應式 Card-based Layout，桌面版三欄、平板版兩欄、手機版單欄；AI 圖片作品使用 Masonry Gallery，並保留不同圖片的原始寬高比。

專案詳情使用 Case Study Page，包含 Overview、Problem、Role、Process、Key Decisions、Solution、Outcome 和 Reflection，桌面版右側提供 Sticky Table of Contents。

桌面版使用 Sticky Navbar，行動版使用 Hamburger Menu 並從右側開啟 Drawer；專案詳情頂部顯示 Breadcrumb；單頁區塊使用 Anchor Links。

聯絡表單使用 Modal，作品圖片支援 Lightbox，儲存和複製操作使用 Toast，FAQ 使用 Accordion，站內快速跳轉使用 Command Palette。

整體使用米白背景、深綠色強調色和黑色正文，視覺元素採用低飽和抽象圖形、半透明網頁面板和空間層次；不要使用家居產品、辦公桌擺拍、商業相簿人物或卡通插畫。

所有頁面 Mobile-first，使用語義化 HTML、CSS Grid 和 Flexbox；互動元件支援鍵盤操作、清晰焦點狀態和螢幕閱讀器；尊重 prefers-reduced-motion；圖片設定 width、height 和 alt，首屏以下圖片使用 Lazy Loading。

這篇在說什麼

很多人請 AI 做網頁，只會說「幫我做一個高級、有設計感的網站」，結果常常不如預期。作者的看法是：AI 不是聽不懂美感，而是你沒給它明確的「零件名稱」。這篇整理了 40 個常見網頁詞彙，每個都附一句說明、適用情境，以及一段可以直接複製給 AI 的提示詞。

40 個詞分成四大類：頁面怎麼排（布局 Layout）、內容按什麼順序出現（頁面結構 Page Structure）、使用者怎麼移動（導覽 Navigation），以及點擊、展開、輸入後會發生什麼（元件 UI Components）。所有範例都用同一個虛構的「Punk 個人網站」示範。

為什麼值得學

用 AI 寫程式做網頁（Vibe Coding）時，最大的落差往往不是技術，而是「說不出自己要什麼」。知道一個東西叫「麵包屑（Breadcrumb）」或「抽屜（Drawer）」，你就能用一個詞代替一大段描述，AI 也更容易一次做對。

這份詞典也適合跟設計師、工程師溝通：大家共用同一套名稱，討論就不會停在「那個會從旁邊滑出來的東西」。

你可以帶走的重點

1. 「高級感」不是指令，零件名稱才是

形容詞讓 AI 自己猜；具體的版面與元件名稱，才能告訴它內容怎麼排、使用者怎麼操作。先想清楚要哪幾種零件，再談風格。

好比裝潢時只跟師傅說「要溫馨」，不如說「客廳一面書牆、餐桌靠窗、走道裝感應燈」。

2. 好提示詞有固定的骨架

細看作者的 40 段提示詞，幾乎都有同樣的結構：先點名用哪個元件、放在哪裡；再寫清楚裡面有什麼內容；接著說明桌機與手機分別怎麼呈現、怎麼互動；最後補上「不要做成什麼樣」。

3. 永遠交代「手機上怎麼辦」

原文幾乎每一段提示詞都分開寫桌機、平板、手機的樣子，例如「桌面版三欄、平板兩欄、手機單欄」、「手機版改成漢堡選單」。不寫，AI 很可能只把桌機版縮小。

4. 選對元件，等於選對使用者的操作方式

同樣是「多顯示一些資訊」，彈出視窗（Modal）會打斷使用者、要他先處理；抽屜（Drawer）從旁邊滑出、不離開原頁；工具提示（Tooltip）只放一句話；輕提示（Toast）幾秒後自己消失。先想「使用者此刻該不該被打斷」，再挑元件。

5. 寫出「不要什麼」，跟寫出「要什麼」一樣重要

作者常在最後加一句限制：「不要做成平均九宮格」、「不要使用辦公桌擺拍或卡通插畫」、「不要只支援 hover」。這能擋掉 AI 最常見的預設套路。

怎麼開始

  1. 先挑一個你想做的頁面，例如個人作品集首頁。
  2. 從四層各挑一兩個詞：例如布局選「便當盒（Bento Grid）」、結構選「首屏（Hero）＋頁尾（Footer）」、導覽選「固定導覽列（Sticky Navbar）」、元件選「燈箱（Lightbox）」。
  3. 複製原文對應的提示詞，把 Punk 換成你自己的名字與內容。
  4. 或直接使用文末的「完整網頁提示詞」，它把十幾個元件組合成一整個網站，修改顏色與頁面名稱即可。
  5. 做出來後用手機打開看一次，不對就回頭補上「手機版怎麼呈現」。
